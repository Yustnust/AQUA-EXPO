# 药液配置与加注控制系统 — PLC设计文档 v1.0

**PLC型号**：西门子 S7-200 SMART CPU ST20（标准型，内置RTC，超级电容保持典型7天/最小6天）
**触摸屏**：昆仑通态 MCGS 12寸
**文档状态**：核心逻辑已确认定稿；485通讯设备（注射泵/温度计/pH计/流量计）接口细节待补充

---

## 一、系统概述

设备为上下两层玻璃缸的实验室配液加注系统：
- **上部玻璃缸**：药剂配液缸，负责进纯净水、搅拌、加药
- **下部玻璃缸**：实验缸，接收配好的溶液，按换水周期定期更换

系统长期**无人值守**运行，因此所有异常检测、报警处理、断电恢复逻辑均按"最坏情况有人不在场"的原则设计。

## 三、内部标志位（断电保持区）

| 符号 | 说明 |
|---|---|
| M_TankA_State | 上缸状态：0=空，1=满（软件标志位，非实体I/O，HMI可手动强制修正） |
| M_TankB_State | 下缸状态：0=空，1=满 |
| M_EStop_Latch | 急停锁存标志，需HMI人工复位才能清除 |
| M_Alarm_Overflow | 漫溢类报警标志（液位计A最高报警/NO阀动作），强制人工确认 |
| DT_TankB_FullTime | 下缸变满时刻的时间戳（年月日时分秒，用于换水周期计算） |
| VD_CycleSetpoint | 换水周期设定值（HMI可调） |
| VD_Timeout_ValveA/B/C | 阀A/B/C各自的动作超时保护时长（HMI独立可调） |
| VD_Timeout_Pump1/2 | 潜水泵1/2动作超时保护时长（HMI独立可调） |
| VD_Delay_ValveA_Verify | 阀A关闭后延时验证时长（HMI可调，见第五章） |
| VD_PreMixTime | 潜水泵预循环时长，即先搅拌再加药的等待时间（HMI可调） |
| M_RunMode | 运行方案选择：方案A/方案B（HMI下拉选择） |
| M_AlarmAckMode | 报警确认模式：0=自动恢复，1=人工确认（漫溢类报警不受此项影响，始终强制人工确认） |

## 四、顶层状态机（实验流程主状态）

```
S0 初始化
   → 上下缸状态强制置"空"（开机默认，也可HMI手动强制）
   → 所有阀门/泵输出复位为OFF
   ↓
S1 上缸进水（阀A开启条件成立）
   → 阀A开，监测流量计读数，达到HMI设定进水量 → 立即关阀A（详见第五章"关闭后延时验证"）
   → 液位计A全程监测，一旦触发最高报警 → 立即关阀A+关NO电磁阀，转入报警状态
   ↓（阀A关闭且验证通过，上缸状态置"满"）
S2 潜水泵预循环
   → 开启潜水泵1、潜水泵2，仅搅拌，不加药
   → 计时达 VD_PreMixTime 后进入下一状态
   ↓
S3 加药
   → 注射泵启动，工作时长 = (目标浓度×上缸注水量)/(母液浓度×注射泵额定流量)
   → 潜水泵持续运行（搅拌+加药同时进行）
   → 注射泵完成后停止，潜水泵可继续运行至转移前
   ↓
S4 上→下转移（阀B开启条件成立，见第五章四态诊断）
   → 阀B开，监测流量开关B+液位计A，正常排空后关阀B
   → 上缸状态置"空"，下缸状态置"满"
   → 记录下缸变满时间戳 DT_TankB_FullTime
   ↓
S5 实验运行中（等待换水周期）
   → 持续采集温度、pH（不参与闭环，仅监测报警）
   → 持续比较：当前RTC时间 − DT_TankB_FullTime ≥ VD_CycleSetpoint？
   ↓（达到换水周期，下缸状态="满"，阀C/流量开关C无报警）
S6 下缸排水（阀C开启条件成立，见第五章四态诊断）
   → 阀C开，监测流量开关C+液位计B，正常排空后关阀C
   → 下缸状态置"空"
   ↓（下缸空，触发新一轮）
   → 返回 S4（上缸此时若已配好新一批溶液，直接转移；若未配好，等待S1~S3完成）
```

> 方案A/方案B的具体分支差异（第16轮沟通中提到"无人值守，两种方案都保留供选择"）待你补充方案B的具体流程后再细化到状态机中；目前S0~S6是双方已确认的主线（对应方案A）。

## 五、阀门 A / B / C 四态诊断逻辑

统一诊断模型：**流量开关状态 × 液位计状态 → 四种组合 → 判定当前所处工况**

### 阀A（上缸进水）— 关闭方式已改为"流量计主导，流量开关仅作校验"

```
开启条件：上缸状态=空，阀B/流量开关B关闭，液位计A关闭，潜水泵/注射泵关闭，
          阀A/流量开关A关闭，无报警，实验进行中

运行中：
  持续比较流量计读数 vs HMI设定进水量
  → 读数 ≥ 设定值：立即下达"关阀A"指令，锁存此刻流量计读数，启动延时 VD_Delay_ValveA_Verify

延时到达后校验（不影响阀已关闭这个事实，只用于故障判断）：
  - 流量开关A应变为OFF：若仍为ON → 报警"阀A关闭异常或流量开关A故障"
  - 若阀已关闭但流量计读数仍在增长 → 报警"阀A内漏或流量计异常"

全程安全监测（独立于上面的逻辑，优先级最高）：
  液位计A闭合（达最高警戒）→ 立即关阀A + 关NO电磁阀 + 触发漫溢类报警（强制人工确认）
```

### 阀B（上缸→下缸转移）

```
开启条件：上缸状态=满，下缸状态=空，流量开关C/阀C关闭，循环泵关闭，注射泵关闭，
          阀B/流量开关B关闭，液位计B关闭，阀A/流量开关A关闭，无报警，实验进行中

关闭逻辑（四态诊断，持续扫描流量开关B + 液位计A）：
  流量开关B=ON  且 液位计A未达最低位  → 正常转移中
  流量开关B=ON  且 液位计A达最低位    → 上缸即将排空
  流量开关B=OFF 且 液位计A达最低位    → 上缸已排空 → 允许关阀B，上缸状态置"空"
  流量开关B=OFF 且 液位计A未达最低位  → 设备故障（阀卡滞/流量开关故障）→ 报警

超时保护：阀B开启后，若在 VD_Timeout_ValveB 时间内流量开关B始终未变ON → 报警"阀B或流量开关B异常"
```

> 注：文档原文中液位计A被复用于阀A的"最高报警"和阀B诊断的"最低位判断"，说明液位计A应为**连续量/多点位式液位计**（同时具备最高、最低两个判定点），而非单一开关型。这个需要你确认液位计A的实际类型（开关量 vs 模拟量/多触点），会影响接线和I/O点数。

### 阀C（下缸排水）

```
开启条件：换水周期计时达到（当前RTC − DT_TankB_FullTime ≥ VD_CycleSetpoint），
          下缸状态=满，阀C/流量开关C关闭，无报警，实验进行中

关闭逻辑（四态诊断，持续扫描流量开关C + 液位计B）：
  流量开关C=ON  且 液位计B未达最低位  → 正常排水中
  流量开关C=ON  且 液位计B达最低位    → 下缸即将排空
  流量开关C=OFF 且 液位计B达最低位    → 下缸已排空 → 允许关阀C，下缸状态置"空"
  流量开关C=OFF 且 液位计B未达最低位  → 设备故障 → 报警

超时保护：阀C开启后，若在 VD_Timeout_ValveC 时间内流量开关C始终未变ON → 报警"阀C或流量开关C异常"
```

### 潜水泵 1/2、注射泵 超时保护

```
潜水泵1/2启动后，若在各自 VD_Timeout_Pump1/2 时间内串联的流量开关未变ON → 报警"潜水泵异常"
注射泵：暂不串联流量开关（待接口文档确认是否需要增加），暂无独立超时校验，
        待技术说明书确认后补充
```

## 六、报警分级与消音/消光逻辑

### 6.1 报警分级

| 级别 | 触发条件示例 | 处理方式 |
|---|---|---|
| **漫溢风险级（强制人工确认）** | 液位计A最高报警、NO电磁阀动作 | 无论 M_AlarmAckMode 设成什么，**始终强制人工确认**才能复位 |
| **一般故障级（按模式处理）** | 阀B/C四态诊断异常、超时保护触发、流量开关瞬时异常 | 按 M_AlarmAckMode 设定：人工确认模式→需按"报警确认"；自动恢复模式→条件消失后自动清除 |

### 6.2 消音 / 消光独立处理

```
消音（HMI"消音"按钮）：
  → 仅将 Q0.6（声音DO）置OFF
  → Q0.7（灯光DO）保持原状态（常亮/闪烁），报警未解除
  → 消音仅对"当前已知的这次报警"生效
  → 若消音后触发新的报警（不同类型，或同一报警消失后重新触发）→ 声音重新鸣响

消光（= 报警确认/复位，仅在报警根本原因已消失后才允许操作）：
  → 一般故障级：报警条件消失 + （若为人工确认模式）操作员按"报警确认" → Q0.7置OFF，状态机解锁
  → 漫溢风险级：报警条件消失 + 操作员必须按"报警确认" → Q0.7置OFF，状态机解锁（无自动恢复选项）
```

### 6.3 报警日志（纯故障追溯，不绑定人员信息）

记录字段：**时间戳 + 报警类型 + 动作（触发/消音/复位）**，写入断电保持区，定期同步至HMI历史数据/趋势记录。不做登录系统，不记录操作人员身份。

## 七、急停逻辑（硬件断电 + 软件感知复位 双通道）

```
急停触发：
  【硬件通道】急停按钮直接切断潜水泵、注射泵、电动球阀的动力回路（不经过PLC逻辑，物理层面立即生效）
  【软件通道】急停按钮同时并联一路信号接入 I0.7
             PLC检测到 I0.7=ON：
               1. 强制将所有阀门/泵的内部输出线圈复位为OFF（M_EStop_Latch置位）
               2. 顶层状态机锁定，禁止任何自动状态切换
               3. 触发报警：灯光DO常亮（漫溢级处理，强制人工确认）；声音DO按消音逻辑处理
               4. HMI显示"急停触发，等待复位"

急停解除（物理按钮松开/旋出，I0.7恢复OFF）：
  → 状态机不自动恢复运行，M_EStop_Latch保持置位
  → 操作员必须在HMI上确认"急停已解除" + 按"系统复位"
  → 复位后：上下缸状态强制置"空"（M_TankA_State=0, M_TankB_State=0），
    流程回到 S0 初始化重新开始整个流程
  → 不支持"从急停前的中断点继续运行"
```

## 八、换水周期计时（时间戳方案）

```
下缸状态由"空"变为"满"的瞬间（阀B正常关闭完成后）：
  → 读取PLC当前RTC时间，写入 DT_TankB_FullTime（断电保持区）

系统持续运行期间：
  → 周期性（如每秒一次，用SM0.5上升沿触发）读取当前RTC时间
  → 已运行时长 = 当前RTC时间 − DT_TankB_FullTime
  → 已运行时长 ≥ VD_CycleSetpoint 时，满足阀C开启条件之一

断电恢复后：
  → DT_TankB_FullTime 已在断电保持区中保留（前提：断电时长未超过CPU ST20超级电容
    保持能力，典型7天/最小6天）
  → 重新上电后立即用"当前RTC − DT_TankB_FullTime"重新算出已运行时长，不会因断电丢失进度
  → 若断电时长超过6~7天导致RTC本身停走，需要人工在HMI上重新校准PLC时钟
    （可加一条开机检测：若RTC时间早于DT_TankB_FullTime本身，说明时钟已丢失，触发提示报警）
```
