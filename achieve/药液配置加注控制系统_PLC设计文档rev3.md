# 药液配置与加注控制系统 — PLC设计文档 v3.0

**PLC型号**：西门子 S7-200 SMART CPU ST20（标准型，内置RTC，超级电容保持典型7天/最小6天）
**触摸屏**：昆仑通态 MCGS 12寸
**文档状态**：核心逻辑已确认定稿（方案A主线）；方案B流程待补充；485通讯设备接口细节待补充
**版本说明**：v2.0 相对 v1.0 新增/修改内容已用【v2新增】标注；v3更正内容（急停触点类型、安全继电器反馈）已用【v3更正】/【v3新增】标注

## 一、系统概述

设备为上下两层玻璃缸的实验室配液加注系统：
- **上部玻璃缸**：药剂配液缸，负责进纯净水、搅拌、加药
- **下部玻璃缸**：实验缸，接收配好的溶液，按换水周期定期更换

系统长期**无人值守**运行，因此所有异常检测、报警处理、断电恢复逻辑均按"最坏情况有人不在场"的原则设计。

## 四、顶层状态机（实验流程主状态）【v2更新：新增静止等候子步骤、节奏滞后判断、实验结束终态】

```
S0 初始化
   → 上下缸状态强制置"空"（开机默认，也可HMI手动强制）
   → 所有阀门/泵输出复位为OFF
   ↓
S1 上缸进水（阀A开启条件成立）
   → 阀A开，同步启动"S1实测计时器"
   → 监测流量计读数，达到HMI设定进水量 → 立即关阀A（关闭后延时验证，见第五章）
   → 液位计A-高位全程监测，一旦触发 → 立即关阀A+关NC电磁阀-上缸，转入漫溢报警
   ↓（阀A关闭且验证通过，上缸状态置"满"，S1实测计时器停止，记录本次S1实测时长）
S2 潜水泵预循环
   → 开启潜水泵1、潜水泵2，仅搅拌，不加药
   → 正常计时至 VD_PreMixTime；若触发节奏纠偏第1层，压缩至不低于 VD_PreMixTime_MinSafe
   ↓
S3 加药
   → 注射泵启动，工作时长 = (目标浓度×上缸注水量)/(母液浓度×注射泵额定流量)
   → 潜水泵持续运行，注射泵完成后停止
   ↓
S3.5 静止等候【v2新增】
   → 溶液沉降缓冲，正常等待 VD_RestTime；若触发节奏纠偏第0层，压缩至不低于 VD_RestTime_Min
   ↓（S1实测 + S2标称 + S3计算 + 静止等候标称 = 本轮总时长，滚动更新 VD_T_Rolling）
S4 上→下转移（阀B开启条件成立，见第六章四态诊断）
   → 阀B开，监测流量开关B+液位计A-低位，正常排空后关阀B
   → 液位计B-高位全程监测，一旦触发 → 立即关阀B+关NC电磁阀-下缸，转入漫溢报警（不管四态诊断处于哪个状态）
   → 上缸状态置"空"，下缸状态置"满"
   → 记录下缸变满时间戳 DT_TankB_FullTime
   → 下缸"满"状态开始期间，持续累加 VD_ExperimentDuration_Accum
   ↓
S5 实验运行中（等待换水周期，同时进行调度判断）【v2更新】
   → 持续采集温度、pH（不参与闭环，仅监测报警）
   → 持续计算：下缸预计排空时刻 = DT_TankB_FullTime + VD_CycleSetpoint + VD_S6_Rolling
   → 持续判断：(下缸预计排空时刻 − 当前时间) ≤ VD_T_Rolling？
              → 是，且上缸状态=空 → 自动触发启动新一轮S1
              → 是，但上缸状态≠空 → 触发"配液节奏滞后"提示报警，启动三层纠偏机制（见第七章）
   → 持续判断：VD_ExperimentDuration_Accum ≥ VD_ExperimentTarget？
              → 是 → 转入 S7 实验结束
   ↓（达到换水周期，下缸状态="满"，阀C/流量开关C无报警）
S6 下缸排水（阀C开启条件成立，见第六章四态诊断）
   → 阀C开，同步启动"S6实测计时器"，监测流量开关C+液位计B-低位，正常排空后关阀C
   → 下缸状态置"空"，S6实测计时器停止，滚动更新 VD_S6_Rolling
   → 下缸"满"状态结束，本轮满液时长已计入累加值
   ↓（下缸空，触发新一轮）
   → 返回 S4（若新一轮S1-S3.5已配好，直接转移；若未配好，等待完成，期间处于下缸空等或已由纠偏机制提前介入）

S7 实验结束【v2新增】
   → 状态机锁定，所有阀门/泵停止
   → HMI提示"实验时长已达标，实验结束"
   → 需人工在HMI确认后才能重新进入S0开始新实验（不自动重启）
```

> 方案B的具体流程差异待你补充，目前S0~S7为双方已确认的方案A主线。

## 五、阀A"关闭后延时验证"逻辑（沿用v1，无变化）

```
运行中：
  持续比较流量计读数 vs HMI设定进水量
  → 读数 ≥ 设定值：立即下达"关阀A"指令，锁存此刻流量计读数，启动延时 VD_Delay_ValveA_Verify

延时到达后校验：
  - 流量开关A应变为OFF：若仍为ON → 报警"阀A关闭异常或流量开关A故障"
  - 若阀已关闭但流量计读数仍在增长 → 报警"阀A内漏或流量计异常"

全程安全监测（独立于上面逻辑，优先级最高）：
  液位计A-高位闭合 → 立即关阀A + 关NC电磁阀-上缸 + 触发漫溢类报警（强制人工确认）
```

## 六、阀门 A / B / C 四态诊断逻辑【v2：液位计判据更新为高低位独立点，新增对称漫溢保护】

### 阀A（上缸进水）
开启/关闭逻辑见第五章。

### 阀B（上缸→下缸转移）

```
开启条件：上缸状态=满，下缸状态=空，流量开关C/阀C关闭，循环泵关闭，注射泵关闭，
          阀B/流量开关B关闭，液位计A-低位ON（上缸此时应为满，低位应为OFF——
          此处沿用原表述，实际以"上缸状态=满"这一软件标志为准），无报警，实验进行中

关闭逻辑（四态诊断，持续扫描流量开关B + 液位计A-低位）：
  流量开关B=ON  且 液位计A-低位=OFF  → 正常转移中
  流量开关B=ON  且 液位计A-低位=ON   → 上缸即将排空
  流量开关B=OFF 且 液位计A-低位=ON   → 上缸已排空 → 允许关阀B，上缸状态置"空"
  流量开关B=OFF 且 液位计A-低位=OFF  → 设备故障（阀卡滞/流量开关故障）→ 报警

独立漫溢保护【v2新增】：
  液位计B-高位闭合 → 不管四态诊断处于哪个状态，立即强制关阀B + 关NC电磁阀-下缸
                      + 触发漫溢类报警（强制人工确认）

超时保护：阀B开启后，若在 VD_Timeout_ValveB 时间内流量开关B始终未变ON → 报警"阀B或流量开关B异常"
```

### 阀C（下缸排水）

```
开启条件：换水周期计时达到（含节奏调度判断，见第四章S5），下缸状态=满，
          阀C/流量开关C关闭，无报警，实验进行中

关闭逻辑（四态诊断，持续扫描流量开关C + 液位计B-低位）：
  流量开关C=ON  且 液位计B-低位=OFF  → 正常排水中
  流量开关C=ON  且 液位计B-低位=ON   → 下缸即将排空
  流量开关C=OFF 且 液位计B-低位=ON   → 下缸已排空 → 允许关阀C，下缸状态置"空"
  流量开关C=OFF 且 液位计B-低位=OFF  → 设备故障 → 报警

超时保护：阀C开启后，若在 VD_Timeout_ValveC 时间内流量开关C始终未变ON → 报警"阀C或流量开关C异常"
```

### 潜水泵1/2、注射泵 超时保护

```
潜水泵1/2启动后，若在各自 VD_Timeout_Pump1/2 时间内串联的流量开关未变ON → 报警"潜水泵异常"
注射泵：暂不串联流量开关（待接口文档确认是否需要增加），暂无独立超时校验，待技术说明书确认后补充
```

## 七、配液节奏滞后 — 三层自动纠偏机制【v2新增】

触发前提：第四章S5中判断"下缸预计排空时刻 − 当前时间 ≤ VD_T_Rolling"，但此时上缸状态≠空（新一轮无法准时启动）。

**纠偏优先级（风险从低到高依次消耗）：**

```
第0层 — 压缩/取消静止等候（代价最小，无工艺安全意义，纯缓冲垫）
  → 本轮S3.5静止等候时长压缩，最低不低于 VD_RestTime_Min
  → 若压缩后节奏已追平，纠偏结束，不再往下一层

第1层 — 压缩S2潜水泵预循环时间
  → 本轮S2时长压缩，最低不低于 VD_PreMixTime_MinSafe（工艺安全下限，不能到0）
  → 若压缩后节奏已追平，纠偏结束

第2层 — 顺延换水周期
  → 本轮阀C开启时机顺延，不严格按 VD_CycleSetpoint 执行
  → 顺延至新溶液经S1-S3.5实际配好、阀B转移完成后，才允许阀C开启
  → 顺延幅度不得超过 VD_CycleExtend_Max；超过则升级至第3层

第3层 — 人工介入
  → 停止自动纠偏，M_Alarm_ScheduleLag 置位（需人工确认复位）
  → HMI提示"配液节奏严重滞后，已超出自动纠偏范围，需人工检查"
  → 系统保持当前状态等待人工处理，不再擅自继续顺延
```

**T的计算原则**：T（VD_T_Rolling）始终按**标称值**（S1实测 + VD_PreMixTime标称 + S3计算 + VD_RestTime标称）滚动更新，不使用纠偏后的压缩实际值——因为调度决策是提前做出的，需按最坏情况留足时间，纠偏机制只在真正执行到对应步骤、发现确实来不及时才启用。

## 八、报警分级与消音/消光逻辑（沿用v1，无实质变化，漫溢类报警来源已扩展至上下两缸对称保护）

### 8.1 报警分级

| 级别 | 触发条件示例 | 处理方式 |
|---|---|---|
| **漫溢风险级（强制人工确认）** | 液位计A/B高位报警、任一NC电磁阀动作 | 无论 M_AlarmAckMode 设成什么，始终强制人工确认才能复位 |
| **节奏滞后级（强制人工确认）【v2新增】** | 三层纠偏用尽仍无法追平节奏 | 停止自动纠偏，强制人工确认后才能继续 |
| **一般故障级（按模式处理）** | 阀B/C四态诊断异常、超时保护触发、流量开关瞬时异常 | 按 M_AlarmAckMode 设定：人工确认模式→需按"报警确认"；自动恢复模式→条件消失后自动清除 |

### 8.2 消音 / 消光独立处理（沿用v1）

```
消音：仅将声音DO置OFF，灯光DO保持原状态；消音仅对当前已知报警生效，新报警重新鸣响
消光（=报警确认/复位）：报警根本原因消失后，操作员按"报警确认"，灯光DO置OFF，状态机解锁
```

### 8.3 报警日志

记录字段：**时间戳 + 报警类型 + 动作（触发/消音/复位）**，写入断电保持区。不做登录系统，不记录操作人员身份。

## 九、急停逻辑（硬件断电 + 软件感知复位 + 安全继电器反馈确认，v3更新）

### 9.1 接线原则：双触点分离，PLC监测回路与动力回路物理独立

急停按钮本身必须为**常闭型**触点（断线即安全：接线松脱或电缆断裂时效果等同于按下急停，系统自动进入安全停止状态，不会因故障而"检测不到急停"）。急停按钮至少需要两组独立常闭触点，分别用于两条完全独立的回路：

```
【第一组常闭触点】—— 安全回路，不经过PLC
  → 串入安全继电器（强制导向/force-guided型）的输入回路
  → 安全继电器线圈失电后，其主触点断开，切断潜水泵/注射泵/电动球阀的
    220V/380V动力电源（纯硬件动作，与PLC逻辑完全无关，PLC死机/程序卡死时仍生效）

【第二组常闭触点】—— PLC监测回路
  → 独立走PLC自身的24VDC电源，不接触220V
  → 接入 I1.1，供PLC感知"急停已被按下"，用于软件层面的状态机锁定与复位判断
```

两组触点物理独立、互不影响，即使PLC监测回路出现故障（断线、DI点损坏等），也不影响第一组触点直接切断动力电这一最基础的安全保障。

### 9.2 安全继电器反馈确认（新增，解决"动力回路是否真正切断"的确认问题）

普通接触器/继电器存在主触点因电弧烧蚀而粘连熔焊的风险——线圈已失电、控制回路已正确动作，但主触点可能仍卡死在闭合状态，动力电实际未断开，且PLC和操作员对此毫不知情。因此安全继电器必须选用**强制导向型（force-guided）**规格：其主触点（切动力电）与辅助反馈触点在机械结构上强制联动，主触点若粘连闭合，辅助反馈触点绝不可能同时显示"已断开"——这是判断动力回路是否真正切断的可靠依据。

```
安全继电器的强制导向辅助触点 → 独立接入PLC I1.2

急停真正生效的判定条件（双重确认）：
  I1.1 = OFF（急停按钮已触发）
  AND I1.2 = 确认已断开（安全继电器辅助触点反馈动力回路已切实断开）
  → 才判定"急停真正生效"

若 I1.1 已触发（OFF），但延时一定时间后 I1.2 仍未反馈"已断开"：
  → 判定"安全继电器/接触器故障，主触点可能粘连"
  → 触发【继电器故障】最高优先级报警（见9.4），不允许任何自动恢复尝试，
    必须立即人工检修
```

> 建议选型时优先考虑符合 EN ISO 13849-1 / IEC 60204-1 标准、内置双通道冗余自检功能的安全继电器模块（如Pilz、Schmersal等品牌的对应产品），这类模块能周期性自检两路通道状态是否一致，进一步降低隐性故障风险。

### 9.3 急停触发与解除流程

```
急停触发：
  【硬件通道】安全继电器切断潜水泵、注射泵、电动球阀的动力回路（不经过PLC逻辑，物理层面立即生效）
  【软件通道】I1.1检测到OFF后：
    1. 强制所有阀门/泵内部输出线圈复位为OFF（M_EStop_Latch置位）
    2. 顶层状态机锁定，禁止任何自动状态切换
    3. 触发报警：灯光DO常亮（漫溢级处理）；声音DO按消音逻辑处理
    4. HMI显示"急停触发，等待复位"
    5. 延时校验 I1.2 是否反馈"已断开"，未反馈则升级为【继电器故障】最高级报警（见9.4）

急停解除：
  → I1.1恢复ON（触点重新闭合）后，状态机不自动恢复，M_EStop_Latch保持置位
  → 操作员须在HMI确认"急停已解除"+按"系统复位"
  → 复位后：上下缸状态强制置"空"，流程回到S0初始化重新开始
  → 不支持从中断点继续运行
```

### 9.4 继电器故障报警（新增，最高优先级）

```
触发条件：I1.1已确认急停触发（OFF），但超过设定延时后 I1.2 仍未反馈动力回路已断开

处理方式：
  → 优先级高于漫溢风险级，不受 M_AlarmAckMode 影响，不允许任何形式的自动恢复
  → 状态机保持锁定，HMI持续提示"安全继电器/接触器故障，动力回路可能未真正切断，
    请立即人工检修，禁止在故障排除前尝试复位"
  → 该报警的确认/复位应设置为需要更高权限或更明确的二次确认操作（具体交互方式待后续
    HMI画面设计阶段细化），避免被误当作普通报警随手清除
```

## 十、换水周期与实验时长计时（时间戳方案）【v2：新增实验时长累加逻辑】

```
下缸状态由"空"变为"满"瞬间（阀B正常关闭完成后）：
  → 读取PLC当前RTC时间，写入 DT_TankB_FullTime（断电保持区）
  → 开始累加 VD_ExperimentDuration_Accum（仅在下缸="满"期间累加）

下缸状态由"满"变为"空"瞬间（阀C排空完成后）：
  → 停止累加，本轮满液时长已计入 VD_ExperimentDuration_Accum

实验停止判断（持续进行）：
  → VD_ExperimentDuration_Accum ≥ VD_ExperimentTarget（HMI设定）→ 转入S7实验结束

断电恢复：
  → DT_TankB_FullTime、VD_ExperimentDuration_Accum 均在断电保持区，
    前提是断电时长未超过CPU ST20超级电容保持能力（典型7天/最小6天）
  → 重新上电后用"当前RTC − DT_TankB_FullTime"重新算出已运行时长，累加值不受断电影响
  → 若断电时长超过6~7天导致RTC停走，需人工在HMI重新校准PLC时钟
    （建议加开机检测：若RTC时间早于DT_TankB_FullTime，判定时钟已丢失，触发提示报警）
```
