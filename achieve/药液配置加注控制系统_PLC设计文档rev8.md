## 一、系统概述

设备为上下两层玻璃缸的实验室配液加注系统：
- **上部玻璃缸**：药剂配液缸，负责进纯净水、搅拌、加药
- **下部玻璃缸**：实验缸，接收配好的溶液，按换水周期定期更换

系统长期**无人值守**运行，因此所有异常检测、报警处理、断电恢复逻辑均按"最坏情况有人不在场"的原则设计。

**流量计Modbus寄存器表（节选，与本设计相关部分）：**

| 寄存器 | 地址(HEX) | 含义 | 说明 |
|---|---|---|---|
| 0x0009 | 计量值 | 0~99999999，**只读**，低3位为小数部分 | 持续累加，**无清零/复位寄存器**，需用差值法计算单次进水量（见第四章S1） |
| 0x000F | 平均流速 | 只读，低2位小数 | 近1分钟平均流量，仅供监测参考 |
| 0x0017 | 瞬时流速 | 只读，低2位小数 | 实时流速，仅供监测参考 |
| 0x0012 | 单位 | 可读写，默认按"升(L)"=0x03假设 | 需现场核实实际配置值 |

**重要澄清（v8）**：该流量计"计量值"寄存器为**持续累加、只读**，设备本身**不提供清零/复位功能**（0x0011~0x0015等可写寄存器均为通讯地址/波特率/单价/单位/校正参数等配置项，与累计流量清零无关）。因此PLC无法像常见做法那样"进水前清零、进水后直接读增量"，必须改用**差值法**：阀A开启瞬间先读取并快照当前"计量值"，进水过程中用"当前计量值 − 快照值"计算本次实际进水量，详见第四章S1。

**流量计Modbus地址与数据格式调试确认（2026-09-05）**：

经现场用 Modbus Poll 与 S7-200 SMART PLC 联调 BPM32FC 积算仪确认：

| 项目 | 确认值 | 说明 |
|---|---|---|
| 从站地址 | 2 | 积算仪地址拨码/参数设定为 2 |
| 串口参数 | 9600/8/N/1 | 8 数据位、无校验、1 停止位；PLC 系统块与 MBUS_CTRL 均一致 |
| 累积流量协议地址 | 0x0008~0x0009 | 32 位 IEEE-754 浮点，**高字节在前**（Big-endian） |
| PLC MBUS_MSG 地址 | `16#9C49` | 即 40001+8=40009；STL 中必须写成 16 进制，避免 `40009` 被解析为 INT 出错 |
| 读取数量 | 2 | Count=2，对应 2 个 16 位寄存器 |
| 数据方向 | **A+/B- 需对调** | USB 转 485 能通的线序直接接到 PLC Port0 时 A/B 反了，对调后 PLC 才能正常通讯 |
| PLC 解析 | 需字节顺序转换 | 先 `SWAP VW86`、`SWAP VW88`，再交换 `VW86` 与 `VW88` 位置，方可得到正确 REAL |

> **关键经验教训**：BPM32FC 作为 Big-endian 设备，16 位整数和 32 位浮点在 S7-200 SMART（Little-endian）中均需做字节顺序修正；仅当寄存器数量=1 时只需 `SWAP`，数量=2 的浮点需"SWAP+字交换"。

**状态码定义（经现场确认，2026-09-06）：**

| 状态码 | HEX | bit5 | 错误码 | 含义 |
|---|---|---|---|---|
| 64 | 40H | 0=空闲 | 0 | 空闲/休眠态 |
| **96** | **60H** | **1=激活** | **0** | **就绪/激活态（可接受命令，泵上电默认此状态）** |
| 100 | 64H | 1=激活 | 4 | 运动中状态（需强停 40002=1 才能恢复 96） |
| 103 | 67H | 1=激活 | 7 | 设备未初始化（命令时序冲突导致） |

> **关键澄清**：96 (60H) 是就绪态，不是"忙"。bit5=1 表示激活可接受命令，bit5=0 表示空闲休眠。之前误以为 96=忙、64=就绪是错误的。

**调试关键经验教训（2026-09-06）：**

1. **96 是就绪态**：泵上电后默认进 96，无需自动复位（断电重启后 96 可直接接受命令）
2. **运动后状态变 100**：抽液/排液完成后状态变 100，需写强停（40002=1）才能恢复 96
3. **103 错误原因**：命令时序冲突（如复位未完成就发抽液，或连续发送多个命令）
4. **T37 脉冲间隔必须 > MBUS_CTRL 超时**：如 T37=300ms < 超时=1000ms，读请求被反复取消无法完成超时判断，从站离线时 VB201 保持 0，无法检测故障
5. **写 Done 位（M20.2）需程序清零**：MBUS_MSG 的 Done 位会保持 1，如不清零，写使能（M22.1=VW320>=10 AND NOT M20.2）恒为 0，第二次写请求无法触发
6. **每次只触发一个写命令**：等状态回 96（就绪）再发下一个，避免命令溢出导致 103 错误
7. **复位电流需充足**：40016 复位电流设置过低会导致活塞不动，需检查电源或调整电流参数（现场设为 25，范围 1-31）

> **注意**：注射泵 16 位寄存器无需手动 SWAP，MBUS_MSG 已自动处理 16 位数据顺序。仅 32 位浮点数据（如流量计累计流量）需手动 SWAP+字交换。

**注射泵 PLC 程序编写要点（2026-09-06，基于 FC99_TestFlow.stl 调试验证）：**

### 1. 程序架构：任务调度状态机

采用单任务号（VW320）+ 2 个 MBUS_MSG 实例（读/写各一）的架构，通过任务号驱动写地址（VD330）和写数据（VW190）切换：

```
任务号VW320:
  0  = 读状态码(默认)
  10 = 写复位(40003=1)
  11 = 写抽液(40006=步数)
  12 = 写排液(40007=步数)
  13 = 强停  (40002=1)
```

- 读任务固定地址 41001（16#A029），RW=0
- 写任务用 VD330 存放地址（MOVD 16#9C43/9C46/9C47/9C42），RW=1
- 写数据缓冲在 VW190（MOVW 目标步数）

### 2. 库存储区初始化（关键）

首次扫描必须清空 Modbus 库存储区，否则断电残留状态导致库状态机卡死报 Error=6：

```stl
LD     SM0.1
FILL   0, VW608, 143    // 清VB608~VB893(286字节=143字)
```

> V 区断电不丢，残留的库状态机会导致后续 MBUS_MSG 始终报忙（Error=6）。

### 3. 读请求触发：定时器脉冲（不可用 EU）

读 First 引脚必须用定时器脉冲触发，不能用 EU 上升沿（EU 只触发一次，无法持续轮询）：

```stl
// T37: 2000ms脉冲发生器(必须>1000ms超时, 否则读请求被反复取消无法超时)
LD     M22.0           // 读使能=VW320<10
AN     T37
TON    T37, 20         // 2000ms

LD     M22.0
=      L60.0           // EN
LD     T37
=      L63.7           // First(定时器完成位做脉冲)
LD     L60.0
CALL   MBUS_MSG, L63.7, 16#01, 16#00, 16#A029, 16#01, &VB190, M20.1, VB201
```

> **T37 间隔必须 > MBUS_CTRL 超时（1000ms）**：若 T37=300ms < 1000ms，新的 First 脉冲会把旧请求取消，永远到不了超时，从站离线时 VB201 保持 0 无法检测故障。

### 4. 写请求触发：EU 上升沿（仅触发一次）

写 First 引脚用 EU 上升沿触发，保证每次写命令只发送一次：

```stl
LDW>=  VW320, 10        // 写模式
AN     M20.2            // 写未完成
=      M22.1            // 写使能

LD     M22.1
=      L60.0            // EN
LD     M22.1
EU                     // 上升沿做First
=      L63.7
LD     L60.0
CALL   MBUS_MSG, L63.7, 16#01, 16#01, VD330, 16#01, &VB190, M20.2, VB201
```

### 5. 写完成处理：清触发位 + 清 Done 位 + 切回读（关键）

写完成后必须同时做三件事，否则第二次写请求无法触发：

```stl
// 写Done: 清触发位, 清写Done(否则M22.1=0), 切回读
LDW>=  VW320, 10
A      M20.2
R      M21.1, 1         // 清复位触发位
R      M21.2, 1         // 清抽液触发位
R      M21.3, 1         // 清排液触发位
R      M21.5, 1         // 清强停触发位
R      M20.2, 1         // 清写Done位(关键!)
MOVW   0, VW320         // 切回读模式
```

> **M20.2 必须程序清零**：MBUS_MSG 的 Done 位会保持 1，如不清零，写使能 `M22.1 = VW320>=10 AND NOT M20.2` 恒为 0，第二次写请求的 First 无法触发。

### 6. 就绪判断与写命令门控

写命令前必须判断泵就绪（VW192=96），避免命令溢出导致 103 错误：

```stl
// 就绪判断
LDW=   VW192, 96
=      M21.4            // 就绪标志

// 写请求触发(上升沿) + 就绪条件
LD     M21.2            // 抽液触发
EU
A      M21.4            // 必须就绪
MOVW   11, VW320

// 强停例外: 无需就绪条件(100状态时M21.4=0, 仍需能触发)
LD     M21.5
EU
MOVW   13, VW320
```

### 7. 读成功判断（避免离线保持旧值）

只有读成功（M20.1=1 且 VB201=0）才更新状态码 VW192，避免从站离线后保持旧值导致 M21.4 误置 1：

```stl
// 读Done且无错误(直接判断VB201=0): 才更新状态码到VW192
LD     M20.1
LDB=   VB201, 0
MOVW   VW190, VW192
```

> 超时（VB201=3）时 M20.1 也可能=1（超时也是完成），必须同时判断 VB201=0。

### 8. 控制流程示例

```
泵断电重启 → 上电默认96(就绪)
  ↓
M21.2置1(EU) → VW320=11 → 写抽液40006=100步
  ↓ 活塞动作
状态变100(运动中)
  ↓
M21.5置1(EU) → VW320=13 → 写强停40002=1
  ↓ 状态回96
M21.4=1(就绪) → 可发下一个命令

M21.5置1 → 强停 → 状态回96
```

> **关键规则**：每次只触发一个写命令，等状态回 96（就绪）再发下一个。强停用于 100 状态恢复 96。

**重要澄清（v6）**：该泵为**柱塞式计量泵**（丝杆推动活塞，一次行程完成固定体积的抽取或排放），**不是**连续流动的蠕动泵/隔膜泵。控制方式是**直接写入目标步数**，泵完成后停止，没有"持续运行时长"的概念。因此第四章S3的加药逻辑改为"计算目标步数→下发抽/排液指令→轮询状态码确认完成"，不再是"运行时长计算"，详见下方S3更新。

将 FC99_TestFlow.stl 现场调通的关键逻辑移植到正式生产程序，涉及 FC4/FC0/FC13/FC21 四个文件：

**1. FC4_ModbusPolling.stl — 状态码归一化修正 + 写命令就绪门控**

- **归一化修正**：bit5 含义从"0=忙/1=就绪"改为"1=激活/0=空闲"
  - 96(60H)→VW4=0（就绪），64(40H)→VW4=1（空闲），100(64H)→VW4=2（运动中），103(67H)→VW4=11（未初始化）

- 泵上电默认进入 96（就绪态），冷启动不再自动下发复位命令（40003=1）
- 原因：自动复位会在泵未就绪时发送命令，可能导致 103（命令时序冲突）错误

**3. FC13_State_S3_Dosing.stl — S3 加药流程集成强停恢复**

- **子状态机重写**（VW226：0~9，共10态）：
  ```
  0=计算 → 1=写抽液 → 2=等抽液运动 → 3=写强停 → 4=等恢复就绪
  → 5=写排液 → 6=等排液运动 → 7=写强停 → 8=等恢复就绪+计算/循环 → 9=完成
  ```
- **核心流程**：抽液→等运动→**强停恢复**→等就绪→排液→等运动→**强停恢复**→等就绪→计算/循环
  - 每次抽液/排液运动完成后发强停（40002=1）恢复 96 就绪态，泵才能接受下一条命令
- **运动检测**：VW4=2（100运动中）→置 M12.1/M12.2（已开始）；VW4≠2 且已开始→运动完成
- **运动超时**：T102（30秒）防止泵卡在运动态，超时直接发强停恢复
- **地址格式**：全部改为十六进制（40006→16#9C46，40007→16#9C47，40002→16#9C42）
- **全局错误**：VW4≥4 才报错（VW4=2 运动中不算错误）

**4. FC21_ManualSyringePump.stl — 地址格式修正**

- 40006→16#9C46，40007→16#9C47，40003→16#9C43（全部改为十六进制）
- 避免十进制大数被 MBUS_MSG 解析为 INT 导致 Error=6

## 四、顶层状态机（实验流程主状态）【v2更新：新增静止等候子步骤、节奏滞后判断、实验结束终态】

```
S0 初始化
   → 上下缸状态强制置"空"（开机默认，也可HMI手动强制）
   → 所有阀门/泵输出复位为OFF
   ↓
S1 上缸进水（阀A开启条件成立）【v8更新：流量计差值法】
   → 阀A开，同步启动"S1实测计时器"
   → 阀A开启瞬间，读取流量计"计量值"寄存器(0x0009)，快照为 VD_FlowMeter_Snapshot
   → 持续读取当前"计量值"，计算 本次进水量 = 当前计量值 − VD_FlowMeter_Snapshot
   → 本次进水量 ≥ HMI设定进水量 → 立即关阀A（关闭后延时验证，见第五章）
   → 液位计A-高位全程监测，一旦触发 → 立即关阀A+关NC电磁阀-上缸，转入漫溢报警
   ↓（阀A关闭且验证通过，上缸状态置"满"，S1实测计时器停止，记录本次S1实测时长S1_actual，
     本次进水量同时作为S3加药公式"上缸注水量"的输入）
   → 【v3新增】用S1_actual执行一次二次校正计算（见第七章7.3），
      重新核定本轮 VD_S2_Target / VD_RestTime_Target
S2 潜水泵预循环
   → 开启潜水泵1、潜水泵2，仅搅拌，不加药
   → 按 VD_S2_Target 计时（该目标值已在S5触发时预规划、S1完成后二次校正，见第七章）
   ↓
S3 加药【v6重写：步数控制+状态轮询，非时长控制】
   → 计算目标抽取体积：V目标 = (目标浓度×上缸注水量) / 母液浓度
   → 换算为步数：N步 = V目标(µL) ÷ 单步分辨率(µL/步)，单步分辨率取决于所选进样器规格
   → 写入注射泵"抽液"寄存器(16#9C46)=N步，下发抽取母液指令
   → 轮询状态码(41001)，等待VW4=2(运动中)→VW4≠2(运动完成)
   → 写强停(16#9C42=1)恢复96就绪态，等待VW4=0(就绪)
   → 写入注射泵"排液"寄存器(16#9C47)=N步，下发排放到管路指令（泵阀一体内部阀自动切换流路）
   → 轮询状态码(41001)，等待VW4=2→VW4≠2(运动完成)
   → 写强停(16#9C42=1)恢复96就绪态，等待VW4=0(就绪)
   → 潜水泵在整个S3期间持续运行（搅拌+加药同时进行）
   → S3完成判定：以状态码反馈为准，不是固定时长；S3计算值用于T的预估时仍可给出理论估算
     （N步×单步耗时的理论值），但实际完成时刻以轮询结果为准，逻辑上与S1"以流量计读数
     判断完成"是同一模式
   ↓
S3.5 静止等候【v2新增】
   → 溶液沉降缓冲，按 VD_RestTime_Target 计时（该目标值已在S5触发时预规划、S1完成后二次校正）
   ↓（S1实测 + S2标称 + S3计算 + 静止等候标称 = 本轮总时长，滚动更新 VD_T_Rolling）
S4 上→下转移（阀B开启条件成立，见第六章四态诊断）
   → 阀B开，监测流量开关B+液位计A-低位，正常排空后关阀B
   → 液位计B-高位全程监测，一旦触发 → 立即关阀B+关NC电磁阀-下缸，转入漫溢报警（不管四态诊断处于哪个状态）
   → 上缸状态置"空"，下缸状态置"满"
   → 记录下缸变满时间戳 DT_TankB_FullTime
   → 下缸"满"状态开始期间，持续累加 VD_ExperimentDuration_Accum
   ↓
S5 实验运行中（等待换水周期）【v4更新：调度预规划计算触发点改回S5，上升沿触发】
   → 持续采集温度、pH（不参与闭环，仅监测报警）
   → 持续计算：下缸预计排空时刻 = DT_TankB_FullTime + VD_CycleSetpoint + VD_S6_Rolling
   → 持续比较：(下缸预计排空时刻 − 当前时间) ≤ VD_T_Rolling ？
     该条件由"不满足"变为"满足"的**上升沿**（仅触发一次，非逐扫描周期重复触发）：
       1. 立即执行一次性节奏预规划计算（可用时间=下缸预计排空时刻−当前时间 vs
          所需时间=VD_T_Rolling），按三层纠偏算法（见第七章）算出本轮
          VD_S2_Target / VD_RestTime_Target / VD_CycleExtend_Target
       2. 若上缸状态=空，同时启动新一轮S1；若上缸状态≠空，说明上一轮尚未收尾完成，
          属于比"节奏滞后"更严重的异常，单独报警（不在第七章讨论范围内）
   → 持续判断：VD_ExperimentDuration_Accum ≥ VD_ExperimentTarget？
              → 是 → 转入 S7 实验结束
   ↓（达到换水周期，下缸状态="满"，阀C/流量开关C无报警）

   → 下缸"满"状态结束，本轮满液时长已计入累加值
   ↓（下缸排空）
   → 若新一轮S1-S3.5已完成（阀B转移就绪）→ 直接返回S4转移
   → 若新一轮S1-S3.5尚未完成 → 下缸空等，空等时长不得超过 VD_CycleExtend_Target
     （第二层纠偏额度内视为正常；超出仍未就绪则已在第七章触发人工介入报警）

S7 实验结束【v2新增】
   → 状态机锁定，所有阀门/泵停止
   → HMI提示"实验时长已达标，实验结束"

```

```
    已ON但流量开关B始终无流 → 报警"阀B已开到位但无流量，怀疑上缸无液/管路堵塞/流量开关故障"
  阀B关闭后，阀B关到位反馈(I1.6)应在延时内变ON：
    超时未ON → 报警"阀B执行机构关闭故障"
    已ON但流量开关B仍有流 → 报警"阀B关到位但仍有流量，怀疑内漏"

独立漫溢保护【v2新增】：
  液位计B-高位闭合 → 不管四态诊断处于哪个状态，立即强制关阀B + 关NC电磁阀-下缸
                      + 触发漫溢类报警（强制人工确认）

超时保护：阀B开启后，若在 VD_Timeout_ValveB 时间内流量开关B始终未变ON → 报警"阀B或流量开关B异常"
         （此超时判据与上方限位反馈交叉诊断为两套独立判据，可互相印证故障定位）
```

### 阀C（下缸排水）

```
开启条件：换水周期计时达到（含节奏调度判断，见第四章S5），下缸状态=满，
          阀C/流量开关C关闭，无报警，实验进行中

  流量开关C=ON  且 液位计B-低位=ON   → 下缸即将排空

  流量开关C=OFF 且 液位计B-低位=OFF  → 设备故障 → 报警

  阀C开启后，阀C开到位反馈(I1.7)应在 VD_Timeout_ValveC 内变ON：

    已ON但流量开关C仍有流 → 报警"阀C关到位但仍有流量，怀疑内漏"

超时保护：阀C开启后，若在 VD_Timeout_ValveC 时间内流量开关C始终未变ON → 报警"阀C或流量开关C异常"
         （此超时判据与上方限位反馈交叉诊断为两套独立判据，可互相印证故障定位）
```

## 七、配液节奏滞后 — 三层自动纠偏机制【v4更新：触发点改回S5上升沿，预规划+S1后二次校正】

### 7.1 设计原则：预先规划，而非执行中逐层试错

三层纠偏（压缩静止等候→压缩S2→顺延周期）中，**S2排在S3.5之前执行**——如果等到S3.5阶段才发现"纠偏不够用"，S2早已按标称时长跑完，来不及回头压缩。因此纠偏方案**必须在S1开始之前就一次性规划好本轮S2、S3.5各自要用多少时长**，而不是走一步看一步。

### 7.2 预规划计算触发点：S5阶段调度条件达成的上升沿

```
持续比较（第四章S5）：(下缸预计排空时刻 − 当前时间) ≤ VD_T_Rolling ？
该条件由"不满足"变为"满足"的上升沿触发一次计算（非逐扫描周期重复触发，PLC用
比较指令+边沿检测指令实现，与"固定节点算一次"实现难度相同）：

可用时间 Available = 下缸预计排空时刻 − 当前时间（触发那一刻的值，理论上正常情况下
                     应约等于 VD_T_Rolling，因为条件刚好在这一刻达成）
所需时间 Needed = VD_T_Rolling（本轮S1-S3.5标称总时长）

正常情况下 Available ≈ Needed，Δ≈0，本轮无需纠偏，直接按标称参数执行——
纠偏机制真正派上用场的场景，主要是"S1完成后二次校正"（见7.3）阶段捕捉到的
实际执行偏差，而不是这一步的预规划计算本身。

若 Available ≥ Needed（含近似相等情况）：
  → VD_S2_Target = VD_PreMixTime，VD_RestTime_Target = VD_RestTime，
    VD_CycleExtend_Target = 0
  → 若上缸状态=空，立即启动新一轮S1

若 Available < Needed（例如上一轮转移收尾延后、导致这一刻上缸还不能立即开始S1，
                       使实际可用时间比理论值更紧张），缺口 Δ = Needed − Available，
按顺序分层扣减：

  第0层额度 = VD_RestTime − VD_RestTime_Min
    若 Δ ≤ 第0层额度：
      VD_RestTime_Target = VD_RestTime − Δ
      VD_S2_Target = VD_PreMixTime
      VD_CycleExtend_Target = 0 → 规划完成
    否则：
      VD_RestTime_Target = VD_RestTime_Min（第0层用满）
      Δ = Δ − 第0层额度，继续第1层

  第1层额度 = VD_PreMixTime − VD_PreMixTime_MinSafe
    若 Δ ≤ 第1层额度：
      VD_S2_Target = VD_PreMixTime − Δ
      VD_CycleExtend_Target = 0 → 规划完成
    否则：
      VD_S2_Target = VD_PreMixTime_MinSafe（第1层用满）
      Δ = Δ − 第1层额度，继续第2层

  第2层额度 = VD_CycleExtend_Max
    若 Δ ≤ 第2层额度：
      VD_CycleExtend_Target = Δ（即预计下缸排空后允许"空等" Δ 这么久，
                                 等新溶液经S1-S3.5配好、阀B转移完成，见第四章S6末尾）
      → 规划完成，同时触发"配液节奏滞后"提示报警（一般故障级，非漫溢级）
    否则：
      → 三层额度全部用尽仍不够，触发【人工介入】报警（见7.4），
        M_Alarm_ScheduleLag 置位，停止自动纠偏，本轮不再规划，等待人工处理

若上缸状态=空，规划完成后立即启动新一轮S1。
```

### 7.3 S1完成后二次校正（提高精度，主要纠偏场景）

S1的实际耗时存在波动（如水压变化），是本机制真正需要应对的主要不确定性来源。S1真正跑完、上缸状态置"满"的那一刻，用实测值S1_actual重新校正一次剩余的S2、S3.5目标：

```
S1完成时刻，重新计算：
  剩余可用时间 Available' = 下缸预计排空时刻 − 当前时间（此刻重新取值，已扣除S1实际耗时）
  剩余所需时间 Needed' = VD_S2_Target（7.2已定的目标） + S3计算值 + VD_RestTime_Target（7.2已定的目标）

  按7.2同样的三层分层算法，用 Available' 和 Needed' 重新算一次 Δ'，
  重新核定 VD_S2_Target、VD_RestTime_Target（VD_CycleExtend_Target若在7.2已经定过，
  此处只做微调，不重复触发滞后报警，除非二次校正后发现缺口进一步扩大到超出已定额度）

  → 这一步用S1的确定性实测值替换了预规划阶段基于估算的假设，消除了S1本身波动带来的误差，
    使S2/S3.5的压缩量更精确，避免"压缩过头"或"压缩不够"
```

### 7.4 人工介入报警（触发条件：7.2预规划阶段或7.3二次校正阶段，三层额度用尽仍无法覆盖缺口）

```
处理方式：
  → 停止自动纠偏，M_Alarm_ScheduleLag 置位（需人工确认复位）
  → HMI提示"配液节奏严重滞后，已超出自动纠偏范围，需人工检查"
  → 系统保持当前状态等待人工处理，不再擅自继续顺延或空等
```

### 7.5 T的计算原则（沿用v2，无变化）

VD_T_Rolling滚动更新时仍取**标称值**（S1实测 + VD_PreMixTime标称 + S3计算 + VD_RestTime标称），不使用纠偏后的压缩值——因为它代表"正常无干扰情况下的基准耗时"，供下一轮预规划时估算所需时间用。

## 九、急停逻辑（硬件断电 + 软件感知复位 + 安全继电器反馈确认，v3更新）

### 9.1 接线原则：双触点分离，PLC监测回路与动力回路物理独立

急停按钮本身必须为**常闭型**触点（断线即安全：接线松脱或电缆断裂时效果等同于按下急停，系统自动进入安全停止状态，不会因故障而"检测不到急停"）。急停按钮至少需要两组独立常闭触点，分别用于两条完全独立的回路：

```
【第一组常闭触点】—— 安全回路，不经过PLC
  → 串入安全继电器（强制导向/force-guided型）的输入回路
  → 安全继电器线圈失电后，其主触点断开，切断潜水泵/注射泵/电动球阀的
    220V/380V动力电源（纯硬件动作，与PLC逻辑完全无关，PLC死机/程序卡死时仍生效）

【第二组常闭触点】—— PLC监测回路
  → 独立走PLC自身的24VDC电源，不接触220V
  → 接入 I1.1，供PLC感知"急停已被按下"，用于软件层面的状态机锁定与复位判断
```

两组触点物理独立、互不影响，即使PLC监测回路出现故障（断线、DI点损坏等），也不影响第一组触点直接切断动力电这一最基础的安全保障。

### 9.2 安全继电器反馈确认（新增，解决"动力回路是否真正切断"的确认问题）

普通接触器/继电器存在主触点因电弧烧蚀而粘连熔焊的风险——线圈已失电、控制回路已正确动作，但主触点可能仍卡死在闭合状态，动力电实际未断开，且PLC和操作员对此毫不知情。因此安全继电器必须选用**强制导向型（force-guided）**规格：其主触点（切动力电）与辅助反馈触点在机械结构上强制联动，主触点若粘连闭合，辅助反馈触点绝不可能同时显示"已断开"——这是判断动力回路是否真正切断的可靠依据。

```
安全继电器的强制导向辅助触点 → 独立接入PLC I1.2

急停真正生效的判定条件（双重确认）：
  I1.1 = OFF（急停按钮已触发）
  AND I1.2 = 确认已断开（安全继电器辅助触点反馈动力回路已切实断开）
  → 才判定"急停真正生效"

若 I1.1 已触发（OFF），但延时一定时间后 I1.2 仍未反馈"已断开"：
  → 判定"安全继电器/接触器故障，主触点可能粘连"
  → 触发【继电器故障】最高优先级报警（见9.4），不允许任何自动恢复尝试，
    必须立即人工检修
```

> 建议选型时优先考虑符合 EN ISO 13849-1 / IEC 60204-1 标准、内置双通道冗余自检功能的安全继电器模块（如Pilz、Schmersal等品牌的对应产品），这类模块能周期性自检两路通道状态是否一致，进一步降低隐性故障风险。

### 9.3 急停触发与解除流程

```
急停触发：
  【硬件通道】安全继电器切断潜水泵、注射泵、电动球阀的动力回路（不经过PLC逻辑，物理层面立即生效）
  【软件通道】I1.1检测到OFF后：
    1. 强制所有阀门/泵内部输出线圈复位为OFF（M_EStop_Latch置位）
    2. 顶层状态机锁定，禁止任何自动状态切换
    3. 触发报警：灯光DO常亮（漫溢级处理）；声音DO按消音逻辑处理
    4. HMI显示"急停触发，等待复位"
    5. 延时校验 I1.2 是否反馈"已断开"，未反馈则升级为【继电器故障】最高级报警（见9.4）

急停解除：
  → I1.1恢复ON（触点重新闭合）后，状态机不自动恢复，M_EStop_Latch保持置位
  → 操作员须在HMI确认"急停已解除"+按"系统复位"
  → 复位后：上下缸状态强制置"空"，流程回到S0初始化重新开始
  → 不支持从中断点继续运行
```

### 9.4 继电器故障报警（新增，最高优先级）

```
触发条件：I1.1已确认急停触发（OFF），但超过设定延时后 I1.2 仍未反馈动力回路已断开

处理方式：
  → 优先级高于漫溢风险级，不受 M_AlarmAckMode 影响，不允许任何形式的自动恢复
  → 状态机保持锁定，HMI持续提示"安全继电器/接触器故障，动力回路可能未真正切断，
    请立即人工检修，禁止在故障排除前尝试复位"
  → 该报警的确认/复位应设置为需要更高权限或更明确的二次确认操作（具体交互方式待后续
    HMI画面设计阶段细化），避免被误当作普通报警随手清除
```

## 十、换水周期与实验时长计时（时间戳方案）【v2：新增实验时长累加逻辑】

```
下缸状态由"空"变为"满"瞬间（阀B正常关闭完成后）：
  → 读取PLC当前RTC时间，写入 DT_TankB_FullTime（断电保持区）
  → 开始累加 VD_ExperimentDuration_Accum（仅在下缸="满"期间累加）

下缸状态由"满"变为"空"瞬间（阀C排空完成后）：
  → 停止累加，本轮满液时长已计入 VD_ExperimentDuration_Accum

实验停止判断（持续进行）：
  → VD_ExperimentDuration_Accum ≥ VD_ExperimentTarget（HMI设定）→ 转入S7实验结束

断电恢复：
  → DT_TankB_FullTime、VD_ExperimentDuration_Accum 均在断电保持区，
    前提是断电时长未超过CPU ST20超级电容保持能力（典型7天/最小6天）
  → 重新上电后用"当前RTC − DT_TankB_FullTime"重新算出已运行时长，累加值不受断电影响
  → 若断电时长超过6~7天导致RTC停走，需人工在HMI重新校准PLC时钟
    （建议加开机检测：若RTC时间早于DT_TankB_FullTime，判定时钟已丢失，触发提示报警）
```
