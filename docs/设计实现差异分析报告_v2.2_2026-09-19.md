```
| VD178 | VD_S5_Elapsed【v2.2废弃】 | 原S5已运行时长,v2.2改为双倒计时器管理,本变量不再使用 |
```

**关键问题**:

- **双重 S6 触发机制并存,可能冲突或矛盾**

**修复建议**:
1. **方案 A:完全按设计意图重写**——FC16 不再判断 S6,只负责 VD_ExperimentDuration_Accum 累加;S6 触发完全由 FC40 通过 VW2=6+PV≤S6_actual*10 触发
2. **方案 B:更新设计文档**——承认 FC16 当前实现,标注 VD178 是"v2.2 简化判断辅助变量",由 FC40 提供 VD186 阈值

### 不一致 #3:`FC1A_State_S2_MixDose` 与设计文档 §4.3 S2 不完全一致

**设计文档 §4.3 S2**:
```
S2 搅拌 + 加药(VW304=2)
   → 开启潜水泵1、潜水泵2,同时启动注射泵加药
   → 按 VD_PreMixTime(VD28)严格固定计时(T38),不压缩、不调整
   → 注射泵采用"目标步数→抽液→轮询→排液→轮询"完成判定
   → T38 计时到且注射泵动作完成 → VW304 = 3
```

**实际代码**(`FC1A_State_S2_MixDose.stl` L65-72):
```stl
// 完成判定 - 搅拌计时到 AND 加药子状态 9 → VW304=3
LDW=   VW226, 9
A      T38
LPS
R      Q0.0, 1
R      Q0.1, 1
R      T38, 1
MOVW   3, VW304
LPP
```

**问题**:
- 设计文档说"T38 计时到且注射泵动作完成"——是 AND 关系
- 代码也用 `A T38` 实现 AND 关系 ✓
- 但 `LPS + R + R + R + MOVW + LPP` 链栈消耗——**L65 LDW= VW226, 9; A T38; LPS** 提供栈深 2
- **R Q0.0, 1 消耗栈顶(深 1)✓**,**R Q0.1, 1 消耗栈顶(深 0)✓**
- **R T38, 1 栈空,不执行!**
- **MOVW 3, VW304 栈空,不执行!**
- LPP 弹栈

**栈管理修正后**:
- R Q0.0, 1 执行 ✓(潜水泵 1 关)
- R Q0.1, 1 执行 ✓(潜水泵 2 关)
- R T38, 1 失效(T38 不复位)
- VW304=3 **不写入**——**S2 永远卡住**

**这与设计意图严重冲突**——S2 永远完成不了。

**修复**:每条独立 LD,或 LPS 后每条 MOVW/R 单独 LD

### 不一致 #4:`FC40` 的"触发下一轮 S1 条件" 与设计文档 §7.6 不一致

**设计文档 §7.6**:
```
Prep_Needed = (VD70 + VD28 + VD430) × 10    // 转换为 100ms 时基

IF Timer_Current_PV <= Prep_Needed AND VW304 = 0 AND VW6 = 0 THEN
    S  M16.1, 1                      // 触发下一轮 S1 脉冲
END_IF
```

**实际代码**(`FC40_RhythmCorrection.stl` L96-117):
```stl
// 下一轮 S1 触发条件
LD     SM0.0
MOVR   VD70, VD190                 // VD_S1_Actual
+R     VD28, VD190                 // + VD_PreMixTime(固定)
+R     VD430, VD190                // + Prep_Safety_Margin
*R     10.0, VD190                 // → 100ms 时基
ROUND  VD190, AC0
MOVW   AC0, VW200                  // VW200 = Prep_Needed × 10

LD     SM0.0
MOVW   VW190, VW192                // VW192 = 当前 PV
-I     VW200, VW192                // PV - Prep_Needed×10
AW<=   VW192, 0                    // PV <= Prep_Needed×10 ?
LPS

LDW=   VW304, 0                    // 上缸空闲(可启动下一轮)
AW=    VW6, 0                      // 无报警
LPP
ALD
S      M16.1, 1                    // 触发下一轮 S1 脉冲
```

**计算逻辑差异**:
- 设计文档:`Prep_Needed = (VD70 + VD28 + VD430) × 10`
- 实际代码:`VW200 = (VD70 + VD28 + VD430) × 10` 然后 `VW192 = VW190 - VW200`
- `AW<= VW192, 0` 等价于 `VW190 - VW200 ≤ 0` 等价于 `VW190 ≤ VW200` 等价于 `PV ≤ Prep_Needed×10`

**逻辑上等价** ✓

但**栈消耗问题**:
- `AW<= VW192, 0` 后 LPS(深 2)
- LDW= VW304, 0(AW= 压栈,深 2)
- AW= VW6, 0(深 2)
- LPP 弹栈(深 1)
- ALD 弹栈(深 0)
- S M16.1, 1 看栈顶(深 0=FALSE),**S 不执行!** ⚠️

**M16.1 永远不会被置位**——**下一轮 S1 永远不会被 FC40 触发**!

但 FC10 的 S1 启动条件 `LD V0.0; EU; AW= VW6, 0; A I0.6; ...`——**V0.0(启动命令)只在 S0 由 HMI 下发**——FC10 NETWORK 1(原文档第 449 行)只在启动命令 V0.0 上升沿时触发 S1,后续轮次**没有 V0.0 命令,FC10 不会自动触发 S1**!

**意味着系统的"自动循环"完全依赖 FC40 触发 M16.1 → FC11 S1 启动**——但 FC40 触发 M16.1 失败!

**这是设计意图与实现的关键不一致**——按设计意图 M16.1 应由 FC40 触发,但代码不工作。

**修复**:
1. FC40 S M16.1, 1 之前加 LD SM0.0 提供栈顶
2. 或改写为 `LPS; AW=...; LD SM0.0; S M16.1, 1; LPP`

### 不一致 #5:`FC40` 的"S6 触发条件" 与设计文档 §7.5 不一致

**设计文档 §7.5**:
```
S6_actual = VD116                   // S6滚动实测时长(首轮时实际存的是S4实测)
IF VW306 = 0 THEN
    S6_actual = VD108               // 首轮无实测值用默认值
END_IF

IF Timer_Current_PV <= S6_actual × 10 AND VW2 = 6 AND VW6 = 0 THEN
    MOVW 7, VW2                     // 转 S6 排水
END_IF
```

**实际代码**(`FC40_RhythmCorrection.stl` L74-93):
```stl
// S6 触发条件
LD     SM0.0
MOVR   VD116, VD190                // S6_actual = VD116
*R     10.0, VD190                 // S6_actual × 10 (100ms 时基)
ROUND  VD190, AC0
MOVW   AC0, VW194                  // VW194 = S6_actual × 10

LD     SM0.0
MOVW   VW190, VW192                // VW192 = 当前 PV
-I     VW194, VW192                // PV - S6_actual×10
AW<=   VW192, 0                    // PV <= S6_actual×10 ?
LPS                                // 保存触发条件结果

LDW=   VW2, 6                      // 当前在 S5
AW=    VW6, 0                      // 无报警
LPP                                // 恢复触发条件结果
ALD                                // 与 S5/无报警 条件合并
MOVW   7, VW2                      // 转 S6 排水
```

**问题**:
1. **设计文档说"首轮 VW306=0 时 S6_actual = VD108"**——**代码未实现这个分支!**FC40 直接用 VD116,首轮 VW306=0 时 VD116=0(冷启动默认值)→ S6_actual=0 → S6 永远立即触发!
2. **栈消耗问题**:
   - `MOVW VW190, VW192` 消耗栈顶(深 1)
   - `-I VW194, VW192` 栈空,**不执行!** ⚠️
   - `AW<= VW192, 0` 栈空,**不执行!** ⚠️
   - `LPS` 栈空...等等 LPS 是空栈操作,结果未定义
   - **VW192 永远不变**(等于 VW190),AW<= 永远不执行

**实际行为**:
- `-I` 不执行:VW192 保持 VW190 的值(0 或 T46/T48 的当前 PV)
- `AW<= VW192, 0` 不执行 → 栈深 0 → LPS 栈空 → LDW= VW2, 6 重新压栈(深 1) → AW= VW6, 0 压栈(深 1) → LPP 弹栈(深 0) → ALD 弹栈(深 -1?!) → MOVW 7, VW2 栈空

**结果**:**S6 触发完全失效**

但**FC16 S5 自己用 VD178 判断 S6**——所以**实际上 S6 是被 FC16 触发的**,FC40 的 S6 触发逻辑是死代码!

### 不一致 #6:`FC18 S7` 复位条件多了 `I1.1=OFF` 急停要求,设计文档未提

**设计文档 §4.3 S7**:
```
S7 实验结束(VW2=8)
   → 唯一出口为物理系统复位按钮 I0.3
```

**实际代码**(`FC18_State_S7_End.stl` L35-47):
```stl
LDN    I1.1                        // 急停已释放
A      I0.3                        // 系统复位按钮按下
EU
R      M10.6, 1
R      V1.0, 1
MOVR   0.0, VD364
MOVR   0.0, VD440
MOVR   0.0, VD372
MOVW   0, VW2
```

**问题**:
- 复位条件要求**急停释放 + I0.3 上升沿**——比设计文档多一个条件
- 这可能是合理的额外保护,但**设计文档没明说**
- **I1.1 = OFF 才是急停触发**(v10.2 文档说"急停按钮已释放 NO 触点恢复 OFF=正常")——`LDN I1.1` 表示 I1.1=OFF(急停触发),**这与文档相反!**

**实际行为**:
- 正常情况:I1.1=ON(急停释放,NO 接法)→ LDN I1.1=OFF → A I0.3 不满足
- **S7 永远无法复位!**

这是一个**真正的 P0 BUG**——S7 设计意图是"按系统复位按钮后回 S0",但实际要求**急停也触发**才能复位——这逻辑反了。

**修复**:
```stl
LD     I1.1                        // 急停已释放(NO 触点 ON)
A      I0.3
EU
```
