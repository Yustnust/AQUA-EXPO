## 一、数据记录总则

### 1.1 记录目的

HMI本地历史数据服务于三个核心目的，缺一不可：

| 目的 | 说明 | 主要使用方 |
|---|---|---|
| 趋势分析 | 通过轮次/时间维度展示过程量变化趋势，评估配液节奏稳定性、纠偏效果、加药精度 | 工艺工程师、画面6趋势曲线 |
| 故障追溯 | 报警触发前后5分钟的过程量、状态机变化、报警字位变化，用于根因定位 | 维护人员、画面5报警日志 |
| 合规存档 | 实验过程数据长期可追溯，满足实验过程可复核的合规要求 | 质量管理、外部审计 |

### 1.2 记录位置

| 存储位置 | 路径 | 用途 | 容量分配（按4GB Flash示例） |
|---|---|---|---|
| HMI本地Flash | `/Flash/HistData/aqua_expo.db`（SQLite主库） | 实时写入、近线查询、趋势画面数据源 | 2GB |
| SD卡（若支持） | `/SDCard/HistData_Bak/`（自动月度归档副本） | 双备份冗余，防Flash单点失效 | 按SD卡容量 |
| U盘导出缓冲 | `/Flash/Export/`（导出临时文件） | CSV/Excel导出中转，导出完成自动清理 | 0.5GB |
| 远程PC（可选） | \\上位机\AQUA-EXPO_Archive\ | 年度归档永久保存（人工U盘转储） | 不限 |

**主存储介质为SQLite数据库文件**。若昆仑通态MCGS原生历史组件不支持SQLite直写，由组态脚本通过ODBC/文件IO中间层落库；本规格以SQLite为逻辑模型，物理实现差异在HMI选型确认后映射。

### 1.3 记录触发

历史记录采用"周期采样 + 事件触发"双轨制：

| 触发方式 | 触发条件 | 适用变量类别 | 写入时机 |
|---|---|---|---|
| 周期采样 | 每1分钟（默认，可配1秒~1小时）定时 | 过程量（实测值/流量/加药计算） | 每60秒整点写入一条 |
| 事件触发-状态变化 | VW2状态机变化、VW4泵状态码变化、VW8轮次+1 | 状态量、过程量快照 | 变化沿即刻写入一条 |
| 事件触发-报警 | VB300~303任一位0→1或1→0、VW6变化 | 报警量、过程量快照 | 报警沿即刻写入一条 |
| 事件触发-阶段切换 | S1→S2→S3→S3.5→S4→S5→S6切换瞬间 | 过程量、纠偏滚动值 | 切换瞬间写入一条 |
| 事件触发-参数修改 | 设定值VD10~VD140被HMI写入且变化超阈值 | 设定值 | 写入确认后即刻写入一条 |

### 1.4 单元标识

每条历史记录必须能溯源到具体缸单元：

| 字段 | 取值 | 说明 |
|---|---|---|
| UnitID（单元号） | 1~8整数 | 1=1号缸单元 … 8=8号缸单元，与PLC IP末段101~108一一对应 |
| PLC_IP | 192.168.2.101~108 | 与UnitID绑定：UnitID + 100 = IP末段 |
| PLC_ConnName | PLC_01~PLC_08 | HMI连接名，与变量地址表第12.2章一致 |

**单元编号映射表**（写入数据库`unit_map`元数据表，参见第5章DDL）：

| UnitID | PLC_ConnName | PLC_IP | 默认使能 |
|---|---|---|---|
| 1 | PLC_01 | 192.168.2.101 | 是（首期） |
| 2 | PLC_02 | 192.168.2.102 | 否 |
| 3 | PLC_03 | 192.168.2.103 | 否 |
| 4 | PLC_04 | 192.168.2.104 | 否 |
| 5 | PLC_05 | 192.168.2.105 | 否 |
| 6 | PLC_06 | 192.168.2.106 | 否 |

## 三、数据结构定义

### 3.1 历史记录表Schema（逻辑结构）

历史主表采用"长表"（Long Format）设计：一条记录 = 一个时间点 × 一个变量 × 一个单元。便于按变量灵活查询，避免列式扩展。

| 字段名 | 数据类型 | 长度 | 是否主键 | 是否可空 | 说明 |
|---|---|---|---|---|---|
| RecordID | BIGINT | 8 | 是（自增） | 否 | 全局唯一记录ID，自增主键 |
| Timestamp | TEXT | 25 | 否（联合索引） | 否 | ISO8601本地时区时间戳，格式`YYYY-MM-DDTHH:MM:SS.sss+08:00` |
| UnitID | INTEGER | 1 | 否（联合索引） | 否 | 单元号1~8 |
| VarName | TEXT | 32 | 否（联合索引） | 否 | 变量符号名，如`VD_S1_Actual` |
| VarAddress | TEXT | 12 | 否 | 否 | PLC地址，如`VD70`、`VW2`、`VB300` |
| Value | REAL | 8 | 否 | 否 | 变量数值（DWORD按无符号整数存为REAL） |
| Unit | TEXT | 8 | 否 | 是 | 单位，如`s`/`L`/`min`/`%`/`Hz`/`µL`/`步`，状态量/报警量为NULL |
| DataType | TEXT | 8 | 否 | 否 | 数据类型：`REAL`/`DWORD`/`INT`/`WORD`/`BYTE`/`BOOL` |
| Quality | TEXT | 8 | 否 | 否 | 质量戳：`Good`/`Bad`/`Unknown` |
| RecordType | TEXT | 12 | 否 | 否 | 记录类型：`Periodic`/`Event`/`Alarm`/`Config`/`Recover` |
| CycleCount | INTEGER | 2 | 否 | 是 | 实验轮次VW8快照（事件类记录必填，便于按轮次查询） |
| StateMachine | INTEGER | 1 | 否 | 是 | 状态机VW2快照（事件类记录必填） |

**联合唯一索引**：`(Timestamp, UnitID, VarName)` 防止同时间点同变量重复写入。

### 3.2 时间戳格式

- **格式**：ISO8601本地时区，毫秒精度
- **示例**：`2026-07-18T14:30:25.123+08:00`
- **时区**：固定`+08:00`（中国标准时间），HMI不跨时区运行
- **来源**：HMI系统时钟（PLC通过HMI RTC校时同步，参见画面8）
- **写入规则**：以HMI收到PLC响应时刻为准，不使用PLC内部DT时间戳（PLC DT仅用于断电恢复，参见第4章）

### 3.3 单元号编码规则

| 编码 | 含义 |
|---|---|
| 1~8 | 1~8号缸单元，与PLC IP末段-100一一对应 |
| 0 | 系统级事件（如全部单元RTC校时、单元使能全局变更） |
| 99 | 未知单元（断电恢复补记录时无法溯源的临时占位） |

### 3.4 质量戳定义

| 质量戳 | 含义 | 触发场景 |
|---|---|---|
| Good | 数据可信，PLC通讯正常且变量值合法 | 正常周期/事件采样 |
| Bad | 数据不可信，PLC通讯中断或变量值超限 | HMI↔PLC通讯超时（建议>3秒）、读到的值NaN/Inf |
| Unknown | 数据状态不确定，常见于断电恢复补记录 | 断电期间无法采样的时段，补记录时填Unknown |

**质量戳写入策略**：每条记录写入时由HMI通讯层判定。通讯连续3次失败该单元该周期所有变量记录置`Bad`；断电恢复后未采样时段的补记录（第4.4节）置`Unknown`。

### 3.5 记录类型定义

| RecordType | 含义 | 典型场景 |
|---|---|---|
| Periodic | 周期采样记录 | 1分钟定时采的过程量 |
| Event | 事件触发记录 | 状态变化、阶段切换、参数修改、纠偏计算 |
| Alarm | 报警事件记录 | 报警字位变化、报警码变化 |
| Config | 配置变更记录 | 单元使能切换、报警模式切换、RTC校时 |
| Recover | 断电恢复补记录 | 断电期间未采样的时段补录（质量戳Unknown） |

## 四、采样策略

### 4.1 周期采样

| 参数 | 默认值 | 可配范围 | 说明 |
|---|---|---|---|
| 采样间隔 | 60秒 | 1秒~3600秒 | 通过画面8系统设置配置，需管理员权限 |
| 采样精度 | 整分钟对齐 | — | 首次采样从启动后第一个整分钟开始，避免漂移 |
| 采样范围 | 全部8单元 | — | 仅使能单元实际采，未使能单元跳过 |
| 周期采样变量 | A类过程量10项 | — | 见第2.2节 |

**采样间隔与数据量关系**（引用《HMI数据量估算与存储时长测算 v1.0》第2.2节）：

| 采样间隔 | 8单元年数据量 | 2GB可存时长 |
|---|---|---|
| 1秒 | 14.1GB | 52天 |
| 10秒 | 1.41GB | 1.4年 |
| **60秒（默认）** | **241MB** | **8.3年** |
| 300秒 | 47MB | 42年 |

### 4.2 事件采样

事件采样在事件发生瞬间即刻写入一条记录，与周期采样独立，不替代周期采样。

| 事件类型 | 触发条件 | 记录变量 | 与周期采样的关系 |
|---|---|---|---|
| 状态机变化 | VW2值变化 | 全部A类过程量快照 + VW2/VW4/VW6/VW8 | 独立加采，不影响周期 |
| 阶段切换 | S1→S2/S2→S3/S3→S3.5/S3.5→S4/S4→S5/S5→S6 | 切换瞬间全部过程量 + E类纠偏值 | 独立加采 |
| 报警触发 | VB300~303任一位0→1 | 触发位所在字节 + VW6 + 过程量快照 | 独立加采 |
| 报警消除 | VB300~303任一位1→0 | 同上 | 独立加采 |
| 轮次+1 | VW8值+1 | VD96实验时长 + VW8 + E类纠偏滚动值 | 独立加采 |
| 参数修改 | VD10~VD140被HMI写入且超阈值 | 被修改的设定值变量 | 独立加采 |
| 单元使能切换 | UnitN_Enabled变化 | Config记录，不写过程量 | — |
| 报警模式切换 | V200.0变化 | Config记录 | — |
| RTC校时 | HMI下发RTC同步 | Config记录（每单元1条） | — |

### 4.3 首次/末次记录规则

| 场景 | 规则 |
|---|---|
| HMI开机首次连接PLC成功 | 立即对全部使能单元采一条全量快照（44变量全部记录），RecordType=Event，质量戳Good |
| 单元首次使能（UnitN_Enabled: FALSE→TRUE） | 立即对该单元采一条全量快照 |
| 实验启动（VW2: S0→S1） | 立即采全量快照 + 一条`Experiment_Start`事件 |
| 实验结束（VW2: →S7） | 立即采全量快照 + 一条`Experiment_End`事件，含VD96最终值 |
| 急停触发（VW2: →S_ERROR） | 立即采全量快照 + 一条`EStop_Triggered`报警事件 |
| HMI关机/断电前 | 若检测到关机信号（系统钩子），对全部使能单元采一条末次快照 |

### 4.4 断电恢复补记录策略

PLC DT10（DT_TankB_FullTime）超级电容保持≥6天，HMI开机后按以下策略补记录：

| 断电时长 | 补记录策略 | 质量戳 |
|---|---|---|
| <60秒（瞬时抖动） | 不补，下一周期正常采 | Good |
| 60秒~1小时 | 按60秒等间隔补Unknown记录，时间戳=断电开始时刻+60秒、+120秒… | Unknown |
| 1小时~7天 | 按10分钟等间隔补Unknown记录（降采样，避免数据膨胀） | Unknown |
| >7天（PLC DT丢失） | 触发M_Alarm_RTC_Lost报警事件；补记录仅标"断电期间无数据"边界事件 | Unknown |
| 恢复后首条 | 立即采全量快照，RecordType=Recover，质量戳Good | Good |

**补记录写入规则**：
1. HMI开机后读取DT_TankB_FullTime，与HMI当前RTC比较，计算断电时长
2. 按上表策略生成补记录，全部置RecordType=Recover、Quality=Unknown、Value=0
3. 每个单元至少生成1条"断电边界事件"：`(断电开始时刻, UnitID, 'PowerOff_Start', ...)`和`(恢复时刻, UnitID, 'PowerOff_End', ...)`

### 5.1 本地数据库Schema（SQLite DDL示例）

```sql
-- ============================================================
-- AQUA-EXPO HMI历史数据库 SQLite DDL
-- 文件: /Flash/HistData/aqua_expo.db
-- 版本: v1.0  日期: 2026-07-18
-- 编码: UTF-8  时区: +08:00

PRAGMA journal_mode = WAL;        -- 写入并发安全
PRAGMA synchronous = NORMAL;      -- 平衡安全与性能（断电时最多丢1秒数据）
PRAGMA encoding = 'UTF-8';
PRAGMA page_size = 4096;

-- ---------- 元数据表：单元映射 ----------
CREATE TABLE IF NOT EXISTS unit_map (
    UnitID        INTEGER PRIMARY KEY,           -- 1~8
    PLC_ConnName  TEXT NOT NULL,                 -- 'PLC_01' ~ 'PLC_08'

INSERT OR IGNORE INTO unit_map VALUES

(5,'PLC_05','192.168.2.105',0,'5号缸单元'),
(6,'PLC_06','192.168.2.106',0,'6号缸单元'),
(7,'PLC_07','192.168.2.107',0,'7号缸单元'),
(8,'PLC_08','192.168.2.108',0,'8号缸单元');

-- ---------- 元数据表：变量字典 ----------
CREATE TABLE IF NOT EXISTS var_dict (
    VarName     TEXT PRIMARY KEY,        -- 'VD_S1_Actual'
    VarAddress  TEXT NOT NULL,           -- 'VD70'
    DataType    TEXT NOT NULL,           -- 'REAL'/'DWORD'/'INT'/'WORD'/'BYTE'/'BOOL'
    Unit        TEXT,                    -- 's'/'L'/'min'/...
    Category    TEXT NOT NULL,           -- '过程量'/'状态'/'报警'/'设定值'/'纠偏滚动值'
    SampleMode  TEXT NOT NULL,           -- '周期'/'事件'/'周期+事件'
    Description TEXT
);

-- (var_dict 数据由HMI组态启动时从内嵌变量字典CSV初始化，44行，参见附录)

-- ---------- 主表：历史记录（长表） ----------
CREATE TABLE IF NOT EXISTS hist_record (
    RecordID      INTEGER PRIMARY KEY AUTOINCREMENT,
    Timestamp     TEXT    NOT NULL,       -- '2026-07-18T14:30:25.123+08:00'
    UnitID        INTEGER NOT NULL,       -- 1~8, 0=系统, 99=未知
    VarName       TEXT    NOT NULL,       -- 关联 var_dict.VarName
    VarAddress    TEXT    NOT NULL,       -- 冗余字段，加速无字典查询
    Value         REAL    NOT NULL,       -- 数值（DWORD按无符号存REAL）
    Unit          TEXT,                   -- 冗余字段
    DataType      TEXT    NOT NULL,       -- 冗余字段

    CycleCount    INTEGER,                -- VW8快照
    StateMachine  INTEGER,                -- VW2快照
    FOREIGN KEY (UnitID) REFERENCES unit_map(UnitID),
    FOREIGN KEY (VarName) REFERENCES var_dict(VarName)
);

-- ---------- 报警事件表（位级展开） ----------
CREATE TABLE IF NOT EXISTS alarm_event (
    AlarmEventID  INTEGER PRIMARY KEY AUTOINCREMENT,
    Timestamp     TEXT    NOT NULL,
    UnitID        INTEGER NOT NULL,
    AlarmBit      TEXT    NOT NULL,       -- 'V300.0' / 'V301.5' / ...
    AlarmCode     INTEGER NOT NULL,       -- 对应VW6编码 10~99
    AlarmDesc     TEXT    NOT NULL,       -- '上缸漫溢' / '阀A关后流' / ...
    Priority      TEXT    NOT NULL,       -- '最高级'/'漫溢级'/'节奏级'/'一般级'
    Event         TEXT    NOT NULL,       -- 'Trigger'/'Ack'/'Clear'
    Operator      TEXT,                   -- 操作员账号（确认/消音时填）
    CycleCount    INTEGER,
    StateMachine  INTEGER
);

-- ---------- 系统事件表（配置/操作审计） ----------
CREATE TABLE IF NOT EXISTS sys_event (
    SysEventID    INTEGER PRIMARY KEY AUTOINCREMENT,
    Timestamp     TEXT    NOT NULL,
    UnitID        INTEGER NOT NULL,       -- 0=系统级
    EventType     TEXT    NOT NULL,       -- 'UnitEnabled_Change'/'RTC_Sync'/'AlarmMode_Change'/'Login'/'Logout'/'ParamModify'/'ManualOp'/'PowerOff'/'PowerOn'
    Operator      TEXT,
    Detail        TEXT,                   -- JSON或自由文本
    Result        TEXT                    -- 'Success'/'Failed'
);
```

### 5.2 表分区策略

### 7.3 数据点采样规则（长时段自动降采样）

为避免长时段查询返回过多数据点导致曲线卡顿，按显示窗口自动降采样：

| 时间范围 | 原始数据点数（1分钟采样×1单元） | 显示数据点数上限 | 降采样算法 |
|---|---|---|---|
| 1小时 | 60 | 60 | 不降采样 |
| 24小时 | 1440 | 240 | 每6点取1点（首点） |
| 7天 | 10,080 | 336 | 每30点取最大/最小/首点三点 |
| 30天 | 43,200 | 720 | 每60点取最大/最小/首点 |
| 自定义>30天 | >43,200 | 1440 | 动态计算采样步长 |

**降采样算法**：
- 步长`step = ceil(总点数 / 上限)`
- 每个窗口取3个代表点：`max`、`min`、`first`，保证曲线包络不失真
- 报警事件点不降采样，强制全量显示（在曲线上叠加红色竖线标记）

### 7.4 数据查询接口

趋势画面通过以下SQL查询接口获取数据（伪SQL，由HMI组态脚本封装）：

```sql
-- 查询1：按时间范围+变量查（时间轴模式）
SELECT Timestamp, UnitID, VarName, Value, CycleCount, StateMachine, Quality
FROM hist_record_YYYYMM
WHERE UnitID = ?
  AND VarName IN (?, ?, ?)        -- 选中的曲线变量
  AND Timestamp BETWEEN ? AND ?
  AND Quality != 'Bad'
ORDER BY Timestamp ASC;

-- 查询2：按轮次范围+变量查（轮次轴模式）
SELECT Timestamp, UnitID, VarName, Value, CycleCount
FROM hist_record_YYYYMM
WHERE UnitID = ?
  AND VarName IN (?, ?, ?)
  AND CycleCount BETWEEN ? AND ?
  AND RecordType IN ('Event', 'Periodic')
ORDER BY CycleCount ASC, Timestamp ASC;

-- 查询3：报警事件叠加（红色竖线标记）
SELECT Timestamp, AlarmCode, AlarmDesc, Priority
FROM alarm_event_YYYYMM
WHERE UnitID = ?
  AND Timestamp BETWEEN ? AND ?
ORDER BY Timestamp ASC;

-- 查询4：缩放（时间窗口收缩，重新查询更细粒度）
-- 复用查询1，缩小BETWEEN范围

-- 查询5：平移（左右拖动，时间窗口滑动）
-- 复用查询1，平移BETWEEN范围

-- 查询6：对比（同变量多单元叠加）
SELECT Timestamp, UnitID, VarName, Value
FROM hist_record_YYYYMM
WHERE UnitID IN (?, ?, ?)
  AND VarName = ?
  AND Timestamp BETWEEN ? AND ?
ORDER BY Timestamp ASC, UnitID ASC;
```

**性能要求**：单次查询响应≤500ms（基于2GB数据库、带索引）。若超时，自动启用降采样。

### 8.5 恢复查询方法

归档数据需要查询时，按以下流程恢复：

## 九、数据完整性保障

### 9.1 断电保护

| 机制 | 说明 |
|---|---|
| SQLite WAL模式 | `PRAGMA journal_mode=WAL`，写入先WAL后主库，断电时WAL可恢复 |
| 同步级别 NORMAL | `PRAGMA synchronous=NORMAL`，平衡性能与安全，断电最多丢1秒事务 |
| 周期Commit | 每条记录立即Commit（不批量缓存），断电不丢已确认写入 |
| SD卡双备份 | 月度归档同步写SD卡，Flash损坏时可从SD卡恢复 |
| PLC DT时间戳 | PLC DT10断电保持≥6天，断电恢复后用于计算断电时长（第4.4节） |
| HMI RTC电池 | HMI实时时钟由电池保持，断电不丢失时间基准 |

### 9.2 写入校验

| 校验项 | 方法 |
|---|---|
| 字段非空 | Timestamp/UnitID/VarName/Value/Quality/RecordType为NOT NULL，违例拒绝写入 |
| 外键约束 | UnitID→unit_map、VarName→var_dict，违例拒绝写入 |
| 联合唯一 | (Timestamp, UnitID, VarName) 唯一索引防重复写入 |
| 数值范围 | Value必须在变量字典定义的合理范围内（如VD96≥0、VW2∈{0,1,2,3,4,5,6,7,8,99}），违例置Quality=Bad |
| 写入后回读 | 关键事件（报警/参数修改）写入后立即回读校验，回读不一致触发`WriteVerify_Failed`系统事件 |
| 时间戳单调 | 新记录Timestamp必须≥上一条，违例记`Timestamp_Backward`系统事件并修正为上一条+1ms |

### 9.3 定期一致性检查

| 检查项 | 周期 | 方法 | 异常处理 |
|---|---|---|---|
| 索引完整性 | 每日 | `PRAGMA integrity_check` | 失败则重建索引`REINDEX` |
| 表行数统计 | 每日 | 各表`SELECT COUNT(*)`与上次比较 | 行数异常减少触发`RowCount_Anomaly`事件 |
| 孤儿记录 | 每周 | hist_record中UnitID/VarName不在字典的记录 | 标记Quality=Bad，记入sys_event |
| 时间戳连续性 | 每周 | 检查过程量周期记录是否存在>2分钟空档 | 空档记`Gap_Detected`事件 |
| 数据库文件大小 | 每月 | 监控aqua_expo.db大小，超阈值告警 | 触发提前归档 |
| WAL文件大小 | 每日 | 监控aqua_expo.db-wal大小 | 超阈值执行`PRAGMA wal_checkpoint(TRUNCATE)` |

### 9.4 损坏恢复

| 损坏场景 | 恢复流程 |
|---|---|
| SQLite主库轻微损坏（索引） | 1. 停止写入 <br> 2. `REINDEX`重建索引 <br> 3. `PRAGMA integrity_check`验证 <br> 4. 恢复写入 |
| SQLite主库严重损坏（数据页） | 1. 停止写入 <br> 2. 尝试`.recover`命令导出可读数据 <br> 3. 从最近月度归档ZIP恢复上月数据 <br> 4. 重建主库 <br> 5. 记`DB_Corrupted`系统事件 <br> 6. 恢复写入 |
| Flash完全损坏 | 1. HMI报警提示Flash故障 <br> 2. 从SD卡最近月度归档恢复至新Flash <br> 3. 当月数据丢失，记`Flash_Failed`事件 |
| SD卡损坏 | 1. 提示SD卡故障 <br> 2. 主库不受影响 <br> 3. 尽快更换SD卡并执行一次月度归档同步 |
| 断电后WAL未提交 | 1. 开机SQLite自动WAL回放 <br> 2. 未提交事务自动回滚 <br> 3. 第4.4节断电补记录策略补Unknown记录 |

**恢复演练**：建议每年进行一次损坏恢复演练，验证归档恢复流程可用。
