## 一、报警字总览

报警字共4字节32位，地址 `VB300~VB303`（即 `V300.0~V303.7`），断电保持，按位编码。每位对应一个独立报警类型，HMI读取报警字后按位解析当前所有活动报警。

| 字节 | 位范围 | 类别 | 报警码段 |
|---|---|---|---|
| VB300 | V300.0~V300.7 | 高优先级（漫溢/急停/继电器故障/节奏滞后） | 99 / 10~14 / 20~21 |
| VB301 | V301.0~V301.7 | 一般故障级-阀门A类 | 30~36（V301.7预留） |
| VB302 | V302.0~V302.7 | 一般故障级-阀门B/C类 | 40~47 |
| VB303 | V303.0~V303.7 | 一般故障级-其他（阀C关/泵/注射泵/RTC/流量） | 49, 60~66（V303.7预留） |

**优先级链**（FC3 NETWORK1 实现，VW6始终保存当前最高优先级未确认报警码）：
```
最高级(99) > 漫溢级(10~14) > 节奏级(20) > 一般级(21,30~66)
```

## 四、报警确认模式与复位规则

### 4.1 M_AlarmAckMode（V200.0）作用域

| 模式 | 值 | 一般故障级（V301.x/V302.x/V303.x，VW6=21/30~66） | 高优先级（V300.0~V300.6，VW6=10~14/20/99） |
|---|---|---|---|
| 自动恢复 | 0 | 条件消失后FC3 NETWORK5自动R复位报警位→VW6重算为0→自动消光 | **不受此模式影响**，仍强制人工确认 |
| 人工确认 | 1 | 条件消失后需HMI下发V0.3确认→FC3 NETWORK4复位报警位→VW6=0→消光 | 同上，强制人工确认 |

### 4.2 复位条件汇总

| 报警类别 | 复位命令 | 附加条件 | 实现位置 |
|---|---|---|---|
| 最高级（V300.5 安全继电器） | V0.7 CMD_SafetyRelayAck（高权限确认） | I1.2安全继电器反馈正常 | FC19 NETWORK4 |
| 漫溢级（V300.0~V300.3） | V0.3 CMD_AckAlarm（HMI二次确认） | 对应液位计/阀反馈恢复正常 | FC3 NETWORK4 |
| 急停锁存（V300.4） | I0.3系统复位按钮（物理） | I1.1=ON（急停释放） | FC19 State_Error |
| 节奏级（V300.6） | V0.3 CMD_AckAlarm（人工确认） | 节奏恢复正常 | FC3 NETWORK4 |
| 节奏提示（V300.7） | 按模式（V0.3或自动） | 条件消失 | FC3 NETWORK4/5 |
| 一般故障级（V301.x/V302.x/V303.x） | 按模式（V0.3或自动） | 对应DI条件消失 | FC3 NETWORK4/5 |

### 4.3 消音/消光分离原则（FC3 NETWORK2/3/4）

| 操作 | 命令源 | 效果 | 不影响 |
|---|---|---|---|
| 消音 | I0.4就地按钮 OR V0.4 HMI命令 | 关Q0.7声音，置M_Sound_Latched | 灯光Q8.0、报警锁存位、VW6、状态机 |
| 消光（报警确认） | V0.3 HMI报警确认 | 根本原因消失后关Q8.0灯光、清报警锁存位、VW6=0 | — |
| 新报警重鸣 | VW6由0变非0 | 清M_Sound_Latched，Q0.7重新鸣响 | 操作员需再次消音 |

## 五、HMI组态实施要点

1. **报警指示灯阵列**：画面5按V300.0~V303.7顺序排列32个指示灯（4行×8列），每位绑定对应BOOL变量，颜色按本表"显示颜色"列配置。
2. **报警码大字显示**：画面5顶部用大字号显示VW6当前值，并按本表"显示文本"列映射中文描述。
3. **确认按钮分级**：
   - 一般报警确认按钮 → 写V0.3（CMD_AckAlarm）
   - 安全继电器故障确认按钮 → 写V0.7（CMD_SafetyRelayAck），需高权限+二次确认弹窗
4. **优先级颜色脚本**：HMI侧按VW6值区间判断颜色（99红闪/10~14红/20橙/其他黄），避免逐位判断。
5. **预留位处理**：V301.7预留,V303.2 已用于 S4 等待超时(一般级 49),V303.7预留，HMI指示灯置灰不显示，文本标注"预留"。
6. **多报警同时存在**：VW6仅显示最高优先级，但32位指示灯阵列应全部点亮活动报警位，便于操作员识别全部故障。

## 六、McgsPro 报警属性配置规范（v1.1 新增）

> **修订说明（2026-09-10）**：v1.0 只定义了业务层的优先级和颜色，未给出 McgsPro 组态软件所需的**报警分组（整数 0~255）**和**报警分级（整数 0~100）**数值配置。McgsPro 报警浏览构件和报警条构件**依赖每个变量属性页中独立配置的报警属性**才能显示报警，报警组（组对象）仅用于筛选，不自动创建报警。本章节补足 McgsPro 端的组态配置规范。

│           ↑ 必须配好才能产生报警                          │
│                                                         │
│  Layer 2: 报警组（组对象 U1_Alarm_Unit ~ U8_Alarm_Unit）│
│  ┌───────────────────────────────────────────────────┐ │
│  │ 功能：把 Layer 1 已配好报警属性的变量组织成集合    │ │
│  │ 作用：报警浏览构件/报警条构件 通过"报警对象"绑定   │ │
│  │       组对象后，只显示该组内的报警                 │ │
│  │ ⚠ 注意：只加成员不配属性 = 白搭！必须先配 Layer 1 │ │
│  └───────────────────────────────────────────────────┘ │
│                                                         │
│  Layer 3: 画面构件（报警浏览/报警条）                    │
│  ┌───────────────────────────────────────────────────┐ │
│  │ 数据来源 → 报警对象 = U1_Alarm_Unit                │ │
│  │ 数据来源 → 分组筛选 / 分级筛选（可留空=不筛选）    │ │
│  └───────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
`

### 6.2 报警分组方案（按单元号分组）

McgsPro 报警分组范围 **0~255 整数**。本项目采用**按单元号分组**，一套 McgsPro 工程监控 8 台 PLC，每台 PLC 的所有报警归入独立分组，便于按单元筛选。

| McgsPro 分组号 | 对应 PLC 单元 | MCGS 连接名 | 包含的报警变量 |
|---|---|---|---|
| **1** | 1号单元 | PLC_01 | U1_Alarm_Overflow_AHigh ~ U1_Alarm_RTC_Lost（共27个，见6.4节） |
| **2** | 2号单元 | PLC_02 | 同上，前缀 U2_ |
| **3** | 3号单元 | PLC_03 | 同上，前缀 U3_ |
| **4** | 4号单元 | PLC_04 | 同上，前缀 U4_ |
| **5** | 5号单元 | PLC_05 | 同上，前缀 U5_ |
| **6** | 6号单元 | PLC_06 | 同上，前缀 U6_ |
| **7** | 7号单元 | PLC_07 | 同上，前缀 U7_ |
| **8** | 8号单元 | PLC_08 | 同上，前缀 U8_ |
| **0** | 公共/内部变量 | — | 项目内部报警（如通讯中断、RTC 丢失等，可扩展） |

> **组态操作**：McgsPro 实时数据库 → 新增 8 个**组对象**（Group），命名 U1_Alarm_Unit ~ U8_Alarm_Unit，每个组对象的成员 = 该单元所有 Alarm 变量。

### 6.3 报警分级方案（按业务优先级）

McgsPro 报警分级范围 **0~100 整数**，值越大优先级越高。用于报警浏览构件的分级筛选、颜色分级显示。

| 业务优先级 | McgsPro 分级 | 对应报警码段 | 显示颜色 | 强制人工确认 |
|---|---|---|---|---|
| **最高级**（安全继电器故障） | **90** | 99 | 红色闪烁 | 是（V0.7 高权限 + I1.2 反馈） |
| **漫溢级** | **80** | 10 ~ 14 | 红色 | 是 |
| **节奏级** | **70** | 20 | 橙色 | 是 |
| **一般级（节奏提示）** | **50** | 21 | 黄色 | 按 M_AlarmAckMode |
| **一般级（阀门A/B/C/泵/RTC）** | **30** | 30 ~ 36, 40 ~ 47, 49, 60 ~ 65 | 黄色 | 按 M_AlarmAckMode |

> **为什么分级值用 90/80/70/50/30 而不是连续的 4/3/2/1/0**？
> 答：McgsPro 报警浏览构件的"分级筛选"支持范围语法（如 30-90），用间隔值可以在运行时灵活扩大/缩小筛选范围，避免修改所有变量的分级值。

### 6.5 McgsPro 组态操作步骤

#### 步骤 1：配置单个变量的报警属性（以 U1_Alarm_ValveA_OpenTimeout 为例）

1. McgsPro 组态环境 → **工作台** → **实时数据库**
2. 找到 U1_Alarm_ValveA_OpenTimeout 变量，**双击**
3. 在弹出的变量属性对话框中，切换到 **"报警属性"** 标签页
4. 点击 **"增加"** 按钮
5. 配置一条新报警：

| 字段 | 填写值 |
|---|---|
| 报警类型 | 开关量报警 |
| 条件 | 等于 |
| 目标值 | 1 |
| 报警说明 | 34 阀A开到位超时-检查阀A机械或限位 |
| 报警分组 | 1 |
| 报警分级 | 30 |
| 报警确认 | ☑ 勾选（一般级可按 M_AlarmAckMode 决定是否强制） |
| 闪烁效果 | ☑ 勾选（可选） |

6. 点击 **"确认"** 保存，回到实时数据库

#### 步骤 2：批量复制（减少重复劳动）

McgsPro 支持变量属性复制：

1. 选中已配好报警的变量 → 右键 → **复制**
2. 选中同类的目标变量（Ctrl 多选）→ 右键 → **粘贴报警属性**
3. 只需要修改报警说明文本（每个报警不同）、分组号（单元号）、分级值（优先级）

建议按分级分批操作：
- 先配好最高级（90）→ 复制给漫溢级（改分级为80）→ 复制给节奏级（改分级为70）→ 复制给一般级（改分级为30）
- 8 个单元按同样的分组逻辑批量复制前缀

#### 步骤 3：创建报警组（组对象）

1. 实时数据库 → **新增对象** → 类型选 **"组对象"**
2. 对象名 U1_Alarm_Unit
3. 成员 → 添加 **6.4 表中所有带序号的变量**（跳过 V301.7 / V303.3 / V303.6 / V303.7）
4. 对 2~8 号单元重复，分组号改对应单元号

#### 步骤 4：画面构件绑定

**报警浏览构件**（画面5_报警日志）：

| 属性页 | 字段 | 填写值 |
|---|---|---|
| 数据来源 | 显示模式 | 实时报警数据 |
| 数据来源 | 报警对象 | U1_Alarm_Unit（或运行时按 SelectedUnit 动态切换） |
| 数据来源 | 分组筛选 | 留空（=不筛选） |
| 数据来源 | 分级筛选 | 留空（=不筛选，或填 90 只看最高级） |
| 数据来源 | 分类筛选 | 留空 |
| 显示属性 | 列字段 | ☑ 对象名 / ☑ 报警说明 / ☑ 日期 / ☑ 时间 / ☑ 报警值 / ☑ 分级 |

**报警条构件**（画面1_总览顶部全局报警横幅）：

| 属性页 | 字段 | 填写值 |
|---|---|---|
| 基本属性 | 报警对象 | 空（显示全部） |
| 基本属性 | 显示内容 | 报警说明 + 对象名 |
| 基本属性 | 显示优先级 | 按分级（分级高的优先显示） |

#### 步骤 5：运行测试（最小化验证）

配置完成后，先验证一个变量能否正确触发：

1. McgsPro **运行环境** → 工作台 → **实时数据库**
2. 找到 U1_Alarm_ValveA_OpenTimeout → 右键 → **变量值操作** → **强制值** → 填 **1** → 确定
3. 打开画面5（报警日志页），观察报警浏览构件是否出现一行 "34 阀A开到位超时..."
4. 复位测试：右键变量 → 强制值 → 填 **0**，观察该行是否变为"已恢复"或消失

**如果强制值=1 后报警浏览里什么都没出现**，排查方向：
- 变量的"报警属性"标签页里**是否真的有一条报警配置**？（最常见遗漏）
- 报警浏览构件的"报警对象"是否为空或绑了错误的组？
- 报警浏览构件的**筛选条件**是否意外过滤了（如分级筛选填了 90，而你的报警分级是 30）？
