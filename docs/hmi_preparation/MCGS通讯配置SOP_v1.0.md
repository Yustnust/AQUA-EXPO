### 1.3 协议方案对比与选型决策

| 对比项 | 方案A：S7协议（优先） | 方案B：Modbus TCP（备选） | 方案C：混合方案 |
|---|---|---|---|
| PLC侧工作量 | 零额外编程，系统块配置IP即可 | 需OB1调用MBUS_SERVER，约1天开发量 | S7部分零工作量，Modbus部分1天 |
| HMI驱动要求 | 需S7-200 SMART驱动 | 通用Modbus TCP Client驱动 | 两种驱动并存 |
| 通讯端口 | 102（ISO-on-TCP） | 502（Modbus TCP标准） | 102+502并存 |
| 数据类型支持 | BOOL/INT/REAL/DWORD全类型原生 | 仅16位寄存器，REAL需双寄存器拼装、BOOL需按位解析 | 分协议区分 |
| 8连接数限制 | 受HMI侧S7驱动授权限制（待厂商确认） | 通常无连接数硬限制 | S7 4连接 + Modbus 4连接 |
| 通讯效率 | 高（西门子优化协议） | 中（请求-响应模式） | 取决于各单元分配 |
| 长期维护 | 与西门子生态深度集成 | 通用协议，映射表需同步维护 | 复杂度最高，不推荐 |
| 厂商推荐 | 首选 | 备选 | 仅当S7仅支持4连接时启用 |

### 1.5 8连接瓶颈分析

| 检查点 | PLC侧（S7-200 SMART CPU ST20） | HMI侧（昆仑通态MCGS） |
|---|---|---|
| 总连接数上限 | 8个以太网连接（含PG/HMI/OP/Open IE共享） | 受MCGS组态软件S7驱动授权限制 |
| 每台PLC实际占用 | 1个HMI连接资源（每PLC仅1台HMI连） | 8条并发S7连接（待厂商确认） |
| 是否瓶颈 | 否（每PLC仅1连接） | **是（关键风险点）** |
| 应对策略 | 无需调整 | 若<8连接，启用方案B或方案C |

> **关键确认事项**：AQEX-24已问询昆仑通态MCGS TPC1211-T12CE的S7驱动是否支持8连接（待回复）。回复前按方案A准备，回复后按决策树定型。

## 二、方案A：S7协议配置（优先）

### 2.1 PLC侧配置（每台PLC均需执行，仅IP不同）

#### 2.1.1 系统块配置路径

STEP 7-Micro/WIN SMART → 项目树 → CPU ST20 → **系统块** → **通信**

| 参数 | 值 | 说明 |
|---|---|---|
| IP地址 | 192.168.2.101~108（按单元号101~108） | X=单元号，1号=101，8号=108 |
| 子网掩码 | 255.255.255.0 | C类 |
| 默认网关 | 192.168.2.1 | 跨网段时启用，首期可不启用 |
| 启用DHCP | 否 | 固定IP，避免地址漂移 |
| 启用MODBUS TCP服务器 | 否 | 方案A不启用，仅方案B启用 |
| S7协议端口 | 102（默认） | ISO-on-TCP标准端口 |
| 允许PUT/GET通信访问 | 否（建议禁用） | S7协议HMI连接不需要PUT/GET，禁用提升安全性 |

#### 2.1.2 PLC连接数分配

S7-200 SMART CPU ST20本体以太网口最多支持8个连接（按固件V2.5+）：

| 连接类型 | 默认分配 | 方案A实际占用 | 说明 |
|---|---|---|---|
| PG（编程器） | 1 | 0~1（调试时占用） | STEP 7在线调试占用 |
| HMI/OP | 4~8（固件相关） | 1（每PLC仅1台HMI连） | **无瓶颈** |
| Open IE（PUT/GET/Modbus TCP） | 与HMI共享 | 0 | 方案A不启用Open IE |

**结论**：方案A下每台PLC侧仅占用1个HMI连接资源，PLC侧连接数完全无瓶颈，瓶颈在HMI侧（见1.5节）。

### 2.4 8连接限制确认方法

#### 2.4.1 8连接能力验证步骤

| 步骤 | 操作 | 期望结果 | 异常处理 |
|---|---|---|---|
| 1 | MCGS组态中建立8个S7设备实例（PLC_01~PLC_08） | 8个设备均能添加且无授权报错 | 若第5个设备添加时报"超出授权限制"→MCGS标准版S7驱动限制<8连接，**立即切换方案B** |
| 2 | 8台PLC全部上电（PLC侧IP已配置） | 8台PLC均能ping通（见5.1节） | — |
| 3 | MCGS工程运行，进入通讯维护画面 | 8个连接状态均显示"在线" | 若≤4个连接在线而>4个显示"超时"→切换方案C或B |
| 4 | 同时读取8台PLC的VW2（状态机） | 8单元状态机均能实时刷新 | 若部分单元不刷新，检查HMI侧S7驱动并发能力 |
| 5 | 长时间运行测试（24小时） | 8连接均无断线 | 若偶发断线，见第六章故障排查 |

#### 2.4.2 切换方案B的判定标准

满足以下任一条件即判定方案A不满足需求，切换方案B：

| # | 判定条件 | 检查方法 |
|---|---|---|
| 1 | MCGS无法添加第5个及以上S7设备实例 | 设备工具箱拖入设备时报授权错误 |
| 2 | 8个设备可添加但运行时仅≤4个连接能在线 | 通讯维护画面观察连接状态 |
| 3 | 厂商回复明确不支持8连接 | AQEX-24回复内容 |
| 4 | 8连接虽可建立但通讯延迟>1s或丢包率>5% | 通讯测试SOP第5.5节延迟测量 |

#### 2.4.3 切换方案C的判定标准

若厂商回复MCGS支持4连接S7（而非8连接），则：

- 1~4号PLC走S7协议（连接PLC_01~PLC_04，IP .101~.104）
- 5~8号PLC走Modbus TCP（连接PLC_05_TCP~PLC_08_TCP，IP .105~.108，端口502）
- 详见第四章方案C

## 三、方案B：Modbus TCP配置（备选）

### 3.1 PLC侧配置（每台PLC均需执行）

#### 3.1.1 系统块启用Modbus TCP服务器

| 步骤 | STEP 7-Micro/WIN SMART 菜单路径 | 操作 | 确认 |
|---|---|---|---|
| 1 | 项目树 → CPU ST20 → 系统块 → 通信 | 勾选"启用MODBUS TCP服务器" | □ |
| 2 | 系统块 → 通信 → Modbus TCP端口 | 填入 502（标准Modbus TCP端口） | □ |
| 3 | 系统块 → 通信 → 允许PUT/GET通信访问 | 可保持禁用（Modbus TCP独立于PUT/GET） | □ |
| 4 | 系统块 → 通信 → IP地址 | 192.168.2.10X（按单元号101~108） | □ |
| 5 | 系统块 → 通信 → 连接数分配 | Open IE（Modbus TCP）保留≥1连接 | □ |
| 6 | 编译并下载系统块到PLC | PLC RUN灯常亮，无错误 | □ |

#### 3.1.2 OB1调用MBUS_SERVER指令

在OB1主程序中调用MBUS_SERVER指令，将以太网口暴露V区为Modbus TCP保持寄存器：

```
// OB1 NETWORK: Modbus TCP从站初始化（每周期调用）
// 参数说明（按S7-200 SMART系统手册）:
//   HoldStart = &VB0          // V区映射起始地址（保持寄存器40001对应VW0）
//   MaxHold   = 200           // 保持寄存器数量（200个寄存器=400字节=VB0~VB399）
//   MaxInput  = 0             // 输入寄存器数量（本系统未用AI，设0）
//   MaxCoil   = 0             // 线圈数量（本系统未用线圈区，位操作按字解析）
//   MaxDisc   = 0             // 离散输入数量（本系统未用）
LD SM0.0
MBUS_SERVER VB0, 1, 1000, 1, 1000, V2.0
// 注：具体参数列表以S7-200 SMART系统手册为准，本SOP按《Modbus通讯报文规格书_v1.0》第6.1节示例
```

**MaxHold容量核算**：

| V区范围 | 字节数 | 寄存器数 | 寄存器号 | 用途 |
|---|---|---|---|---|
| VB0~VB149 | 150 | 75 | 40001~40075 | 命令/状态/状态机/参数/实测值 |
| VB150~VB199 | 50 | 25 | 40076~40100 | 纠偏中间变量 |
| VB200~VB228 | 29 | 15 | 40101~40115 | Modbus RTU层缓冲区（一般TCP不访问） |
| VB300~VB303 | 4 | 2 | 40151~40152 | 报警字4字节32位 |
| VB350~VB370 | 21 | 11 | 40176~40186 | AQEX-36迁移的6个VD参数 |
| **MaxHold=200** | **400** | **200** | **40001~40200** | **覆盖VB0~VB399，足够** |

> 若后续报警日志区VB500~VB599需通过Modbus TCP访问，需扩展MaxHold至300（VB0~VB599）；首期VB500区不通过TCP访问，MaxHold=200足够。

### 3.2 V区到保持寄存器映射规则

#### 3.2.1 映射总则

MBUS_SERVER将V区按字（VW，2字节）映射为Modbus保持寄存器（4xxxxx，16位）：

| V区数据类型 | 映射规则 | 寄存器占用 | 字节序 |
|---|---|---|---|
| VW（INT/WORD） | 1个VW = 1个保持寄存器 | 1个 | S7-200 SMART为大端，Modbus TCP亦为大端，直映 |
| VD（REAL/DWORD） | 1个VD = 2个连续保持寄存器 | 2个 | 高字在高地址（大端），跨寄存器字节序需现场实测 |
| VB（BYTE） | 1个VB嵌入1个保持寄存器的高字节或低字节 | 0.5个（按字读取） | 建议按VW读取后位运算解析 |
| V位（BOOL） | 单位无法直接映射为16位寄存器 | — | 方案1（推荐）：按VW读取后HMI侧位运算；方案2：拆字映射到线圈区（本系统未用） |
| DT（日期时间） | DT占8字节=4个保持寄存器 | 4个 | HMI侧按BCD解析 |

#### 3.2.2 地址换算公式

```
TCP寄存器号 = 40001 + (V区字节偏移 / 2)

例1：VW2 → 字节偏移2 → 寄存器号 = 40001 + 2/2 = 40002
例2：VD10 → 字节偏移10 → 寄存器号 = 40001 + 10/2 = 40006（占40006~40007）
例3：V300.0（VB300）→ 字节偏移300 → 寄存器号 = 40001 + 300/2 = 40151（占40151~40152）
```

#### 3.2.4 V位变量解析规则（重要）

由于单个V位无法直接映射为16位寄存器，HMI侧需按VW读取后位运算解析：

| V位 | 所在VW | 寄存器 | 位偏移 | HMI解析 |
|---|---|---|---|---|
| V0.0（CMD_Start） | VW0 | 40001 | bit0 | (寄存器值 AND 0x0001) ≠ 0 |
| V0.7（CMD_SafetyRelayAck） | VW0 | 40001 | bit7 | (寄存器值 AND 0x0080) ≠ 0 |
| V1.0（STA_StartAck） | VW0 | 40001 | bit8 | (寄存器值 AND 0x0100) ≠ 0 |
| V1.7（STA_TankB_State） | VW0 | 40001 | bit15 | (寄存器值 AND 0x8000) ≠ 0 |
| V300.0（M_Alarm_Overflow_AHigh） | VB300 → 40151低字节 | 40151 | bit0 | (寄存器值 AND 0x0100) ≠ 0（注意40151对应VW300，bit8~15为VB300，bit0~7为VB301） |

> **位偏移注意点**：S7-200 SMART V区按字读取时，VW0的高字节=VB0，低字节=VB1。因此V0.x在VW0的高字节（bit8~15），V1.x在VW0的低字节（bit0~7）。MCGS侧解析时需注意字节序。

### 4.4 方案C维护注意事项

| # | 注意点 | 影响 |
|---|---|---|
| 1 | 两套CSV模板需分别维护（S7版V区地址 + Modbus版寄存器地址） | 变量地址变更时需同步两套模板 |

### 6.1 常见通讯故障速查表

#### 6.1.1 连接失败类故障

| 现象 | 可能原因 | 排查方法 | 解决措施 |
|---|---|---|---|
| 单台PLC ping不通 | 网线压接不良/网线断/PLC IP未配置/端口DOWN | `ping IP`；查PLC系统块IP；查交换机端口灯 | 重新压接RJ45；配置PLC IP；更换交换机端口 |
| 全部PLC ping不通 | 交换机故障/调试机IP段错误/交换机断电 | `ping 192.168.2.2`（交换机管理IP）；`ipconfig`查调试机IP | 检查交换机供电；修正调试机IP至192.168.2.x段 |
| HMI ping通但S7连不上 | HMI驱动未配置/PG/PC接口占用/PLC连接数满 | STEP 7在线测试；查HMI驱动日志 | 关闭STEP 7释放PG连接；检查PLC连接数 |
| HMI ping通但Modbus TCP连不上 | 502端口未开放/MBUS_SERVER未调用 | `telnet 192.168.2.101 502` | 检查系统块Modbus TCP启用；检查OB1 MBUS_SERVER调用 |
| MCGS无法添加第5个S7设备 | MCGS标准版S7驱动限制<8连接 | 设备工具箱拖入设备时报授权错误 | 切换方案B（Modbus TCP）或方案C（混合） |
| HMI某单元"通讯中断" | 该PLC掉线/网线松动/IP冲突 | `ping 192.168.2.10X`；`arp -a`查MAC冲突 | 修复该PLC网络；解决IP冲突 |

#### 6.1.2 超时类故障

| 现象 | 可能原因 | 排查方法 | 解决措施 |
|---|---|---|---|
| HMI显示某单元数据不动 | S7连接假死/PLC扫描周期阻塞 | STEP 7在线查看PLC RUN灯/STOP状态 | 重启PLC；检查程序死循环 |
| Modbus TCP偶发超时 | PLC扫描周期长/MBUS_SERVER响应慢 | Wireshark抓包看请求-响应间隔 | 优化PLC扫描周期；增加HMI超时阈值 |
| 8连接并发时部分超时 | HMI侧S7驱动并发能力不足/带宽不足 | iperf3带宽测试；HMI驱动日志 | 切换方案B；降低采集频率 |
| 长时间运行后偶发超时 | 网络设备重启/UPS切换/温度异常 | 查HMI连接日志时间分布 | 加UPS稳压；查机柜温度 |
| 拔网线后不自动重连 | HMI重连配置错误/重连间隔过长 | 查HMI驱动重连参数 | 调整重连间隔为5000ms；启用自动重连 |

#### 6.1.3 数据错位类故障

| 现象 | 可能原因 | 排查方法 | 解决措施 |
|---|---|---|---|
| VD变量值异常（如1.4E-45而非5.0） | Modbus TCP REAL字节序错（高低字颠倒） | Wireshark抓包看4字节顺序；Modbus Poll读40006看原始2寄存器值 | HMI驱动配置REAL字节序为大端；或HMI侧手动拼装 |
| VW变量值异常（如256而非1） | 位偏移错误（V0.0应在VW0高字节bit8而非bit0） | Modbus Poll读40001看原始16位值 | 修正HMI位偏移配置（V0.x→bit8~15，V1.x→bit0~7） |
| 报警字位解析错误 | VB300与VW300字节序混淆 | Modbus Poll读40151看原始值 | V300.x在40151低字节bit8~15（注意VW300高字节=VB300） |
| 8单元数据互相串扰 | MCGS变量绑定连接名错误 | 检查CSV导入的"连接名"列 | 修正CSV并重新导入 |
| 写入后PLC无响应 | 写入地址错误/握手协议未遵循 | STEP 7在线监视对应V区地址 | 检查地址映射；按握手协议（V0.x置位后等V1.x确认） |
| Modbus TCP返回异常码02 | 寄存器地址超出MBUS_SERVER映射范围 | 核对变量地址表第十一章映射表 | 调整HoldStart/MaxHold参数 |
| Modbus TCP返回异常码03 | 非法数据值（如写REAL时只写1寄存器） | 检查FC06/FC16功能码选择 | VD变量用FC16写2寄存器 |
| Modbus TCP返回异常码04 | PLC内部错误（MBUS_SERVER执行失败） | STEP 7在线监视MBUS_SERVER ENO | 检查HoldStart指针/MaxHold参数 |

```
现象：HMI显示某单元通讯中断

  ├─ Step1: 调试机ping该PLC IP（ping 192.168.2.10X）
  │    ├─ ping通 → 网络OK，转Step2
  │    └─ ping不通 → 检查网线/交换机端口/PLC IP/供电
  │         ├─ 单台ping不通 → 该PLC网线/IP问题
  │         └─ 全部ping不通 → 交换机故障或调试机IP段错误
  │
  ├─ Step2: STEP 7在线连接该PLC
  │    ├─ 在线成功 → PLC正常，转Step3
  │    └─ 在线失败 → PLC停机/连接数满
  │         ├─ PLC RUN灯不亮 → PLC停机，重启PLC
  │         └─ 在线报"连接数满" → 关闭其他PG连接，释放资源
  │
  ├─ Step3: HMI工程检查该单元驱动配置
  │    ├─ 配置正确（IP/TSAP/连接名匹配） → 转Step4
  │    └─ 配置错误 → 修正IP/单元使能/连接名
  │
  ├─ Step4: Wireshark抓包分析
  │    ├─ HMI有请求、PLC有响应 → 检查HMI变量绑定（地址/数据类型）
  │    ├─ HMI有请求、PLC无响应 → PLC侧S7/Modbus服务未启用，检查系统块
  │    └─ HMI无请求 → 检查HMI驱动层/单元使能变量（UnitN_Enabled）
  │
  └─ Step5: 协议层诊断
       ├─ S7协议（方案A）：检查TSAP（本地10.00/远程02.00）/机架槽（0/1）
       └─ Modbus TCP（方案B）：telnet IP 502 测端口；Modbus Poll单点读测寄存器
```
