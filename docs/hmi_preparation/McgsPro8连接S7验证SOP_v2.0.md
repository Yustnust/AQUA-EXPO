## 〇、概述与环境准备

### 0.1 验证目标

在HMI组态完成、未上现场PLC硬件前,通过本机S7服务端模拟8台S7-200 SMART PLC,对McgsPro工程的8连接S7驱动配置进行**端到端并发验证**:

1. **单连接验证**: 确认1台PLC的S7通讯链路、变量读写、状态机联动正确
2. **8连接并发**: 确认8台PLC同时在线、728通道稳定刷新、无超时断连
3. **故障恢复**: 确认单PLC掉线/网络抖动后,其余单元不受影响且可自动重连
4. **性能极限**: 探测采集周期与通道数上限,为现场部署留出余量

### 0.2 通道规模说明

任务书目标: 8×91变量=728通道。
当前 `McgsPro变量导入_8单元_v2.0.csv` 实测 **600通道(8×75)**,已覆盖8单元全部VW/VD/VB/V位核心变量。
- 第二阶段验证以CSV实际600通道为准(导入流程完全一致)
- 第四阶段将扩展至728通道(每单元补16个备用变量)及1000+通道(每单元补~50个备用变量),验证上限
- 728与1000+通道均使用同一CSV模板按相同格式追加,不影响SOP操作步骤

### 0.3 验证通过标准(总览)

| 项 | 通过标准 |
|---|---|
| 8连接全部建立 | 8/8在线,无连接失败 |
| 10分钟稳定性 | 无超时、无断连、无重连风暴 |
| 728通道刷新 | 全部变量延迟<500ms(实测应<50ms本机) |
| 并发写入8单元 | 8个CMD_Start=1同时下发,无冲突、无丢包 |
| 单PLC断开隔离 | 断开1台后其余7台不受影响 |
| 网络抖动恢复 | ifconfig down/up后30秒内自动重连 |
| CPU占用 | McgsPro运行期CPU<30%,内存<200MB |
| 网络流量 | 8连接稳定在<200KB/s |

### 0.4 验证失败备选方案

| 故障现象 | 备选方案 |
|---|---|
| 8连接不稳定(频繁断连) | 改用Modbus TCP(PLC侧OB1调用MBUS_SERVER,详见《MCGS通讯配置SOP_v1.0》第三章) |
| 性能不足(CPU>50%或刷新>500ms) | 采集周期降至500ms,或拆分到2台HMI(1~4号单元+5~8号单元) |
| 单连接失败但其他正常 | 排查对应端口/父设备IP配置,勿整体回退 |
| 8连接建立但偶发超时 | 启用McgsPro"采集优化"=优化,降低静态变量采集频率至1000ms |

**自检失败处理**:
- Python版本低 → 升级Python或用 `py -3` 指定版本
- PLCSim加载失败 → 检查 `plc_simulator.py` 是否在 `s7_server.py` 同目录

- 端口被占 → `taskkill /F /PID <占用进程>` 或改用其他起始端口

### 0.7 通用约定

**日志级别**:
- INFO(默认): 输出连接建立/断开/状态转移,适合本SOP主流程
- DEBUG: 输出每一帧S7报文,适合排查协议问题
- WARNING: 仅输出异常,适合长时间稳定性测试(降低日志干扰)

**McgsPro模拟运行**:
- 入口: 工具→模拟运行(快捷键F5)
- 退出: 模拟环境窗口右上角关闭,或Alt+F4
- 重新进入: 修改组态后需先关闭模拟运行,再F5重启

**性能监控三类工具**:
1. **Windows任务管理器**: 监控McgsPro进程CPU/内存/网络
2. **McgsPro设备状态**: 设备窗口双击子设备→"设备调试"页查看在线状态/采集计数/错误码
3. **s7_server.py监控输出**: 每5秒打印8单元VW2/VW6/VW8/扫描周期/连接数

```python
# save as /tmp/set_vd10.py, run while s7_server.py is running
import socket, struct, threading

def set_vd10(port, value):
    """写VD10为指定浮点值"""
    sock = socket.socket()
    sock.connect(('127.0.0.1', port))
    # COTP CR
    sock.sendall(b'\x03\x00\x00\x16\x11\xe0\x00\x00\x01\x00\x01\x00'
                 b'\xc0\x01\x0a\xc1\x02\x01\x00\xc2\x02\x02\x00')
    sock.recv(1024)
    # Setup
    sock.sendall(b'\x03\x00\x00\x19\x02\xf0\x80'
                 b'\x32\x01\x00\x00\x00\x01\x00\x04\x00\x06'
                 b'\x28\x00\x01\x00\x00\x08\x01\xc0\x01\xc0')
    sock.recv(1024)
    # Write VD10 (area=0x85, db=1, addr=10, len=4, float=value)
    packed = struct.pack('>f', value)
    item = bytes([0x12, 0x0A, 4, 1, 0x85, 0, 0, 10, 0, 0, 0, 0])
    data_item = bytes([0x03, 0x06, 0, 4]) + packed
    req = (b'\x03\x00\x00\x25\x02\xf0\x80'
           b'\x32\x01\x00\x00\x00\x02\x00\x0e\x00\x08'
           b'\x05\x01') + item + data_item
    sock.sendall(req)
    sock.recv(1024)
    sock.close()
    print(f"port {port} VD10={value} written")

# 并发写8单元VD10为不同值
threads = []
for i, val in enumerate([5.0, 5.5, 6.0, 6.5, 7.0, 7.5, 8.0, 8.5]):
    t = threading.Thread(target=set_vd10, args=(10200+i, val))
    threads.append(t); t.start()
for t in threads: t.join()
print("8 units VD10 set concurrently")
```

### D.3 s7_server.py监控表

每5秒(可配 `--monitor-interval`)打印一次:
```
单元    端口    VW2     VW6     VW8     扫描周期  连接数
-----------------------------------------------------------------
U1     10200   1       0       0       6000      1
...
```

| 列 | 含义 | 异常判断 |
|---|---|---|
| VW2 | 状态机值(0~7/99) | 应稳定,不应跳变 |
| VW6 | 报警码 | 应=0,非0表示报警 |
| VW8 | 实验轮次 | 应稳定,运行实验时递增 |
| 扫描周期 | PLC累计扫描次数 | 应每秒+10(100ms周期) |
| 连接数 | 该端口客户端连接数 | 应=1(McgsPro单连接/单元) |

## 附录E:常见错误码与排查

### E.1 s7_server.py日志错误码

| 错误码 | 含义 | 排查 |
|---|---|---|
| 0xFF | 成功 | — |
| 0x85 | 资源/区域错误 | 检查area/db/addr,常见为地址越界(V>599) |
| 0x87 | 数据格式错误 | 检查transport_size |
| 0xD2 | 变量不存在 | 检查V区地址范围 |
| 0xD6 | 写入冲突 | PLC锁竞争(罕见) |

### E.2 McgsPro设备调试错误码

| 错误码 | 含义 | 排查 |
|---|---|---|
| 0 | 无错 | — |
| 1 | 通讯超时 | s7_server未启动或端口错 |
| 2 | 连接失败 | IP/端口/防火墙 |
| 3 | 协议错误 | TSAP/机架槽配置错 |
| 4 | 数据格式错误 | 字节序/数据类型错 |

### E.3 典型故障排查流程

```
故障: McgsPro某单元离线
  ↓
1. 检查s7_server.py是否运行 → 否 → 启动s7_server.py
  ↓ 是
2. 检查s7_server.py监控表该单元"连接数" → 0 → McgsPro未连接
  ↓ 1
3. 检查McgsPro父设备IP/端口配置 → 错 → 修正
  ↓ 对
4. 检查Windows防火墙 → 阻断 → 加白名单
  ↓ 通过
5. 抓包Wireshark看COTP/S7握手 → 异常 → 看s7_server.py DEBUG日志
  ↓ 正常
6. 联系厂商(McgsPro驱动问题)
```
