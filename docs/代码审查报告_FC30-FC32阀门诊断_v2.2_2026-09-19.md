## 〇、整体评价

| 维度 | 评价 |
|---|---|
| **栈管理** | ✅ 基本规范：`TON` 前都用 `LD SM0.0` 或其他明确的 `LD`，没有发现 LPS 后栈空导致的 TON 失效 |
| **JMP/LBL** | ✅ 单 NETWORK 模式，所有跳转在同一 NETWORK 内（P2 修复痕迹明显） |
| **子状态机** | ✅ 结构清晰：空闲 → 等开到位 → 开启完成 → 运行中 → 等关到位 |

## 一、🟠 P1 - 严重 BUG

### BUG #V1：`FC30` 子状态 1 中 `TON T50` 被同一 NETWORK 中其他指令的栈消耗"绕过"

**严重度**：🟠 P1 严重（实际可能是 false positive，但存在隐患）

**位置**：`FC30_ValveA_Diag.stl` L75-94

```stl
LBL    3
// T50超时计时(PT=VW278, 由FC11计算VD358×10写入)
LD     SM0.0
TON    T50, VW278                    ; ⚠️ T50 使能 = SM0.0 = ON，正常计时

// I8.0开到位反馈=ON → 转子状态2
LD     I8.0
MOVW   2, VW260
R      T50, 1
JMP    1

// T50超时 → 开到位超时报警
LD     T50
S      V301.4, 1
MOVW   99, VW2
MOVB   2, VB266
JMP    1
```

**问题分析**：
- `TON T50, VW278` 前 `LD SM0.0` 提供栈顶（TRUE），TON 使能正常。
- 下面 `LD I8.0; MOVW 2, VW260; R T50, 1; JMP 1` 是独立的指令链，**不会消耗 TON 的栈**（TON 不消耗栈）。
- 但 `R T50, 1` 会**复位 T50**——若 I8.0 已 ON，会立即 R T50，超时永远不会触发；这反而是正确的（开到位后就不再计时）。

**结论**：这段代码**逻辑正确**。但与 FC31/FC32 子状态 1 中 `TON T53/T56 + EU + MOVW` 的模式不同，**FC30 没有使用 `EU` 上升沿触发**，而是用常开触点。这与文件头注释的"P3 修复：去掉 EU"一致——因为 PLC 冷启动时阀可能已开到位，常开触点能立即进入子状态 2。

**风险**：若 I8.0 信号抖动（chattering），**可能造成子状态在 1/2/3 之间反复跳变**（每次抖动一次就 MOVW 2, VW260 → R T50 → JMP 1；但下次扫描 I8.0 又 ON，又重复进入；不过 VW260=2 后子状态已转 2，不会再触发子状态 1 逻辑）。**实际无影响**。

### BUG #V2：`FC31` 子状态 1 中 `TON T53` 和 `TON T54` 共享同一个 PT(VW274)，但都被同一条件触发，**超时永远同时发生**

**严重度**：🟠 P1 严重（设计漏洞）

**位置**：`FC31_ValveB_Diag.stl` L66-93

```stl
LBL    3
// T53开到位超时 + T54流量开关超时(两套独立判据)
LD     SM0.0
TON    T53, VW274                  // PT=VD_Timeout_ValveB(VD362)×10
TON    T54, VW274                  // 流量开关超时(同参数，独立计时)

// 开到位=ON → 转S2
LD     I8.2
EU
MOVW   2, VW262
R      T53, 1
R      T54, 1
JMP    1

// 开到位超时 → 报警
LD     T53
S      V302.1, 1
MOVW   99, VW2
MOVB   2, VB268
JMP    1

// 流量开关超时(开阀后一直无流) → 报警
LD     T54
AN     I0.1
S      V302.2, 1
MOVW   99, VW2
MOVB   2, VB268
JMP    1
```

**问题分析**：
- 注释说"T53开到位超时 + T54流量开关超时(**两套独立判据**)"
- 但两个 TON 使用**完全相同的 PT（VW274）**
- 两个 TON 都用 `LD SM0.0` 触发，**同时启动、同时 Done**
- 报警分支也有问题：**先查 T53 → 转 S_ERROR + JMP 1**，永远不会走到 T54 报警分支——T54 报警永远被 T53 "掩盖"
- 设计文档说"两套独立判据可互相印证"，但实际**只有 T53 生效**

**后果**：
- 如果实际故障是"开到位但一直无流"（流量开关 B 故障），T53 和 T54 同时 Done，但 T53 报警先触发，操作员只看到"开到位超时"，无法定位是限位反馈故障还是流量开关故障
- 设计文档第七章（阀 B 诊断）说的"四态独立判据"在 S7-200 SMART 上**用两个 TON 共享 PT 实现不了真正独立**——它们必须用**不同的 PT**（如 T53 = 开到位超时，T54 = 流量开关超时，且 T54 的 PT 必须显著大于 T53 的 PT，给限位反馈留出反应时间）

**修复建议**：
```stl
NETWORK X
// T53开到位超时
LD SM0.0
TON T53, VW274              // PT = VD362 × 10

NETWORK Y
// T54流量开关超时（独立参数）
LD SM0.0
TON T54, VWxxx              // PT = 独立的 VDxxx × 10，必须 > VW274
```

### BUG #V3：`FC30` 漫溢保护 `MOVW 99, VW2` 与同 NETWORK 中其他路径冲突——漫溢与子状态调度都改写 VW2

**严重度**：🟠 P1 严重（逻辑耦合）

**位置**：`FC30_ValveA_Diag.stl` L41-49

```stl
// ========== 第一部分: 漫溢保护(优先级最高,全程监控) ==========
LD     I0.5                        // 液位计A高位=漫溢
S      V300.0, 1                   // M_Alarm_Overflow_AHigh
S      V300.2, 1                   // M_Alarm_NCValve_Top
R      Q0.5, 1                     // 关NC球阀(切断水流)
R      Q0.2, 1                     // 关阀A
MOVW   99, VW2                     // 转S_ERROR
MOVB   2, VB266                    // Diag_Result_A=2故障
JMP    1                           // 跳到结束
```

**问题分析**：
- 漫溢分支用 `MOVW 99, VW2` 转 S_ERROR
- 下面的子状态分支（L57-65）若进入子状态 3，也会用 `MOVW 99, VW2` 转 S_ERROR（多个分支都改 VW2）
- **整个 NETWORK 中只有 1 个 LBL 1 汇合点**，但每个分支用 JMP 跳到 LBL 1
- 漫溢检测的"优先级最高，全程监控"实际上**只在 FC30 被调用时才生效**——而 FC30 **只在 S1 期间被调用**（FC11 → FC30）
- **S2/S3/S4/S5/S6/S7 期间没有漫溢保护！**

**风险**：
- 如果上缸液位漫溢发生在 S3（加药）期间，FC30 不会被调用，**I0.5 高位报警不会被触发**
- 但 FC3（报警处理）和 OB1 NETWORK 12（系统状态）可能会单独处理——需要看 FC3 是否独立监控 I0.5

**修复建议**：
- 把漫溢保护移到 FC3 或 OB1 顶层，**全程每周期监控**，而非依赖 FC30 调用
- 或者在 FC1A/FC13/FC15/FC17 每个状态 FC 内显式调用 FC30 漫溢部分

### BUG #V4：`FC31` 子状态 1 中 `TON T54` 后用 `AN I0.1` 检查"流量开关仍 OFF"——但 `TON T54` 已经 Done 时 I0.1 状态未知

**严重度**：🟠 P1 严重（逻辑漏洞）

**位置**：`FC31_ValveB_Diag.stl` L87-93

```stl
// 流量开关超时(开阀后一直无流) → 报警
LD     T54
AN     I0.1                        // 确认流量开关B仍OFF
S      V302.2, 1                   // M_Alarm_ValveB_OpenNoFlow
MOVW   99, VW2
MOVB   2, VB268
JMP    1
```

**问题分析**：
- T54 用与 T53 **相同的 PT（VW274）**
- T54 Done 时，I0.1 可能处于任何状态：
  - **OFF**（无流）→ AN I0.1 = TRUE → 触发 V302.2 "开阀后一直无流"
  - **ON**（有流）→ AN I0.1 = FALSE → 不触发，**但这种情况说明"流量开关已 ON"，为何 T54 会 Done？**
- 由于 T54 与 T53 共享 PT 且都从开阀瞬间启动，**T54 Done 时 I0.1 必然 OFF**（除非限位反馈在 0.1 秒内触发且流量开关故障，这是极端情况）
- 因此 `AN I0.1` 是**冗余条件**，不影响实际行为

**但更深层的问题**：T53 和 T54 共享 PT + 相同启动条件，导致**这两个"独立判据"实际上是一回事**。如果 PT 设为 5 秒，两个 TON 都在 5 秒后 Done——一个检查"5 秒后开到位是否反馈"（T53），一个检查"5 秒后流量开关是否 ON"（T54）。**两者必须用不同的 PT**：T53 应较短（如 3 秒），T54 应较长（如 8 秒），给流量开关留出"阀开 → 水流到达传感器"的物理延迟。

**修复建议**：
- T54 用独立 VWxxx（独立 PT）
- PT 必须 > T53 的 PT（建议 T54 ≥ T53 × 2）
- 这样才能真正实现"互相印证"

## 二、🟡 P2 - 中等 BUG

### BUG #V5：跨 FC 接口契约不一致——`VB266` vs `VB268/VB270` 写入方式不同

**严重度**：🟡 P2 中等

**位置**：
- `FC30_ValveA_Diag.stl` L48、L94、L111、L178、L190：用 `MOVB` 写 `VB266`
- `FC31_ValveB_Diag.stl` L40、L85、L92、L109、L133、L151：用 `MOVW` 写 `VB268`
- `FC32_ValveC_Diag.stl` L40、L70、L78、L94、L113、L132、L141、L149：用 `MOVW` 写 `VB270`

**调用方检查方式**：
- `FC11` L77：`LDB= VB266, 1`（字节比较）
- `FC15` L87：`AB= VB268, 1`（字节比较）
- `FC17` L39：`AB= VB270, 1`（字节比较）

**问题**：
- FC30 用 `MOVB` 写 VB266（低字节），但调用方用 `LDB=` 字节比较——**一致**
- FC31/FC32 用 `MOVW` 写 VB268/VB270（写完整 WORD），但调用方用 `AB=` 字节比较——**这也工作**（MOVW 会把高字节 VB269/VB271 清零）
- **但**：FC32 的注释 L132、L141、L149 说"已修正：用 MOVW 写完整 WORD"——**说明历史上曾经是 MOVB，后来改 MOVW**。这暗示**之前可能存在 bug**（MOVB 时 VB270 高字节 VB271 未清零，导致比较错乱）。

**为什么说"接口契约不一致"**：
- FC30 的诊断结果字 = `VW266 = VB266 + VB267 × 256`
- FC31 的诊断结果字 = `VW268 = VB268 + VB269 × 256`
- FC32 的诊断结果字 = `VW270 = VB270 + VB271 × 256`
- 但 FC30 用 `MOVB`，FC31/FC32 用 `MOVW`——**不一致**
- 调用方 FC11/FC15/FC17 都用字节比较（`LDB=` 或 `AB=`），所以**当前调用都没问题**
- 但**若未来有人加 HMI 显示 VW266/VW268/VW270，会看到 FC30 只显示低字节有效，FC31/FC32 显示完整 WORD**——这是隐性陷阱

**修复建议**：统一为 `MOVW`（写完整 WORD），并把 `VB267/VB269/VB271` 在初始化时清零。

### BUG #V6：`FC30` 漫溢保护后未调用 FC30 自身的"复位"动作——`V300.0/V300.2` 报警位永久置位

**严重度**：🟡 P2 中等

**位置**：`FC30_ValveA_Diag.stl` L41-49

```stl
LD     I0.5
S      V300.0, 1
S      V300.2, 1
R      Q0.5, 1
R      Q0.2, 1
MOVW   99, VW2
MOVB   2, VB266
JMP    1
```

**问题**：
- `S V300.0, 1` 永久置位——**直到 V0.3 人工确认才能清除**
- 但液位计 A 高位是**物理信号**，若 I0.5 抖动（chattering）或短时触发，**V300.0 仍然置位，系统永久 S_ERROR**
- 漫溢风险级报警是"强制人工确认"——这点**符合设计**（文档 §8.1）
- 但**没有任何机制防止 I0.5 短时尖峰触发永久 S_ERROR**——若现场电磁干扰造成 I0.5 抖动 1 个扫描周期，系统就死锁

**修复建议**：
- 加"漫溢信号需要持续 N 秒才认定"的延时确认
- 或在报警条件中加入"上缸状态=非空"作为辅助判断（空缸不可能漫溢）

### BUG #V7：`FC30` 子状态 2 缺少"阀已关但 I8.0 仍 ON"的判定——可能错过"开到位信号粘连"

**严重度**：🟡 P2 中等

**位置**：`FC30_ValveA_Diag.stl` L97-112

```stl
LBL    4
// I0.0流量开关A=ON → 正常有流, 转子状态3运行中
LD     I0.0
MOVW   3, VW260
JMP    1

// 开到位但无流 → 加2s延时确认避免瞬时波动
LD     I8.0
AN     I0.0
TON    T52, 20
LD     T52
S      V301.5, 1
MOVW   99, VW2
MOVB   2, VB266
JMP    1
```

**问题**：
- 子状态 2 的逻辑：流量开关 ON → 转子状态 3；开到位 ON + 流量开关 OFF → 2 秒后报警
- **缺失**：若 I8.0（开到位反馈）已 OFF（阀已关），但 VW260 还停留在子状态 2，**系统会卡死**
- I8.0 = OFF 的情况：
  - 正常情况（阀已关）→ 应转子状态 0（空闲）或子状态 5（关阀后验证）
  - 但当前代码**只在 I0.0 ON 时转子状态 3**，其他情况都被忽略
- 若 I8.0 OFF + I0.0 OFF（流量开关未触发 + 限位已 OFF），代码走 `LD I8.0; AN I0.0; TON T52, 20` ——TON 启动，**但 T52 永远不会 Done**（因为 I0.0 一直 OFF 是合理状态），最终会一直停在子状态 2，**TON T52 持续计时直到 2 秒报警**

**修复建议**：
```stl
// 新增分支: I8.0 OFF (阀已关) → 转子状态 5 (关阀后验证)
LD     I8.1                        // 关到位反馈（注意是 I8.1 不是 I8.0）
MOVW   5, VW260
JMP    1
```

### BUG #V8：`FC31` 子状态 3 四态诊断逻辑顺序错误——"状态 4 设备故障"判定先于"状态 1/2 正常"判定

**严重度**：🟡 P2 中等（逻辑顺序问题）

**位置**：`FC31_ValveB_Diag.stl` L113-137

```stl
LBL    5
// 状态3: 流量开关OFF + 液位低位ON → 上缸排空，关阀触发
LD     I0.6
AN     I0.1
R      Q0.3, 1
MOVW   4, VW262
JMP    1

// 状态4: 流量开关OFF + 液位低位OFF → 设备故障
LD     I0.1
NOT
AN     I0.6
S      V302.0, 1
MOVW   99, VW2
MOVB   2, VB268
JMP    1

// 状态1/2: 流量开关ON → 正常转移中/即将排空，继续
LD     I0.1
JMP    1
```

**问题分析**：
- STL 是**顺序执行**的（不是并行）
- 第 1 个分支：`I0.6 ON AND I0.1 OFF`（上缸排空 + 流量开关 OFF）→ 关阀转子状态 4
- 第 2 个分支：`I0.1 OFF AND I0.6 OFF`（流量开关 OFF + 液位低位 OFF）→ 报警
- 第 3 个分支：`I0.1 ON`（流量开关 ON）→ 正常继续
- **逻辑上**：第 1 个分支已经处理了 `I0.1 OFF` 的情况；第 2 个分支又处理 `I0.1 OFF`——**重复**
- 第 2 个分支 `LD I0.1; NOT; AN I0.6` 等价于 `LDN I0.1; AN I0.6`
- 但 STL 里：**如果第 1 个分支条件满足，已经 `MOVW 4, VW262; JMP 1`**，永远不会执行第 2 个分支
- **如果第 1 个分支条件不满足（I0.6 OFF），就会继续到第 2 个分支**
- 第 2 个分支 `LDN I0.1; AN I0.6`：若 I0.1 OFF 且 I0.6 OFF → 报警

**实际行为**：
- 转移刚开始时（子状态 3 刚进入）：阀已开（Q0.3=ON），流量开关 B 可能 ON 或 OFF（取决于水到达传感器的延迟）
  - 若 I0.1 OFF + I0.6 OFF（液位计未到低位、流量开关未触发）→ **立即报警 V302.0**——这是**误报**！转移刚启动几秒，不应该判定故障
  - 注释 L128 也承认"需排除刚开始转移时的瞬时(流量开关尚未ON)"——但代码没实现这个保护

**修复建议**：
- 加"转移初期延时确认"：进入子状态 3 后 2~3 秒内不判定状态 4
- 或子状态 3 拆分为 3a（转移初期等待）、3b（稳态诊断）

### BUG #V9：`FC32` 缺少漫溢保护——设计文档说"阀 C 无漫溢"但实际下缸排水口附近可能积液

**严重度**：🟡 P2 中等

**位置**：`FC32_ValveC_Diag.stl` 整个文件（无 I0.7 监控）

**问题**：
- FC30 监控 `I0.5`（液位计 A 高位，上缸漫溢）
- FC31 监控 `I0.7`（液位计 B 高位，下缸漫溢）
- FC32 没有漫溢监控
- 注释 L7 说"阀 C 无漫溢保护(下缸排水不会漫溢)"
- 但**排水过程中下缸正在排水**——液位计 B 高位可能在 S6 开始时短暂触发（如果上轮 S4 转移后下缸液位已接近高位）
- 文档 §2.1 表 I0.7 是"液位计 B-高位(下缸液位达最高警戒，防漫溢，对称保护)"——FC32 应该监控 I0.7

**修复建议**：
- 在 FC32 开头加 `LD I0.7; S V300.1; ...` 漫溢保护（与 FC31 对称）

### BUG #V10：`FC31` 子状态 4 中"内漏"判定使用 `A I0.1`（流量开关 ON）——但关阀瞬间流量开关可能仍有流（惯性）

**严重度**：🟡 P2 中等

**位置**：`FC31_ValveB_Diag.stl` L155-161

```stl
// 关到位=ON AND 流量开关=ON → 内漏
LD     I8.3
A      I0.1
S      V302.4, 1                   // M_Alarm_ValveB_CloseLeak
MOVW   99, VW2
MOVB   2, VB268
JMP    1
```

**问题**：
- 关到位反馈（I8.3）=ON + 流量开关（I0.1）=ON → 判定内漏
- 但**水流动有惯性**——阀刚关时，流量开关 B 可能仍有 0.5~2 秒流量
- 当前代码没有延时确认，**可能误报内漏**
- FC30 的关阀验证有 5 秒延时（VD66 默认），FC31 没有类似保护

**修复建议**：
- 在子状态 4 进入后启动 T55（关到位超时），但**判定内漏前加 2 秒延时**
- 或复用 FC30 的延时验证机制

## 三、🟢 P3 - 低优先级问题

### P3-V1：`FC30` 漫溢保护中 `R Q0.5, 1; R Q0.2, 1` 后立即 `MOVW 99, VW2`——但 Q 点复位可能被上层 FC 重新置位

**位置**：`FC30_ValveA_Diag.stl` L45-47

```stl
R      Q0.5, 1
R      Q0.2, 1
MOVW   99, VW2
```

**问题**：
- FC30 复位 Q0.2/Q0.5，但 FC1A（VW304=2）每周期会 `S Q0.0, 1; S Q0.1, 1`（潜水泵）
- **如果漫溢发生在 S2（VW304=2）期间**：FC30 会被调用吗？——**不会！**（FC30 只被 FC11 在 VW304=1 时调用）
- 所以"FC30 复位 Q0.2/Q0.5"只在 S1 期间有效——但 S1 期间 FC1A 不会被调度（FC1A 只在 VW304=2 时被 OB1 调用）
- **实际影响小**，但**漫溢监控不在 S2/S3/S5/S6 期间生效**——这是设计漏洞（参见 BUG #V3）

---

### P3-V2：`FC31` 子状态 1 中 `EU` 上升沿触发——若 PLC 冷启动时阀已开到位（I8.2=ON），无法进入子状态 2

**位置**：`FC31_ValveB_Diag.stl` L73-78

```stl
LD     I8.2
EU
MOVW   2, VW262
```

**问题**：
- FC30 用了 P3 修复（去掉 EU），改常开触点
- 但 FC31/FC32 仍用 EU——**冷启动时若阀已开到位，会卡在子状态 1 永远超时**
- 文档说明（P3 修复）应该同步应用到 FC31/FC32

**修复建议**：与 FC30 一致，去掉 EU，改用常开触点。

---

### P3-V3：`FC32` 子状态 4 中 `MOVW 0, VW264` 与 `MOVW 1, VW270` 之间无 `JMP`——若 VW264=0 但条件不满足，VW270 不会被写

**位置**：`FC32_ValveC_Diag.stl` L128-134

```stl
LBL    5
// T58关到位超时
LD     SM0.0
TON    T58, VW276

// 关到位=ON AND 流量开关=OFF → 正常完成
LD     I8.5
AN     I0.2
MOVW   0, VW264
MOVW   1, VW270
R      T58, 1
JMP    6
```

**问题**：
- `LD I8.5; AN I0.2; MOVW 0, VW264; MOVW 1, VW270; R T58, 1; JMP 6` 是**指令链**
- `MOVW 0, VW264` 消耗栈顶（I8.5 AND NOT I0.2）
- `MOVW 1, VW270` 消耗栈顶（栈空，不执行！）
- `R T58, 1` 消耗栈顶（栈空，不执行！）
- `JMP 6` 不消耗栈

**实际行为**：
- VW264 会被写 0
- **VW270 不会被写**（仍然保持原值）
- **T58 不会被复位**（继续计时）
- **JMP 6** 仍然执行（跳到结束）

**结论**：
- **VW270 写 1 失败**——调用方 FC17 检查 `AB= VB270, 1` 会失败，系统卡在 S6 完成判定
- **T58 不复位**——下次进入子状态 4 时 T58 累计计时，可能立即 Done

**修复建议**：每个 MOVW 独立 LD：
```stl
LD I8.5
AN I0.2
MOVW 0, VW264                    ; VW264=0空闲

LD I8.5
AN I0.2
MOVW 1, VW270                    ; VW270=1正常完成

LD I8.5
AN I0.2
R    T58, 1                      ; 复位延时计时

JMP 6
```

---

### P3-V4：`FC31` 子状态 4 中 `MOVW 0, VW262; MOVB 1, VB268; R T55, 1` 也是同样的栈消耗问题

**位置**：`FC31_ValveB_Diag.stl` L147-153

```stl
LD     I8.3
AN     I0.1
MOVW   0, VW262
MOVB   1, VB268
R      T55, 1
JMP    1
```

**问题**：与 P3-V3 完全相同——MOVW/MOVB/R 都消耗栈，后两条不执行。
- **VB268 写 1 失败**
- **T55 不复位**
- JMP 1 仍然执行

**但**：FC31 调用方 FC15 用 `AB= VB268, 1` 检查——若 VB268 没写 1，FC15 检查失败，**S4 完成判定永远不触发**。

**修复建议**：同 P3-V3，每个 MOVW/MOVB/R 独立 LD。

---

### P3-V5：`FC30` 子状态 5 中 `MOVW 0, VW260; MOVB 1, VB266; R T51, 1; JMP 1` 同样是栈消耗问题

**位置**：`FC30_ValveA_Diag.stl` L168-179

```stl
LD     T51
LPS
AN     I0.0
LPS
A      I8.1
ALD
ALD
MOVW   0, VW260                    ; VW260=0空闲
MOVB   1, VB266                    ; Diag_Result_A=1正常完成
R      T51, 1                      ; 复位延时计时
JMP    1
LPP
LPP
```

**问题**：
- LPS 后有 2 层栈
- AN I0.0; LPS; A I8.1; ALD; ALD — 第一个 LPS 后再 LPS，栈深最多 2；ALD 弹栈，最终栈深 1
- **MOVW 0, VW260 消耗栈顶，栈空**
- **MOVB 1, VB266 不执行**
- **R T51, 1 不执行**
- **JMP 1 仍然执行**

**后果**：
- VW260 写 0 成功（消耗栈顶那次）
- VB266 写 1 失败
- T51 不复位
- 调用方 FC11 检查 `LDB= VB266, 1` 失败，**S1 完成判定永远不触发**

**修复建议**：同 P3-V3，每个 MOVW/MOVB/R 独立 LD，且去掉多余的 LPS。

---

### P3-V6：注释与代码不一致——`FC31` 文件头注释说"诊断子状态 VW262: 0空闲/1等开到位/2开启完成/3运行中/4等关到位"，但代码使用"4 等关到位"而非文档某些位置写的"5"

**位置**：`FC31_ValveB_Diag.stl` L7 注释 + 实际代码

**问题**：纯注释问题，无实际影响。

---

### P3-V7：`FC30/FC31/FC32` 都没有"诊断子状态非法值"保护——若 VW260/VW262/VW264 因外部干扰变成非法值（如 6、7），子状态调度跳到 LBL 1 结束，但**不报警、不复位**

**位置**：所有三个文件

**问题**：
- `JMP 1`（FC30/FC31）或 `JMP 6`（FC32）是兜底分支
- 若子状态 = 非法值（如 99），没有报警、没有复位，系统会**永远卡住**

**修复建议**：
- 兜底分支加报警 `S V301.x, 1` 或 `MOVW 99, VW2`

---

### P3-V8：`FC30` 子状态 5 中 `LPS/LPP` 配对混乱

**位置**：`FC30_ValveA_Diag.stl` L166-181

```stl
LD     T51
LPS                                ; 保存 T51
AN     I0.0                        ; (NOT I0.0)
LPS                                ; 再保存
A      I8.1                        ; I8.1
ALD                                ; (NOT I0.0) AND I8.1
ALD                                ; AND T51
MOVW   0, VW260
MOVB   1, VB266
R      T51, 1
JMP    1
LPP                                 ; 内层 LPP
LPP                                 ; 外层 LPP
```

**问题**：
- 2 个 LPS 配 2 个 LPP，但 LPS 之间没有新的 LD/AND/OR 操作（只是 AN 和 A）
- 实际上**只需要 1 个 LPS**

**修复**：
```stl
LD     T51
LPS
AN     I0.0
A      I8.1
ALD
MOVW   0, VW260
MOVB   1, VB266
R      T51, 1
JMP   1
LPP
```

## 七、整体建议

1. **FC30/FC31/FC32 整体质量可接受，但栈消耗问题（P3-V3/V4/V5）必须修复**——这三个 BUG 会让"正常完成"判定不触发，整个阀门流程永远卡死
2. **漫溢保护应该移到 OB1 顶层**——不应依赖特定状态 FC 的调用（BUG #V3/V9）
3. **两套独立超时判据必须用独立 PT**（BUG #V2/V4）——当前共享 PT 让"独立判据"名不副实
4. **冷启动 EU 问题需要同步修复**——FC30 已修，FC31/FC32 仍存在（P3-V2）
5. **建议补充单元测试**——每个子状态都应该有"故意触发该子状态 → 验证诊断结果"的自动化测试

## ⚠️ 修订声明(2026-09-19 追加)

**本报告存在"栈消耗 BUG"过度评估的问题**。

在编写本报告时,我对 S7-200 SMART STL 指令的栈行为存在系统性误判:
- 误以为 `MOVx 立即数/字地址, OUT` 会消耗栈顶

**实际正确行为**(经西门子官方文档确认):
- `MOVx IN, OUT` 当 IN 是立即数或字地址时,**不消耗栈**,无条件执行

**本报告的真实情况**:
- 原报告 P3-V3/V4/V5(FC30/FC31/FC32 栈消耗问题):**部分确认**——只有真正的 `LD + S/R + S/R` 链才会触发
- FC30 L168-179 LPS 后栈空:`R T51, 1` 消耗栈顶后,后续 `MOVW 0, VW260; MOVB 1, VB266; R T51, 1` 中的 MOV 不消耗栈,但 R 在 S 之后栈空——**MOVB 1, VB266 不执行**(栈空)
- FC31/FC32 同理

**本报告真正确认的 P1/P2 BUG(不依赖栈分析)**:
- #V2 FC31 独立超时判据共享 PT(P1,确认)
- #V3 漫溢保护依赖 FC30 调用(P1,确认)
- #V5 跨 FC 接口契约不一致(P2,确认)
- #V6 I0.5 短时尖峰永久 S_ERROR(P2,确认)
- #V7 I8.0 OFF 卡死(P2,确认)
- #V8 状态 4 误报(P2,确认)
- #V9 FC32 缺漫溢保护(P2,确认)
- #V10 关阀内漏误报(P2,确认)
