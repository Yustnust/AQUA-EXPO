# 硬件变更 — 设计文档修订方案 v1.1

> 日期：2026-09-20
> 变更来源：设备硬件调整
> - 上下缸转移环节（S4）：去除 NC 阀（下缸 NC 阀 Q0.6），仅保留电动球阀 B + 流量开关 B
> - 下缸排水环节（S6）：去除流量开关 C（I0.2），仅保留电动球阀 C
>
> **确认结论（2026-09-20）**：
> 1. S4 仅删除下缸 NC 阀 `Q0.6`；上缸 NC 阀 `Q0.5`（S1 进水）保留。
> 2. S6 排水完成判定采用「液位计 B 低位 `I1.0` + 延时验证」。
> 3. `Q0.6` 和 `I0.2` 在变量表中标注为「保留/未使用」。
> 4. 报警码 13（NC 球阀-下缸动作）和 45/47（阀 C 流量相关）直接废弃。

---

## 1. 变更摘要

| 环节 | 原硬件 | 新硬件 | 涉及的 PLC 输出 | 涉及的 PLC 输入 |
|---|---|---|---|---|
| S4 上→下转移 | 电动球阀 B + NC 球阀下缸 + 流量开关 B | 电动球阀 B + 流量开关 B | 删除 `Q0.6` 使用 | 保留 `I0.1` |
| S6 下缸排水 | 电动球阀 C + 流量开关 C | 电动球阀 C | 保留 `Q0.4` | 删除 `I0.2` 使用 |

**S1 上缸进水环节不受影响**：`Q0.5`（NC 球阀-上缸）和 `I0.0`（流量开关 A）继续保留。

## 3. S6 变更影响范围

### 3.1 PLC 程序层面

S6 去除流量开关 C 后，原有依赖 `I0.2` 的四态诊断、开关到位超时、内漏检测逻辑均需重写。

| 文件 | 当前使用点 | 建议修改 |
|---|---|---|
| `FC17_State_S6_Drain.stl` | 调用 `FC32` 进行阀 C 诊断 | 保留阀 C 开关控制；诊断结果判定改为基于时间/液位 |
| `FC32_ValveC_Diag.stl` | 全部逻辑基于 `I0.2` + `I1.0` + 限位开关 | **需整体重写**，见下方 3.2 节方案 |
| `FC3A_AlarmReset_Common.stl` | 用 `I0.2` 状态复位 `V302.5/V302.7/V303.1` | 删除 `I0.2` 相关复位条件 |
| `FC3_AlarmHandling.stl` | 阀 C 相关报警进入优先级链 | 报警语义需调整 |

### 3.2 FC32 重写方案（已确认）

采用**方案 A：液位低位 + 延时验证**。

| 状态 | 判定条件 | 说明 |
|---|---|---|
| 开阀成功 | `I8.4=ON`（开到位） | 去掉流量确认，仅确认机械开到位 |
| 排水完成 | `I1.0=ON`（液位计 B 低位）且持续 `VD_Delay_ValveC_Verify` | 用液位低位代替流量开关 OFF |
| 排水异常 | 开到位超时 `T56` 或排水总时长超过 `VD_Timeout_ValveC` | 保留超时保护 |
| 关阀完成 | `I8.5=ON`（关到位） | 不再判断内漏 |

> 注：若下缸液位低位探头位置导致排水不彻底，后续可再引入「S6 设计排水时长 VD114」作为时间兜底，但本次文档基线仅采用液位低位 + 延时。
