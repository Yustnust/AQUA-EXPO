# v2.2 流程重构 — PLC 代码实施前置迁移方案 v1.0

> **配套文档**：《S2-S4流程重构设计方案_v2.2》、《药液配置加注控制系统_PLC设计文档》v10.3、《HMI-PLC变量地址表》v1.9+、《PC设计文档_完整寄存器映射表》v1.2、《STEP7符号表》v1.2
>
> **适用范围**：PLC 代码从 v2.1 升级到 v2.2 之前的**前置准备文档**。本方案明确"哪些地址必须先迁移、迁到哪里、谁动哪些 STL 文件",确保实施时无字节级物理重叠风险。
>
> **文档性质**：**实施前置技术文档**(纯文档工作,**不动 PLC 代码**)。PLC 代码修改由 PLC 工程师按本方案的"实施步骤"逐项执行。

---

## 一、为什么需要这份文档

v2.2 流程重构方案中新增了 7 个变量（VW304/VW306/VD414/VD426/VD430/VD442/VD446/V303.6）和 5 个定时器（T38/T46/T48/T49），其中 4 个地址与 v2.1/AQEX-49 已落地分配存在字节级物理重叠。若不预先迁移，直接将 v2.2 方案下装到 PLC 程序，会导致：

- 上缸配液子流程状态（VW304）覆盖初始化标志位（V304.0）→ 首轮 S1 触发错乱
- 24h 换水目标次数（VD414）被定时器暂存（VW414）改写 → 倒计时偏差
- 双倒计时器显示值（VD442/VD446）与累计加药量（VD440）和 S4 等待时长（VD444）互相覆盖 → HMI 显示错乱

**本方案提供完整的迁移路径**：3 个变量迁移 + 5 个文件改动，所有目标地址已通过字节级 + STL 实际引用双重确认无冲突。

## 二、冲突清单（4 处物理重叠）

### 2.1 VW304 vs VB304\~307

| 项目 | 现有占用 | v2.2 需求 |
| --- | --- | --- |
| V304.0 | M_InitDone（FC0/SBR25/FC19/OB1 写1） | VW304 = State_UpTank |
| V304.1 | RTU1_Online（FC4 写） | ↑ |
| V304.2 | RTU2_Online（FC4 写） | ↑ |
| VB305 | 系统总状态字（OB1 维护） | ↑ |

**冲突后果**：VW304 写入值 2（即上缸进 S2 搅拌）会改写 V304.0\~V304.7 + VB305，导致初始化标志丢失 + RTU 在线误判。

### 2.2 VW414 vs VB414\~417（VD414 的低 4 字节）

| 项目 | 现有占用 | v2.2 需求 |
| --- | --- | --- |
| VW414 | TON→INT 暂存（FC11/15/17 各1处） | VD414 = VD_24h_Target（HMI 设定 REAL） |

**冲突后果**：VW414 写入 TON 整数（例 5000 = 0x1388）会改写 VB414\~VB415 = VD414 的低 2 字节，REAL 浮点解释偏移。HMI 改 VD414 = 24.0 时 FC11 同时写 VW414，两边数据互相破坏。

### 2.3 VD442 vs VD440\~VB440\~443

| 项目 | 现有占用 | v2.2 需求 |
| --- | --- | --- |
| VD440 | Dosed_Volume_Total（FC0/FC13/FC18 写） | VD442 = VD_TimerA（FC40 每秒写） |

**冲突后果**：每周期 FC40 写 VD442 + FC13 写 VD440，两边数据互相覆盖，HMI 显示累计加药量数字乱跳。

### 2.4 VD446 vs VD444\~VB444\~447

| 项目 | 现有占用 | v2.2 需求 |
| --- | --- | --- |
| VD444 | S4Wait_Time（FC15 写，FC16 读） | VD446 = VD_TimerB（FC40 每秒写） |

**冲突后果**：每周期 FC40 写 VD446 + FC15 写 VD444，S4Wait_Time 错乱导致 S5→S6 转 S6 阈值计算错误。

## 三、迁移目标地址（安全性已确认）

### 3.1 目标地址选定原则

1. **字节级空闲**：V 区空闲区中4 字节对齐（REAL 必须对齐）
2. **STL 实际无引用**：对所有 STL 文件做 grep 确认目标地址未被任何 FC/OB/SBR 引用
3. **同区语义**：迁移后变量语义保持（REAL 仍为 REAL，BOOL 仍为 BOOL）
4. **不破坏断电保持**：HMI 设定参数（VD414/426/430）需断电保持；非保持参数（VD442/446）放非保持区

### 3.2 目标地址安全性扫描结果

| 目标地址 | 字节范围 | STL grep 引用次数 | 物理占用来源 | 安全性 |
| --- | --- | --- | --- | --- |
| **M16.4** | M16.4（位） | 0 | 无（相邻 M16.0\~M16.3 v2.2 占用） | ✅ 真空闲 |
| **M16.5** | M16.5（位） | 0 | 无 | ✅ 真空闲 |
| **M16.6** | M16.6（位） | 0 | 无 | ✅ 真空闲 |
| **VW236** | VB236\~VB237 | 0 | 无（VB236\~249 真空闲区） | ✅ 真空闲，4字节对齐 |
| **VD256** | VB256\~VB259 | 0 | 无（第三节空闲区分析标"真空闲"） | ✅ 真空闲，4字节对齐 |
| **VD244** | VB244\~VB247 | 0 | 无（同 VB236\~249 真空闲区） | ✅ 真空闲，4字节对齐 |

> **安全性验证方法**：
> 1. `grep -nE "VW236|VD236|VW23[6789]|VD23[6789]" plc/stl/*.stl` → 0 命中
> 2. `grep -nE "VW256|VD256|VB256|VB257|VB258|VB259" plc/stl/*.stl` → 0 命中
> 3. `grep -nE "VW244|VD244|VB244|VB245|VB246|VB247" plc/stl/*.stl` → 0 命中
> 4. 寄存器映射表 v1.2 第三节空闲区分析：VB236\~249（14B）标"可用，但别浪费"
> 5. VB256\~259 在寄存器映射表 v1.2 第三节空闲区分析中未列入任何已分配项

## 五、PLC 代码实施步骤（按文件列出）

### 5.1 FC0_SysInit.stl 改动

**位置**：L17/L55/L56/L58/L63/L78 注释 + L58/L63/L78 实际指令

**改动前**：
```stl
// V304.0: M_InitDone        初始化完成标志(断电保持)
...
LD     V304.0
JMP    1                  // V304.0=1 → 跳断电恢复路径
...
AN     V304.0             // 冷启动(V304.0=0)
...
S      V304.0, 1          // M_InitDone=1(初始化完成,断电保持)
```

**改动后**：
```stl
// M16.4: M_InitDone        初始化完成标志(断电保持,从V304.0迁移)
...
LD     M16.4
JMP    1                  // M16.4=1 → 跳断电恢复路径
...
AN     M16.4              // 冷启动(M16.4=0)
...
S      M16.4, 1           // M_InitDone=1(初始化完成,断电保持)
```

**注意**：M16.4 **不**断电保持（默认）。如需断电保持，需在 STEP 7 系统块配置 M16.0\~M16.7 断电保持属性（与现有 M10.0\~M15.7 保持属性一致）。

### 5.2 FC4_ModbusPolling.stl 改动

**位置**：RTU 在线标志写入处（具体行号需 grep 确认）

**改动前**：
```stl
S      V304.1, 1          // RTU1_Online=1（注射泵轮询成功）
S      V304.2, 1          // RTU2_Online=1（流量计轮询成功）
```

**改动后**：
```stl
S      M16.5, 1           // RTU1_Online=1（从V304.1迁移）
S      M16.6, 1           // RTU2_Online=1（从V304.2迁移）
```

### 5.3 FC11_State_S1_Inlet.stl 改动

**位置**：L85\~86

**改动前**：
```stl
MOVW   T37, VW414                   // 暂存定时器值(16位整数)
ITD    VW414, VD444                 // 整数→双整数
DTR    VD444, VD70                  // 双整数→实数(VD_S1_Actual)
```

**改动后**：
```stl
MOVW   T37, VW236                   // 暂存定时器值(从VW414迁移至VW236)
ITD    VW236, VD444                 // 整数→双整数(VD444不变)
DTR    VD444, VD70                  // 双整数→实数(VD_S1_Actual)
```

### 5.4 FC15_State_S4_Transfer.stl 改动

**位置**：L123\~124

**改动前**：
```stl
MOVW   T40, VW414                  // 暂存定时器值(16位整数)
ITD    VW414, VD444                // 整数→双整数
DTR    VD444, VD74                 // 双整数→实数(VD_S4_Actual)
```

**改动后**：
```stl
MOVW   T40, VW236                  // 暂存定时器值(从VW414迁移至VW236)
ITD    VW236, VD444                // 整数→双整数(VD444不变)
DTR    VD444, VD74                 // 双整数→实数(VD_S4_Actual)
```

### 5.5 FC17_State_S6_Drain.stl 改动

**位置**：L53\~54

**改动前**：
```stl
MOVW   T42, VW414                  // 暂存定时器值(16位整数)
ITD    VW414, VD444                // 整数→双整数
DTR    VD444, VD78                 // 双整数→实数(VD_S6_Actual)
```

**改动后**：

```stl
MOVW   T42, VW236                  // 暂存定时器值(从VW414迁移至VW236)
ITD    VW236, VD444                // 整数→双整数(VD444不变)
DTR    VD444, VD78                 // 双整数→实数(VD_S6_Actual)
```

### 5.6 FC40_RhythmCorrection.stl 重写（v2.2 主战场）

**当前状态**：文件仍为三层纠偏旧版（VD150/154/158/162/166/170 + VW182 + VW184）

**目标**：按 v2.2 方案第七章 7.1\~7.9 节 + 第十章·四节 5.9 节重写为双倒计时器管理

**重写要点**（不展开，详见 v2.2 方案与 PLC 设计文档 第十章·四节）：

| 网络 | 功能 | 关键变量 |
| --- | --- | --- |
| NETWORK 1 | 计算 T_single = 86400/VD414 - VD426 - VD430 | T_cycle → VD186 |
| NETWORK 2 | 选择当前活动计时器当前值（T46_PV 或 T48_PV） | VW190 |
| NETWORK 3 | S6 触发条件（VW2=6 + VW304=6 + PV ≤ S6_actual×10） | VW2 = 7 |
| NETWORK 4 | 下一轮 S1 触发条件（VW304=0 + PV ≤ Prep_Needed×10） | M16.1 = 1 |
| NETWORK 5 | 倒计时到 0 报警（T46/T48 计时完成 + VW2≠8） | V303.6 = 1 |
| NETWORK 6 | 双倒计时器显示值写入（VD442/VD446 → **VD256/VD244**） | 每周期 T46_PV/10 或 T48_PV/10 |

> ⚠️ 关键：NETWORK 6 中写入目标地址需从 **VD442/VD446 → VD256/VD244**

### 5.7 OB1_MAIN.stl 改动

**位置**：L134（系统总状态计算） + L17 调度顺序注释

**改动前**：
```stl
// 系统总状态计算 → VB305
... // VB305 = 0(良好)/1(故障)/2(急停) 计算
```

**改动后**：
```stl
// 系统总状态计算 → VB305（不变，VB305 与 VW304 字节不重叠：VW304 在 VB304~307，但 VB305 是字节 305，VW304 包含 VB304+VB305）
// 实际：VB305 仍可使用，但需注意 VW304 写入会覆盖 VB305 的位 8\~15
// **方案调整**：将 VB305 迁移到 VW305 之外的字节，或在 OB1 中改用 BMB 操作避免 VW304 高字节覆盖
// 推荐：保持 VB305 不变，在 FC40 重写后，VW304 写入时与 VB305 的互锁需在 OB1 调度逻辑中处理
```

> ⚠️ **本条目待 PLC 工程师在实施 FC40 重写时详细确认**：VW304 包含 VB304+VB305，VW304=2 写入会改写 VB305 的高 8 位（位 8\~15）。需确保 FC40 写入 VW304 之前保存 VB305 状态，写入后恢复，或将 OB1 系统总状态计算逻辑改为不依赖 VB305 高字节。

## 六、实施顺序（严格按序执行）

### 阶段 1：迁移准备（不动代码）

1. **PLC 工程师**：阅读本方案第 1\~5 章，确认理解
2. **PLC 工程师**：在 STEP 7 SMART 软件中备份当前 PLC 程序
3. **PLC 工程师**：用 `static_analysis.py` 对当前 plc/stl/ 目录重新扫描，确认目标地址（M16.4\~6/VW236/VD256/VD244）未在新版本 FC 中被引用

### 阶段 2：M 区迁移（V304.0\~2 → M16.4\~6）

4. 改 FC0_SysInit.stl（L58/L63/L78 + 注释 L17/L55/L56）
5. 改 FC4_ModbusPolling.stl（RTU 在线标志写入处）
6. 改 OB1_MAIN.stl（L134 调度注释 + VB305 处理逻辑）
7. STEP 7 系统块：配置 M16.0\~M16.7 断电保持属性（与现有 M10\~M15 一致）
8. **编译验证**：PLC 编译应无错误，无地址重复警告
9. **下装测试**：单台 PLC 下装，监控 V304.0\~2 不再被写入，M16.4\~6 正常切换

### 阶段 3：VW414 → VW236 迁移

10. 改 FC11_State_S1_Inlet.stl（L85）
11. 改 FC15_State_S4_Transfer.stl（L123）
12. 改 FC17_State_S6_Drain.stl（L53）
13. **编译验证**
14. **下装测试**：S1/S4/S6 完成时监控 VW236 写入正常，VW414 不再被写入

### 阶段 4：VD442/VD446 → VD256/VD244 迁移

15. 重写 FC40_RhythmCorrection.stl（按 v2.2 方案第七章 + 第十章·四节 5.9）

18. **下装测试**：监控 VD256/VD244 每秒更新（T46/T48 当前值/10），HMI 画面显示正确

### 阶段 5：完整 v2.2 实施
