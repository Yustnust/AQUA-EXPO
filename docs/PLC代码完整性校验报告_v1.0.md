**问题P2【严重】**: FC30(阀A诊断)与FC32(阀C诊断)共用 VW270,但含义不同:

| 文件 | 行号 | 地址 | 用途 |

| [FC30_ValveA_Diag.stl#L65](file:///workspace/AQUA-EXPO/plc/stl/FC30_ValveA_Diag.stl#L65) | 代码 | T50, VW270 | T50 PT=VW270 |
| [FC32_ValveC_Diag.stl#L13](file:///workspace/AQUA-EXPO/plc/stl/FC32_ValveC_Diag.stl#L13) | 注释 | VW270 | 阀C诊断结果(0/1/2) |
| [FC32_ValveC_Diag.stl#L67](file:///workspace/AQUA-EXPO/plc/stl/FC32_ValveC_Diag.stl#L67) | 代码 | MOVB 2, VB270 | 阀C诊断结果=2 |
| [FC17_State_S6_Drain.stl#L28](file:///workspace/AQUA-EXPO/plc/stl/FC17_State_S6_Drain.stl#L28) | 代码 | MOVW 0, VW270 | 清阀C诊断结果 |

- **冲突分析**: VW270被FC30用作"阀A超时PT值"(WORD),同时被FC32/FC17用作"阀C诊断结果"(实际VB270/VB271)。虽然S1(FC11→FC30)和S6(FC17→FC32)不会同周期执行,但VW270跨状态复用无显式隔离,存在数据污染隐患。
- **建议**: 将FC30的T50 PT值改用独立地址(如VW278),或FC32诊断结果改用VW272(当前VW272被FC30用作T51 PT值,同样有冲突)。建议重新规划VW250~VW290区段:
  - VW260: 阀A诊断子状态 / VW266: 阀A诊断结果
  - VW262: 阀B诊断子状态 / VW268: 阀B诊断结果
  - VW264: 阀C诊断子状态 / VW270: 阀C诊断结果
  - VW272: 阀A T50 PT / VW274: 阀B T52 PT / VW276: 阀C T56 PT
  - VW278: 阀A T51 延时验证PT / VW280: 备用

### 4.3 MOVB/MOVW/MOVR 操作数匹配检查

**问题P5【严重】**: [FC32_ValveC_Diag.stl#L138](file:///workspace/AQUA-EXPO/plc/stl/FC32_ValveC_Diag.stl#L138) 与 #L159
```
L138: MOVB   1, VW270                    // Diag_Result_C=1正常完成
L159: MOVB   2, VW270
```
- **问题**: `MOVB 1, VW270` 用字节指令写字地址。MOVB写VW270实际只写低字节VB270,VB271保持原值。FC32注释(L139)已意识到此问题但未修正。
- **对比**: 同文件L67/L76/L150用 `MOVB 2, VB270`(正确,写字节),但L138/L159却用 `MOVB 1, VW270`(错误,字地址)。
- **影响**: 若VB271残留非0值,VW270作为WORD读取时结果错误,FC17的 `AW= VW270, 1` 判断可能失效。
- **建议**: L138/L159改为 `MOVW 1, VW270` / `MOVW 2, VW270`,或统一改为 `MOVB 1, VB270` + `MOVB 0, VB271`。

**问题P6【警告】**: [FC11_State_S1_Inlet.stl#L40-L44](file:///workspace/AQUA-EXPO/plc/stl/FC11_State_S1_Inlet.stl#L40)
```
L40: *R     10.0, VD48                  // 临时运算(注意:会修改VD48，实际应用中间变量)
L41: ROUND  VD48, AC0
L42: MOVW   AC0, VW270
L43: // 还原VD48(实际应使用独立中间变量VD280运算)
L44: /R     10.0, VD48
```
- **问题**: 直接修改HMI设定参数VD48(VD_Timeout_ValveA),虽L44还原,但若L41~L42间发生异常(如AC0溢出),VD48可能未还原。
- **建议**: 改用独立中间变量运算,FC11注释已标注"应使用VD282"(L46对VD66的处理方式正确)。
