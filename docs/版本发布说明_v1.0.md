## 第1节 版本概述

### 1.1 发布背景

本版本为AQUA-EXPO药液配置加注控制系统PLC代码的**首个里程碑版本(v1.0.0)**,完成Story 1.2~1.7六轮迭代的全部STL代码开发,涵盖状态机骨架、阀门诊断、节奏纠偏、急停、报警、断电恢复六大功能模块。代码经2轮完整性校验+静态分析,8个严重VD编址冲突已修复5个,2轮校验发现的10个问题(P1~P7 + A1~A3)全部修复。

### 1.2 版本性质

| 项 | 说明 |
|---|---|
| 版本类型 | 里程碑发布(X=1,Y=0,Z=0) |
| 适用范围 | 8台S7-200 SMART CPU ST20(程序完全相同,仅IP不同:192.168.2.101~108) |
| 成熟度 | **预发布候选版**:代码逻辑完整,但含3项已知严重VD编址冲突与若干P0/P1级STL缺陷待修复(见第3节),不建议直接用于生产环境;适用于内部联调与首期1套调试 |
| 下一里程碑 | release-1.1:修复3个VD编址冲突+手动控制FC+参数范围校验(计划2026-08-30) |

### 1.3 版本号编码

| 字段 | 值 | 说明 |
|---|---|---|
| 主版本(X) | 1 | 首个里程碑 |
| 次版本(Y) | 0 | Story 1.2~1.7基线 |
| 修订版本(Z) | 0 | 首次发布 |

**VW0 BCD编码值**: `16#0100`(主=01,次=00,修订=00)

> 注意:TD029(FC0 NETWORK0 VW0版本号写入)为已知技术债务,本版本发布前需完成VW0赋值实现,否则HMI无法显示版本号。若发布时TD029未偿还,本字段降级为"未写入"并在第3节已知问题中标注。

### 1.4 发布摘要

本版本交付20个FC的STL源代码(OB1 + FC0~FC4 + FC10~FC19 + FC30~FC32 + FC40),实现S0~S7+S_ERROR状态机、阀A/B/C四态诊断、三层节奏纠偏、急停双通道处理、32位报警优先级链、断电恢复双路径等核心功能。经2轮校验修复10个问题(含2个严重:VW270跨FC冲突、FC32 MOVB误用),静态分析识别225个问题(3严重/59警告/163提示)。本版本含3项已知严重VD编址冲突(待release-1.1修复)及4项已知STL缺陷(V300.2/V300.3/V303.6/FC4超时),详细见第3节。

### 6.3 回滚决策树

```
现场反馈异常
    │
    ├── 缺陷可重现且影响安全/工艺 → 紧急变更(hotfix)
    │       │
    │       ├── 8台全部异常 → 8台同步下装hotfix版本
    │       └── 单台异常 → 单台下装hotfix版本
    │
    ├── 缺陷偶发或可规避 → 评估后决定
    │       ├── 影响小,可手工规避 → 缺陷单流程,下个版本修复
    │       └── 影响大,无法规避 → 紧急变更
    │
    └── 缺陷无法重现 → 观察期,数据收集后决策
```

## B. 业务变更

### B.1 问题背景
v1.1 引入 S4 互锁(下缸未空时静默等待)后,虽然解决了"下缸未排空时开阀"的安全问题,但引入了**"实验时间被压缩"** 的次生问题:
- VD_S5_Elapsed 在 V1.7=1 期间持续累加
- 但 V1.7=1 期间若 S4 互锁生效,实际下缸"被占用但没跑实验"
- 用户设的 VD_CycleSetpoint=60min 是"下缸有效实验时间",不是"下缸被占用的时间"
- 结果:S4 等 30min,下缸只跑 30min 实验,但 VD_S5_Elapsed 仍按 60min 触发转 S6 → 有效实验时间被压缩 30min

### B.2 修复方案 (A2)
VD_S5_Elapsed 语义保持纯"下缸满的时长",但**FC16 转 S6 阈值动态减去 S4 等待时长**:

```
转 S6 触发条件(旧):VD_S5_Elapsed >= VD_CycleSetpoint×60
转 S6 触发条件(新):VD_S5_Elapsed >= VD_CycleSetpoint×60 - VD_S4Wait_Time
```

### B.3 新增 S4 等待超时报警
S4 等待超过 VD_S4WaitTimeout(默认 1800s=30min)→ V303.2 报警(VW6=49,一般级,仅提示不强制 S_ERROR)。
