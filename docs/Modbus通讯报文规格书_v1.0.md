## 术语表

| 术语 | 含义 |
|---|---|
| 主站(Master) | Modbus总线上发起请求的设备。本系统PLC(CPU ST20 Port0)为RTU主站;HMI为TCP主站(若启用MBUS_SERVER) |
| 从站(Slave) | Modbus总线上响应请求的设备。本系统注射泵(站号01)/流量计K24(站号02)为RTU从站;PLC为TCP从站(若启用MBUS_SERVER) |
| 站号(Slave Address) | RTU总线上唯一标识从站的1字节地址,范围0x01~0xFE(0=广播) |
| 功能码(Function Code) | Modbus请求首字节,指示操作类型。常用:03读保持寄存器/06写单个/10写多个(0x10) |
| 寄存器(Register) | 16位(WORD)存储单元,Modbus保持寄存器区(4xxxxx)支持读写 |
| 线圈(Coil) | 1位(BOOL)存储单元,Modbus线圈区(0xxxxx),本系统暂未使用线圈功能码 |
| CRC16 | 循环冗余校验,RTU帧尾2字节,多项式0xA001,低字节在前 |
| 保持寄存器(4xxxxx) | Modbus地址区,可读可写,本系统注射泵/流量计/HMI访问均用此区 |
| MBUS_CTRL | S7-200 SMART Modbus主站初始化指令,每周期调用 |
| MBUS_MSG | S7-200 SMART Modbus主站读写请求指令(单次请求) |
| MBUS_SERVER | S7-200 SMART Modbus TCP从站指令,将V区映射为TCP保持寄存器 |
| RTU | Remote Terminal Unit,Modbus串行二进制模式,本系统采用RS485+RTU |
| ASCII | Modbus串行ASCII字符模式,本系统不采用(注射泵出厂默认可能为ASCII,需确认切换至RTU) |
| 3.5字符帧间隔 | RTU帧间静默时间,9600bps下约3.65ms,用于帧边界识别 |
| V区 | S7-200 SMART变量存储区,按字节编址(VB)/字(VW)/双字(VD) |

## 第1章 通讯架构总览

### 1.1 架构说明

本系统采用**双层Modbus通讯架构**:

1. **下层(RTU层)**:每套PLC的CPU本体RS485口(Port0)作为**Modbus RTU主站**,通过RS485总线轮询2台从站——注射泵(站号01,南京润泽泵阀一体,柱塞式计量泵)、流量计(站号02,K24)。该总线为**每套单元独立**,不与其他单元共享,也不经过以太网转发(见PLC设计文档第十二章12.1)。

2. **上层(TCP层)**:若HMI(昆仑通态MCGS)不支持8个S7连接,PLC侧需启用**MBUS_SERVER**指令作为**Modbus TCP从站**,将以太网口(502端口)暴露V区为保持寄存器,供HMI(192.168.2.10)作为TCP主站访问8台PLC(192.168.2.101~108)。若HMI选型支持8个S7连接,则上层采用S7协议,TCP层不启用(见变量地址表12.4节)。

```
   PLC Port0         注射泵        流量计K24
   (CPU ST20)        (站号01)      (站号02)
```

| 项 | 规范 |
|---|---|
| 线缆类型 | 屏蔽双绞线(STP/FTP),特性阻抗120Ω |
| A/B定义 | A=DATA+(D+),B=DATA-(D-);接线前务必核对PLC与从站A/B定义(部分厂商A/B定义相反,接反则无通讯) |
| 屏蔽接地 | 屏蔽层在PLC端单点接地,避免多点接地形成地环路 |
| 终端电阻 | 总线两端各接120Ω终端电阻(PLC端+末端从站端),中间从站不接 |
| 最大距离 | 9600bps下RS485总线最大距离1200米(理论值),实际建议≤1000米 |
| 节点数 | RS485标准32节点/段,本系统3节点(1主站+2从站),远低于上限 |
| 分接 | 采用T型分接器或端子排分接,分支线尽量短(≤0.3米) |
| 走线 | 远离动力线(220V/380V)与变频器输出,避免电磁干扰;若必须交叉,90°正交 |

## 第3章 注射泵寄存器映射(站号01)

### 3.1 寄存器总览

依据南京润泽《泵阀一体MODBUS协议V1.7》(见变量地址表8.4章引用)及HMI变量地址表11.2章,注射泵寄存器分布在两个地址区:

- **RW区(可读写)**:40001~40021(0x0000~0x0014),用于参数写入/读取
- **R区(只读)**:41001~41280(0x03E8~0x04FF),用于状态码/位置反馈读取

> **地址换算**:Modbus寄存器地址(0-based offset)= 寄存器号(4xxxxx) - 40001。例:40006对应offset 0x0005;41001对应offset 0x03E8(41001-40001=1000=0x3E8)。

## 第5章 报文帧格式

### 5.1 RTU帧格式

Modbus RTU帧由4部分组成,无起始/结束字符,靠3.5字符静默时间识别帧边界:

```
┌──────────┬──────────┬─────────────┬──────────┐
│ 从站地址 │ 功能码   │ 数据区      │ CRC16    │
│ 1字节    │ 1字节    │ N字节       │ 2字节    │
│ 0x01~FE  │ 03/06/10 │ 变长        │ 低字节在前│
└──────────┴──────────┴─────────────┴──────────┘
        ↑                                   ↑
        └── 帧起始(3.5字符静默后) ───── 帧结束(3.5字符静默前)
```

| 字段 | 长度 | 说明 |
|---|---|---|
| 从站地址 | 1字节 | 0x01~0xFE(0x00为广播,从站不响应) |
| 功能码 | 1字节 | 03/06/10(正常)/83/86/90(异常,功能码+0x80) |
| 数据区 | 变长 | 请求/响应内容,详见5.2~5.4 |
| CRC16 | 2字节 | 低字节在前,高字节在后(多项式0xA001,见5.5) |
| 帧间隔 | 3.5字符 | 9600bps下约3.65ms,帧间静默 |
| 字内间隔 | ≤1.5字符 | 9600bps下约1.56ms,单字节间最大间隔 |

### 5.5 CRC16计算算法

#### 5.5.1 算法描述

Modbus RTU采用CRC-16-ARC算法,多项式0xA001(即0x8005的反转),初始值0xFFFF:

```
1. CRC寄存器初始化为 0xFFFF
2. 对帧中每个字节(不含CRC本身):
   a. CRC = CRC XOR 字节
   b. 循环右移8次:
      若 CRC 最低位 = 1:
         CRC = (CRC >> 1) XOR 0xA001
      否则:
         CRC = CRC >> 1
3. 最终 CRC 为 16 位值:
   低字节 = CRC & 0xFF
   高字节 = (CRC >> 8) & 0xFF
4. 帧尾追加:低字节在前,高字节在后
```

#### 5.5.2 伪代码

```c
uint16_t ModbusCRC16(uint8_t *frame, uint16_t length) {
    uint16_t crc = 0xFFFF;
    uint16_t i, j;
    for (i = 0; i < length; i++) {
        crc ^= frame[i];
        for (j = 0; j < 8; j++) {
            if (crc & 0x0001) {
                crc = (crc >> 1) ^ 0xA001;
            } else {
                crc >>= 1;
            }
        }
    }
    return crc;  // 低字节 = crc & 0xFF,高字节 = (crc >> 8) & 0xFF
}
```

#### 5.5.3 计算示例:请求帧[01 03 03 E8 00 01]的CRC16

逐步计算(仅列每字节处理后的CRC结果):

| 步骤 | 字节 | 操作 | CRC结果 |
|---|---|---|---|
| 初始 | — | CRC=0xFFFF | 0xFFFF |
| 1 | 0x01 | XOR后右移8位 | 0x807E |
| 2 | 0x03 | XOR后右移8位 | 0x2140 |
| 3 | 0x03 | XOR后右移8位 | 0xF160 |
| 4 | 0xE8 | XOR后右移8位 | 0x66F1 |
| 5 | 0x00 | XOR后右移8位 | 0x84A7 |
| 6 | 0x01 | XOR后右移8位 | **0x7A04** |

**最终CRC = 0x7A04**:
- 低字节 = 0x04
- 高字节 = 0x7A

**完整帧**:`01 03 03 E8 00 01 04 7A`(CRC低字节0x04在前,高字节0x7A在后)

|---|---|---|
| [01 03 03 E8 00 01] | 0x7A04 | `01 03 03 E8 00 01 04 7A` |

### 5.6 异常响应

#### 5.6.1 异常响应帧格式

当从站无法执行请求时,返回异常响应:

| 字节 | 内容 | 说明 |
|---|---|---|
| 1 | 从站地址 | 与请求一致 |
| 2 | 异常功能码 | 请求功能码 + 0x80(如03→83,06→86,10→90) |
| 3 | 异常码 | 1字节,见5.6.2 |

#### 5.6.2 异常码定义

| 异常码 | 名称 | 含义 | 本系统处理(见第8章) |
|---|---|---|---|
| 0x01 | 非法功能码 | 从站不支持该功能码(如对只读寄存器用FC06写) | 记录日志,检查寄存器读写属性配置 |
| 0x02 | 非法数据地址 | 请求的寄存器地址不存在(如读40004预留寄存器) | 记录日志,核对寄存器映射表 |

| 0x06 | 从站设备忙 | 从站正在处理上一请求(本系统轮询间隔足够,不应出现) | 重试1次,仍忙则记录日志 |

### 6.2 V区→保持寄存器映射规则

MBUS_SERVER指令将V区映射为Modbus TCP保持寄存器,映射规则:

| 数据类型 | 映射规则 | 说明 |
|---|---|---|
| WORD(VW) | 1个VW = 1个保持寄存器(16位) | 直映,无转换。如VW2→1个寄存器 |
| REAL/DWORD(VD) | 1个VD = 2个保持寄存器(32位) | 占2个连续寄存器,字节序由PLC决定(S7-200 SMART为大端) |
| BOOL(V位) | 位映射或拆字 | 单个V位无法直接映射为保持寄存器(寄存器为16位)。方案1:将包含该位的VW映射为1个寄存器,HMI侧按位解析(推荐);方案2:拆字映射到线圈区(本系统暂未用线圈) |

## 第7章 轮询时序与超时

### 7.1 FC4轮询策略(见FC4_ModbusPolling.stl)

FC4在每个OB1扫描周期被调用(见性能基准测试方案2.1节),轮询策略如下:

```
OB1扫描周期(目标≤5ms空载/≤8ms S5运行/≤10ms 8报警同时活动)
  └─ FC4_ModbusPolling 调用
      ├─ NETWORK 1: MBUS_CTRL初始化(每周期调用,Mode=1/Baud=9600/Parity=0/Port=0)
      └─ NETWORK 2: 基于VW250轮询计数器顺序执行MBUS_MSG
          ├─ VW250=0: 注射泵轮询
          │   └─ MBUS_MSG读41001(0x03E8,FC03,1寄存器)→VW4(MB_Pump_Status)
          │       Done位(M10.0)置1后,VW250→1
          └─ VW250=1: 流量计轮询
              └─ MBUS_MSG读40010(0x0009,FC03,2寄存器)→VD86(MB_Flow_Total)
                  Done位(M10.1)置1后,VW250→0(下一轮)
```

> **FC4现状**:当前为骨架(见FC4_ModbusPolling.stl注释),实际MBUS_MSG参数(站号/地址/功能码)由Story 1.1细化。本规格基于Story 1.1完成后的实际代码执行。

### 7.2 单次请求超时阈值(引用性能基准测试方案1.2/3.3节)

| 从站 | 寄存器 | 超时阈值 | 来源 | 备注 |
|---|---|---|---|---|

| 流量计 | 0x0009(计量值读取) | 1000 ms | 变量地址表11.1"通讯超时"建议值 | 单次读取应<500ms,1000ms为含重试的保守阈值 |

> **实现位置**:MBUS_MSG指令内部超时(默认值)或Story 1.1实现的外部超时逻辑(VD_Timeout相关,**待Story 1.1确认**)。注意:VD_Timeout_ValveA/B/C为阀门动作超时,与Modbus通讯超时不同(见性能基准测试方案3.3节注)。

### 7.4 通讯中断判定逻辑

**连续超时判定**:单从站连续N次请求超时(或返回错误)判定为通讯中断。建议N=3(待Story 1.1确认),即:
- 第1次超时:记录但不报警,继续轮询
- 第2次超时:记录,继续轮询
- 第3次超时:判定通讯中断,触发报警(见7.5)

> **判据来源**:性能基准测试方案3.3节"超时阈值验证"——断开RS485后,从断开到V303.4=1的时间应≤2000ms(注射泵)。3次连续超时(每次2000ms)总耗时6000ms,需Story 1.1确认实际N值或改为单次超时即报警。

## 第8章 错误处理与恢复

### 8.1 Modbus异常码处理

| 异常码 | 处理逻辑 | PLC动作 | 恢复方式 |
|---|---|---|---|
| 0x01非法功能码 | 记录日志(写入VW230诊断区,待Story 1.1确认地址),不立即报警 | 继续轮询下一从站 | 检查寄存器读写属性配置,核对是否对只读寄存器用FC06写 |
| 0x02非法数据地址 | 记录日志,不立即报警 | 继续轮询 | 核对寄存器映射表第3/4章,确认offset计算正确 |
| 0x03非法数据值 | 记录日志,不立即报警 | 继续轮询 | 检查VD_Dose_Steps边界(最大行程步数待确认)、速度参数范围 |
| 0x04从站设备故障 | **立即报警**:置V303.4=1,转S_ERROR(VW2=99),VW6=64 | 故障锁定 | 人工现场检查注射泵机械/流量计传感器,排除故障后系统复位 |
| 0x06从站设备忙 | 重试1次;仍忙则记录日志,本次轮询跳过 | 继续下一从站轮询 | 下次轮询周期重试,若持续忙则需检查从站负载 |

### 8.2 CRC错误处理

| 项 | 处理 |
|---|---|
| CRC校验失败 | **丢弃整个响应帧**,不计入数据,不更新VW4/VD86等变量 |
| 重试 | 同一请求重试1次(性能基准测试方案1.2节指标6) |
| 连续CRC错误 | 连续3次CRC错误(建议值,待Story 1.1确认)判定为通讯故障,触发7.5节中断动作 |
| 可能原因 | 电磁干扰(动力线靠近RS485线)、接线松动、屏蔽未接地、终端电阻缺失、波特率不匹配 |
| 排查 | 见第9章抓包与调试 |

### 8.3 超时重试

```
单次请求发出 → 等待响应:
  ├─ 在超时阈值内收到响应(且CRC校验通过)→ 处理数据,轮询下一从站
  ├─ 在超时阈值内收到响应(但CRC错误)→ 丢弃,重试1次(见8.2)
  ├─ 超时阈值内无响应 → 重试1次
  │   ├─ 重试成功 → 处理数据
  │   └─ 重试仍超时 → 计入连续超时计数(见7.4)
  └─ 连续N次超时(N=3,待确认)→ 通讯中断,触发7.5节动作
```

### 8.4 断线恢复后状态同步

通讯中断恢复(RS485重新连接或从站重新上电)后,PLC需执行状态同步:

```
通讯恢复检测:
  ├─ 检测条件:连续M次请求成功(M=2,待Story 1.1确认)
  ├─ 清除V303.4(M_Alarm_SyringePump)
  ├─ 若当前VW2=99(S_ERROR)且无其他活动报警 → 等待人工系统复位(V2.3按钮或HMI)
  └─ 若当前VW2≠99 → 继续正常轮询

状态同步流程(注射泵):
  1. 立即重新读取41001(状态码),获取当前泵状态
  2. 若状态码=0(空闲/完成) → 正常,继续轮询
  3. 若状态码=1/2/3(运行中/抽液/排液) → 等待动作完成
  4. 若状态码≥4(错误) → 触发8.5节错误处理

状态同步流程(流量计):
  1. 立即重新读取0x0009(计量值)
  2. 若当前处于S1(进水中) → 更新VD86(VD_FlowMeter_Current),重算VD90(本次进水量)
  3. 若VD82(VD_FlowMeter_Snapshot)已过期(中断期间可能有进水) → 标记本轮进水量计算可疑,记录日志
```

### 8.5 注射泵状态码错误处理

| 状态码 | 处理 | 依据 |
|---|---|---|
| 0(空闲/完成) | 正常,FC13判定动作完成 | 变量地址表5.2 |
| 1/2/3(运行中/抽液/排液) | 正常,继续轮询等待 | 变量地址表5.2 |
| ≥4(错误码) | **立即报警**:置V303.4=1,转S_ERROR(VW2=99),VW6=64,停止当前加药流程 | 变量地址表5.2/9.1/9.2 |
| 错误码具体含义 | **待南京润泽V1.7协议确认**(见第10章) | 厂商协议 |

**S_ERROR锁定后**:必须人工系统复位(V2.3按钮或HMI CMD_SafetyRelayAck)才能回S0,不会自动恢复。

### 9.2 抓包示例解读

**抓包场景**:PLC轮询注射泵41001状态码,从站返回状态码0x0002(抽液中)

**抓包原始数据(串口调试助手显示)**:

```
[T+0.000ms] TX: 01 03 03 E8 00 01 04 7A        ← PLC发出请求(8字节)
[T+18.532ms] RX: 01 03 02 00 02 39 85          ← 注射泵响应(7字节,延迟18.5ms)
```

**解读步骤**:
1. **请求帧** `01 03 03 E8 00 01 04 7A`:
   - `01`:从站地址(注射泵站号01)
   - `03`:功能码(读保持寄存器)
   - `03 E8`:起始地址0x03E8(对应寄存器41001)
   - `00 01`:数量1(读1个寄存器)
   - `04 7A`:CRC16(低字节0x04在前,高字节0x7A在后)

2. **响应帧** `01 03 02 00 02 39 85`:
   - `01`:从站地址(与请求一致)
   - `03`:功能码(正常响应,非异常)
   - `02`:字节数2(1个寄存器×2字节)
   - `00 02`:数据(状态码=0x0002=2=抽液中)
   - `39 85`:CRC16(低字节0x39在前,高字节0x85在后)

3. **耗时分析**:
   - 请求8字节@9600bps≈8.3ms + 3.5字符间隔≈3.65ms
   - 响应7字节@9600bps≈7.3ms
   - 从站处理延迟=18.532−8.3−3.65≈6.6ms(典型5~30ms范围内)
   - 总耗时≈18.5ms(远低于2000ms超时阈值)

### 9.3 常见通讯故障排查

| 故障现象 | 可能原因 | 排查方法 |
|---|---|---|
| 从站无响应(全0或无数据) | 1.A/B接反 2.站号冲突 3.波特率不匹配 4.从站未上电 5.从站协议为ASCII非RTU | 1.交换A/B线重试 2.检查站号设置 3.用Modbus Poll以9600/19200分别测试 4.测量从站供电 5.检查注射泵40020是否=3(RS485+RTU) |
| CRC错误率高 | 1.电磁干扰(动力线靠近) 2.屏蔽未接地 3.终端电阻缺失 4.总线距离过长 5.节点数过多 | 1.远离动力线/加屏蔽 2.PLC端单点接地 3.两端加120Ω终端电阻 4.缩短总线/加中继器 5.检查节点数≤32 |
| 数据错位/读不到正确值 | 1.寄存器地址计算错误 2.字节序不匹配(大端/小端) 3.寄存器数量错误(32位DWORD读1个寄存器) 4.功能码错误(对只读寄存器用FC06) | 1.核对offset=寄存器号−40001 2.用Modbus Poll逐字节读取确认字节序 3.DWORD需读2个寄存器 4.核对寄存器读写属性 |
| 间歇性通讯中断 | 1.接线松动 2.终端电阻位置错误(中间节点接了电阻) 3.供电不稳 4.PLC扫描周期过长导致MBUS_MSG未及时调用 | 1.紧固接线 2.仅两端接终端电阻 3.测量供电电压 4.测量扫描周期(性能基准测试方案第2章) |
| 异常响应(83/86/90) | 1.非法功能码(对只读用写) 2.非法数据地址(读预留寄存器) 3.非法数据值(写超范围) | 根据异常码对照5.6.2节处理 |

### 9.4 以太网抓包(TCP层,若启用MBUS_SERVER)

**工具**:Wireshark 4.x

**抓包步骤**:
1. 抓包PC接入HMI与PLC之间交换机的镜像口(需网管型交换机支持端口镜像)
2. 启动Wireshark,设置过滤器

**Wireshark过滤器**:

| 过滤器 | 用途 |
|---|---|
| `tcp.port == 502` | 仅显示Modbus TCP流量(端口502) |
| `host 192.168.2.10 and host 192.168.2.101` | HMI与PLC#1之间流量 |
| `host 192.168.2.10` | HMI全部流量(8台PLC并发) |
| `modbus` | Wireshark内置Modbus解析器(显示解析后字段) |
| `modbus.func_code == 3` | 仅显示FC03读请求 |
| `tcp.port == 502 and tcp.flags.reset == 1` | 检测TCP连接异常重置 |

**Modbus TCP帧结构(Wireshark解析)**:

```
| MBAP头(7字节) | PDU |
| TID(2) | PID(2) | Length(2) | UnitID(1) | FunctionCode(1) | Data(N) |
| 事务ID  | 协议ID  | 长度      | 单元ID    | 功能码           | 数据    |

注:Modbus TCP无CRC16(MBAP头替代RTU的从站地址+CRC);
   PID固定0x0000(表示Modbus协议);
   UnitID对于MBUS_SERVER通常忽略,填1或255
```

**调试要点**:
- HMI单次读写V区耗时≤50ms(性能基准测试方案1.2节指标9,待确认)
- HMI轮询8台PLC一周耗时≤2s(性能基准测试方案1.2节指标10,待确认)
- 单台PLC断网后HMI重连时间≤5s(性能基准测试方案1.2节指标12,待确认)
- 详细测试方法见性能基准测试方案第4~5章,本规格不重复
