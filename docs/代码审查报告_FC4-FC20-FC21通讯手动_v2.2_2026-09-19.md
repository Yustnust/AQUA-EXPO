## 一、🔴 P0 - 致命 BUG

### BUG #M1：`FC4` 所有任务"完成切换"路径 LPS 后栈空——轮询会卡死在某个任务

**严重度**：🔴 P0 致命
**影响范围**：所有 Modbus 任务切换（任务 0/1/2/3/4）

**位置**：`FC4_ModbusPolling.stl` L213-221（任务 4）、L71-77（任务 0）、L108-114（任务 1）、L130-136（任务 2）、L157-170（任务 3 切换部分）

```stl
//   任务4完成切换(成功或T103超时)
LD     M12.0                       ; 栈:[M12.0]
O      T103                         ; 栈:[(M12.0 OR T103)]
R      M11.6, 1                     ; 消耗栈顶，M11.6=0     ✓ 执行
R      M11.7, 1                     ; 栈空，⚠️ 不执行!
R      M15.4, 1                     ; 不执行
S      M15.0, 1                     ; 不执行
MOVW   0, VW290                     ; 不执行!
R      T103, 1                      ; 不执行
```

**栈追踪（详细）**：
```
LD     M12.0       → 栈:[M12.0]                      (深 1)
O      T103        → 栈:[(M12.0 OR T103)]            (深 1)
R      M11.6, 1    → 消耗栈顶，M11.6=0               (深 0) ✓
R      M11.7, 1    → 栈空，⚠️ 不执行!
R      M15.4, 1    → 不执行
S      M15.0, 1    → 不执行
MOVW   0, VW290    → 不执行! VW290 永远卡在 4
R      T103, 1     → 不执行
```

**后果（致命）**：
- **VW290 永远不变 0**——Modbus 轮询**卡在任务 4**
- **M11.7 永远不清零**——下次 MBUS_MSG 调用被禁止
- **M15.4 永远不清零**——任务 4 永远"活跃"
- **M15.0 永远不置位**——任务 0 永远不重启
- **T103 永远不清零**——超时计时器持续计时 → 触发 T103

**所有 5 个任务的"完成切换"路径都有相同问题**（L71-77、L108-114、L130-136、L213-221）。

**实际场景**：
- PLC 上电后，任务 0 启动 → 通讯成功 → M10.0=1 → 尝试切换到任务 1
- 切换路径 L71-77：`R M15.0; S M15.1; MOVW 1, VW290; R M10.0; R T103`
  - `R M15.0` 执行
  - `S M15.1` 不执行
  - `MOVW 1, VW290` 不执行 → VW290 永远卡 0
  - `R M10.0` 不执行 → M10.0 残留=1
  - `R T103` 不执行
- 任务 0 持续重试（M15.0=0 已清除），但 VW290=0 + M15.0 已被 R → 下次 OB1 周期进入任务 0 → M10.0=1（已完成标志残留）→ MBUS_MSG 不被触发（First 不满足）→ 死循环

**修复方法**：

**方案 A（推荐）：每条独立 LD**
```stl
NETWORK X1
LD     M12.0
O      T103
=      V60.4                       ; 保存 OR 结果

NETWORK X2
LD     V60.4
R      M11.6, 1

NETWORK X3
LD     V60.4
R      M11.7, 1

NETWORK X4
LD     V60.4
R      M15.4, 1

NETWORK X5
LD     V60.4
S      M15.0, 1

NETWORK X6
LD     V60.4
MOVW   0, VW290

NETWORK X7
LD     V60.4
R      T103, 1
```

**方案 B：用 LPS 保存**
```stl
LD     M12.0
O      T103
LPS                                ; 保存到第 2 层
R      M11.6, 1
R      M11.7, 1
R      M15.4, 1
S      M15.0, 1
MOVW   0, VW290
R      T103, 1
LPP                                ; 弹出，丢弃栈顶
```

### BUG #M2：`FC4` 任务 0 的 "VW224→VW4 状态归一化" 是死代码——`VW4` 永远被写为 4（错误码）

**严重度**：🔴 P0 致命
**影响范围**：所有依赖 `VW4` 状态的逻辑（FC13/FC21 全局错误检测、运动中判定）

**位置**：`FC4_ModbusPolling.stl` L78-89

```stl
//   === VW224 → VW4 状态归一化映射 (合并 8/9/10/11) ===
//   96→0, 64→1, 100→2, 其他→4
LDW=   VW224, 96
MOVW   0, VW4
LDW=   VW224, 64
MOVW   1, VW4
LDW=   VW224, 100
MOVW   2, VW4
LDW<>  VW224, 100
AW<>   VW224, 96
AW<>   VW224, 64
MOVW   4, VW4
```

**问题分析**：

1. **VW224 在整个 FC4 中从未被 MBUS_MSG 写入**（L26 写入的是 `&VB410`，不是 `&VB224`）
2. **VW224 永远是 0**（PLC 初始化后未赋值）
3. 归一化逻辑：
   - L80 `LDW= VW224, 96`：0=96 → FALSE → MOVW 0, VW4 不执行
   - L82 `LDW= VW224, 64`：FALSE → MOVW 1, VW4 不执行
   - L84 `LDW= VW224, 100`：FALSE → MOVW 2, VW4 不执行
   - L86 `LDW<> VW224, 100`：0≠100 → TRUE
   - L87 `AW<> VW224, 96`：TRUE AND (0≠96)=TRUE → TRUE
   - L88 `AW<> VW224, 64`：TRUE AND (0≠64)=TRUE → TRUE
   - **L89 `MOVW 4, VW4` 执行！VW4 = 4（错误码）**

**后果（致命）**：
- **VW4 永远 = 4**（归一化错误码）
- FC13/FC21 全局错误检测 `AW>= VW4, 4` 永远为 TRUE → **VW390 永远被设为 99（错误态）**
- **VW4=0（就绪）永远检测不到**——FC13 子状态机无法进入"等抽液运动完成"等需要"VW4≠运动中"的逻辑
- **VW4=2（运动中）永远检测不到**——FC13 运动超时保护永远不会启动
- **VW4=4 是错误态**——所有相关报警（V303.4）会持续触发

**实际场景**：
- FC21 启动 → VW390=1（启动态）→ 子状态 1-2 检查 `AW= VW4, 0` 等待就绪 → **VW4=4≠0，永远不满足** → 写命令永远不下发 → 手动注射泵**完全无法启动**

**修复方法**：

**方案 A（推荐）：删除整个 VW224→VW4 归一化段**
```stl
// 删除 L78-89 全部
// 直接使用 L59 的 MOVW VW410, VW4（原始 Modbus 数据）
```

**方案 B：修复 VW224 来源（如果确实需要归一化）**
```stl
NETWORK X
// 任务0成功写入 VW4 后，归一化映射
LD     M10.0                        ; 任务0完成
A      M15.0
AB=    VB379, 0
LPS
LDW=   VW410, 96                    ; ⚠️ 改为 VW410，不是 VW224
MOVW   0, VW4
LPP
LDW=   VW410, 64
MOVW   1, VW4
LPS
LDW=   VW410, 100
MOVW   2, VW4
LPP
LPS
LDW<>  VW410, 100
AW<>   VW410, 96
AW<>   VW410, 64
MOVW   4, VW4
LPP
LPP
LPP
```

### BUG #M3：`FC21` 手动注射泵所有状态机写指令栈消耗——整个模块完全不可用

**严重度**：🔴 P0 致命
**影响范围**：手动注射泵的全部功能（启动、抽液、排液、回零）

**位置**：`FC21_ManualSyringePump.stl` 整个文件（约 278 行）

**栈追踪（启动命令 L15-28）**：
```stl
LD     SM0.0       ; 栈:[SM0.0]
A      V307.2      ; 栈:[SM0.0 AND V307.2]
EU                ; 栈:[SM0.0 AND V307.2↑]
AW=    VW390, 0    ; 栈:[SM0.0 AND V307.2↑ AND VW390=0]    (深 1)
MOVR   0.0, VD392  ; 消耗栈顶，VD392=0     ✓
MOVR   VD452, VD396 ; 栈空，⚠️ 不执行!
R      M13.7, 1    ; 不执行
R      M13.5, 1    ; 不执行
R      M13.6, 1    ; 不执行
R      M12.0, 1    ; 不执行
R      M11.6, 1    ; 不执行
R      M11.7, 1    ; 不执行
MOVW   1, VW390    ; 不执行!
R      V307.2, 1   ; 不执行
```

**后果（致命）**：
- **VW390 永远 = 0**（空闲）——状态机永远不推进
- **VD392/VD396 不更新**——本次目标体积不复制
- **所有握手位残留**（M13.5/6/7、M11.6/7、M12.0）
- **HMI 命令位 V307.2 残留 = 1**——下次按启动按钮 EU 不会触发（无上升沿）

**所有 NETWORK 都有相同问题**——子状态 1-1、1-2、1-3、1-4、2-1、2-2、2-3、2-4、3-1、3-2 的所有写指令栈消耗。

**实际场景**：
- 操作员在 HMI 上点"手动注射泵启动"
- V307.2 = 1（脉冲 1 个周期）
- PLC 检测 V307.2↑ + VW390=0 → 仅 VD392 清零
- VW390 永远不变 1 → 永远进不了任何子状态
- **手动注射泵完全无法启动**

**修复方法**：

每条独立 LD 或用 LPS 保存栈顶，参考 BUG #M1 修复方法。

**示例（启动命令 L15-28）**：
```stl
NETWORK 1
LD     SM0.0
A      V307.2
EU
AW=    VW390, 0
=      V60.4                        ; 缓存启动条件

NETWORK 2
LD     V60.4
MOVR   0.0, VD392

NETWORK 3
LD     V60.4
MOVR   VD452, VD396

NETWORK 4
LD     V60.4
R      M13.7, 1

NETWORK 5
LD     V60.4
R      M13.5, 1

NETWORK 6
LD     V60.4
R      M13.6, 1

NETWORK 7
LD     V60.4
R      M12.0, 1

NETWORK 8
LD     V60.4
R      M11.6, 1

NETWORK 9
LD     V60.4
R      M11.7, 1

NETWORK 10
LD     V60.4
MOVW   1, VW390

NETWORK 11
LD     V60.4
R      V307.2, 1
```

### BUG #M5：`FC20` 所有手动命令的"PLC 清握手位" R 操作栈消耗——HMI 命令位残留

**严重度**：🟠 P1 严重

**位置**：`FC20_ManualControl.stl` L49-122（10 个手动控制指令）

**典型模式**（L49-53 阀A开）：
```stl
LD     SM0.0
A      V306.0
EU
S      M13.0, 1        ; M13.0=1（开阀A）     ✓
R      V306.0, 1       ; 栈空，⚠️ 不执行!
```

**栈追踪**：
```
LD     SM0.0       → 栈:[SM0.0]
A      V306.0      → 栈:[SM0.0 AND V306.0]
EU                → 栈:[SM0.0 AND V306.0↑]
S      M13.0, 1    → 消耗栈顶，M13.0=1       (深 0) ✓
R      V306.0, 1   → 栈空，⚠️ 不执行!
```

**后果**：
- **M13.0/M13.1/M13.2/M13.3/M13.4 锁存成功**——阀/泵动作执行
- **V306.0~V307.1 命令位残留 = 1**——HMI 命令位不清

**实际影响**：
1. **EU 不会再触发**：V306.x 一直是 1，无新上升沿 → 操作员再按按钮无反应
2. **必须 HMI 自己清零**：但 PLC 代码注释说"由 PLC 清握手位"——责任不清晰
3. **HMI 永远收不到确认**：没有 STA_xxx_Done 握手位 → 操作员不知道命令是否执行

**修复方法**：

**方案 A：每条独立 LD**
```stl
NETWORK 1
LD     SM0.0
A      V306.0
EU
S      M13.0, 1

NETWORK 2
LD     SM0.0
A      V306.0
EU
R      V306.0, 1
```

**方案 B：添加 HMI 握手位**
```stl
NETWORK X
LD     SM0.0
A      V306.0
EU
S      V1.5, 1                       ; STA_Manual_ValveA_Open_Done
```

### BUG #M6：`FC20` 阀 A 没有"上缸=空"联锁——可在满水时手动开阀导致漫溢

**严重度**：🟠 P1 严重（安全隐患）

**位置**：`FC20_ManualControl.stl` L49-59

```stl
// 手动阀A控制(开/关)
LD     SM0.0
A      V306.0
EU
S      M13.0, 1
R      V306.0, 1

LD     SM0.0
A      V306.1
EU
R      M13.0, 1
R      V306.1, 1
```

**问题**：
- 阀 B 有联锁：`V1.6 (上缸=满) AND NOT V1.7 (下缸=空)`
- 阀 C 有联锁：`V1.7 (下缸=满)`
- **阀 A 没有任何联锁**——可在任意状态下开阀 A

**设计文档 §10.5.1 表格**说"手动开阀 A：响应条件 VW2=0"——**没有说需要上缸=空**。

**风险**：
- 上缸已经满水（V1.6=1）时手动开阀 A → 进水 → **可能漫溢**
- 设计文档 §10.5.1 规定 V306.0/V306.1/V306.3/V306.5 等都仅 VW2=0 响应，没有强制上缸=空

**修复建议**：
```stl
// 手动阀A联锁: 上缸=空(V1.6=0)
LD     SM0.0
A      V306.0
EU
AN     V1.6                          ; 上缸=空才能开阀A
O      V309.0                        ; 调试模式可绕过
ALD
S      M13.0, 1
```

### BUG #M7：`FC21` 孤儿态自恢复（L1-11）无条件重置 VW390=99 错误态——错误未真正解决就被清除

**严重度**：🟠 P1 严重（设计漏洞）

**位置**：`FC21_ManualSyringePump.stl` L1-11

```stl
LDW<>  VW390, 0
AW<>   VW390, 30
AN     M11.6
AN     M11.7
AN     M12.0
AN     M13.5
AN     M13.6
MOVW   0, VW390
R      M13.7, 1
```

**问题**：
- 条件：`VW390 不在 {0, 30}` 且 `无写请求/写忙/写完成/抽/排标志`
- **VW390=99（错误态）满足条件**：`99≠0 AND 99≠30` → 重置为 0
- 错误未真正解决（V303.4 可能还在，报警未确认）

**实际场景**：
- 注射泵通讯故障 → V303.4=1 → FC21 全局错误检测 L41-55 → VW390=99
- L1-11 立即把 VW390 重置为 0
- 操作员看到 VW390=0（空闲），以为可以重新启动
- 但 V303.4 仍在（FC4 软件滤波前）→ 重新启动后立即又出错

**修复方法**：
```stl
LDW<>  VW390, 0
AW<>   VW390, 30
AW<>   VW390, 99                     ; ⚠️ 新增：排除错误态
AN     M11.6
AN     M11.7
AN     M12.0
AN     M13.5
AN     M13.6
AN     V303.4                        ; ⚠️ 新增：排除报警态
MOVW   0, VW390
R      M13.7, 1
```

### BUG #M8：`FC4` 软件滤波的 `R V303.6, 1` 与 `FC40` 的 `S V303.6, 1` 冲突——已在第三份报告 BUG #E4 提及，这里再强调

**严重度**：🟠 P1 严重

**位置**：
- `FC4_ModbusPolling.stl` L100、L232
- `FC40_RhythmCorrection.stl` L56、L136

**OB1 调度顺序**：`FC4 → FC3 → FC22 → FC40`

**实际行为**：
- 流量计通讯成功（FC4 L100）→ R V303.6 = 0
- FC40 计时完成 → S V303.6 = 1（同一周期或下一周期）
- **最终 V303.6 = 1**（FC40 后置位）

**注释错位**（FC4 L230 注释"V303.6 软件滤波:连续失败<5次时不报警"）：
- 实际 V303.6 是"周期超时"位（FC40 用）
- 不是"通讯失败"位
- 这是 v2.2 复用 V303.6（原流量开关瞬时异常位）造成的命名混乱

**修复方法**：
- 删除 FC4 的 R V303.6（L100、L232）
- FC40 独立管理 V303.6

## 三、🟡 P2 - 中等 BUG

### BUG #M9：`FC4` 任务 3 进入任务 4 的切换（L162-170）栈消耗——`VW290` 永远不变 4

**严重度**：🟡 P2 中等

**位置**：`FC4_ModbusPolling.stl` L162-170

```stl
//  // 进入任务4: 有写请求(M11.6=1)
LD     V60.0
A      M11.6
S      M15.4, 1
MOVW   4, VW290
```

**栈追踪**：
```
LD     V60.0       → 栈:[V60.0]
A      M11.6       → 栈:[V60.0 AND M11.6]
S      M15.4, 1    → 消耗栈顶，M15.4=1     ✓
MOVW   4, VW290    → 栈空，⚠️ 不执行!
```

**后果**：
- **VW290 永远不变 4**——任务 4 永远不启动
- M11.6 写请求永远卡着——自动 S3 加药或手动注射泵都无法写入 Modbus 寄存器

**修复方法**：每条独立 LD。

### BUG #M11：`FC4` 任务 4 失败处理（L203-210）栈管理 OK，但与"成功处理"路径冲突

**严重度**：🟡 P2 中等

**位置**：`FC4_ModbusPolling.stl` L195-221

```stl

LD     M12.0
A      M15.4
AB=    VB383, 0
R      M11.6, 1
R      M11.7, 1
MOVW   0, VW510
R      V303.4, 1
//   任务4失败计数 + 从站异常立即报警

A      M15.4
LPS
AB<>   VB383, 0
INCW   VW510
LPP
AB>=   VB383, 101
S      V303.4, 1
//   任务4完成切换(成功或T103超时)
LD     M12.0
O      T103
R      M11.6, 1                      ; ⚠️ 与 L198 的 R M11.6 重复
R      M11.7, 1
R      M15.4, 1
S      M15.0, 1
MOVW   0, VW290
R      T103, 1
```

**问题**：
- L198 `R M11.6, 1`（成功处理）和 L216 `R M11.6, 1`（完成切换）**重复**
- 但因为 L213-221 的栈消耗问题，L216 不执行——L198 是唯一清 M11.6 的地方

**实际行为**：

- 写失败：M11.6 不清零 → 任务 4 完成切换路径 L216 也因栈消耗失效 → **M11.6 永远卡 1**
- **下次写请求即使满足条件，因 M11.6 已 R（变为 0）会触发新写**

但实际上因为 **L213-221 栈消耗**导致 M11.6 不清——这里逻辑链是断的。

**修复方法**：先把 BUG #M1 修了，重复 R 问题自然解决。

## 五、跨 FC 调用关系

### 5.1 FC4 与 FC13/FC21 的接口

**FC4 提供的接口**：
- VW4：注射泵归一化状态码（0=就绪/1=空闲/2=运动中/4=错误）—— **BUG #M2 让 VW4 永远=4**
- VW222：注射泵位置反馈（半步）
- VD86：流量计累计计量值（L）
- VD94：流量计瞬时流速（L/s）
- V303.4：注射泵通讯/动作异常（报警位）
- V303.6：周期超时（与 FC40 冲突——BUG #E4）

**FC13/FC21 使用的接口**：
- `AW= VW4, 0`：等待就绪 → **VW4=4，永远不满足**
- `AW>= VW4, 4`：判定错误 → **VW4=4，永远满足 → 误判**

**实际后果**：
- FC13 加药：判定 `VW4=0` 失败 → 写命令永远不发
- FC21 手动注射泵：判定 `VW4=0` 失败 → 写命令永远不发
- FC13/FC21 全局错误检测：`VW4>=4` 永远满足 → VW390=99 → **注射泵永远在错误态**

### 5.2 FC20 与 OB1 的接口

**OB1 调用**：
```
NETWORK 9: 手动控制处理（仅 S0 态调用）
NETWORK 10: 手动注射泵控制（仅 S0 态调用）
NETWORK 11: 非 S0 态清除手动控制锁存
```

**问题**：
- OB1 NETWORK 9 写 `LD SM0.0; LDW= VW2, 0; CALL ManualControl`——CALL 总是执行
- FC20 内部的命令位检测依赖 EU（V306.x 上升沿）——但 V306.x 残留=1 → EU 永不触发 → 操作员后续操作完全失效

### 5.3 FC21 与 FC4 的接口

**FC21 写请求到 FC4**：
- `S M11.6, 1`：FC21 触发写请求 → FC4 在任务 4 处理
- `MOVD 16#xxxx, VD232`：FC21 设置写目标地址
- `MOVW xx, VW230`：FC21 设置写数据

**FC4 在任务 4 处理写请求**：
- L191 `CALL MBUS_MSG, L63.7, 16#1, 16#1, VD232, 16#1, &VB410, M12.0, VB383`——VD232 来自 FC21，VW410 来自 FC21 的 VW230

**问题**：
- FC21 设置 VD232/VW230/M11.6 后，FC4 任务 4 调度
- 但任务 4 进入路径（L162-170）栈消耗导致 VW290 永远不变成 4
- 即使变成 4，FC4 任务 4 完成切换（L213-221）栈消耗导致轮询卡死

## 八、整体建议

1. **BUG #M2（VW224 死代码）是隐藏最深的 BUG**——VW4 永远=4 让整个注射泵相关逻辑（FC13/FC21）完全失效。建议**立即删除 L78-89**。
2. **BUG #M1（任务切换栈消耗）让 Modbus 轮询只跑 1 次就停**——所有任务切换路径（L71-77、L108-114、L130-136、L162-170、L213-221）必须修复。
3. **BUG #M3（FC21 完全不可用）是模块级 P0**——FC21 全部子状态写指令都需要修复。
4. **BUG #M6（阀 A 无联锁）是安全隐患**——上缸满水时手动开阀 A 可能漫溢，必须加联锁。
5. **BUG #M7（孤儿态清除错误态）是 UX 问题**——操作员看到错误消失但实际未解决，可能误操作。
