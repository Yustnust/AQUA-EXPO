## 一、系统概述

设备为上下两层玻璃缸的实验室配液加注系统：
- **上部玻璃缸**：药剂配液缸，负责进纯净水、搅拌、加药
- **下部玻璃缸**：实验缸，接收配好的溶液，按换水周期定期更换

系统长期**无人值守**运行，因此所有异常检测、报警处理、断电恢复逻辑均按"最坏情况有人不在场"的原则设计。

**多单元架构原则【v9新增】**：全系统共8套上述缸体，各自独立成套（各1台PLC、1条485总线、1套阀门/泵/传感器），彼此之间**没有工艺耦合**，任一单元的故障、停机、程序下装/调试均不影响其余7套单元的实验运行。这一原则也延伸到安全设计：8套单元的急停回路、报警回路各自独立，不设集中联动急停或跨单元联动报警（详见第九章、第十二章）。

> 跨 POU 无 JMP/LBL 依赖，各 POU 内部 LBL 编号独立（FC0 用 1/2；SBR25 用 8/9/10/88/89；SBR26 用 1/3/4/5/6/7）。

> VD_Vol_Target（原 VD370，与 VD372 字节冲突）迁移至 VD584（VB584~VB587），断电保持区扩展为 VB1~VB600 连续覆盖。

## 四、顶层状态机（实验流程主状态）【v2.2重构更新：取消独立预循环与静止等候，上缸配液与下缸实验并行，引入24h换水次数硬约束】

v2.2 将原单一主状态机拆分为 **VW2（下缸主状态机）** 与 **VW304（上缸配液子流程状态）** 两个并行状态字：下缸实验（S4→S5→S6）与上缸配液（S1→S2→S3）同时运行，仅在 S4 处交汇。

### 4.1 VW2（下缸主状态机）

| 值  | 状态       | 说明                  |
| -- | -------- | ------------------- |
| 0  | S0 初始化   | 待机、等待启动             |
| 5  | S4 转移    | 上缸 → 下缸转移（上下缸唯一交汇点）      |
| 6  | S5 实验运行  | 下缸内有液或正在转移/排水，实验计时中 |
| 7  | S6 下缸排水  | 下缸排空                |
| 8  | S7 实验结束  | 全部结束                |
| 99 | S_ERROR | 报警停机                |

### 4.2 VW304（上缸配液子流程状态）

| 值 | 状态         | 说明            |
| - | ---------- | ------------- |
| 0 | 空闲         | 上缸无配液任务       |
| 1 | S1 上缸进水    | 阀A开，流量计累计（差值法）     |
| 2 | S2 搅拌 + 加药 | 潜水泵运行，同时注射泵加药 |
| 3 | S3 配完等待转移  | 已完成，等下缸排空     |
| 4 | 已转移        | 本轮完成，准备下一轮触发  |

### 4.3 流程说明

```
S0 初始化
   → 上下缸状态强制置"空"（开机默认，也可HMI手动强制）
   → 所有阀门/泵输出复位为OFF
   → 按下HMI启动后，首轮直接进入 S5 下缸空等，同时触发首轮 S1 上缸进水
   ↓
S1 上缸进水（VW304=1）【v8差值法保留】
   → 阀A开，同步启动"S1实测计时器"，记录 VD_S1_Actual
   → 阀A开启瞬间快照流量计"计量值"寄存器(0x0009)为 VD_FlowMeter_Snapshot
   → 持续用"当前计量值 − 快照值"计算本次进水量
   → 本次进水量 ≥ HMI设定 VD_TargetInletVolume → 立即关阀A（关闭后延时验证见第五章）
   → 液位计A-高位全程监测，一旦触发 → 立即关阀A+关NC球阀-上缸，转入漫溢报警
   ↓（阀A关闭且验证通过）
   → VW304 = 2，进入 S2 搅拌 + 加药合并阶段

S2 搅拌 + 加药（VW304=2）【v2.2合并：取消独立预循环】
   → 开启潜水泵1、潜水泵2，同时启动注射泵加药
   → 按 VD_PreMixTime(VD28) 严格固定计时（T38），不压缩、不调整
   → 注射泵采用"目标步数→抽液→轮询→排液→轮询"完成判定（沿用第六章注射泵逻辑）
   → T38 计时到且注射泵动作完成 → VW304 = 3，进入 S3 配完等待转移

S3 配完等待转移（VW304=3）
   → 上缸溶液已配好，等待下缸排空、具备转移条件
   → 不触发任何报警，保持等待即可

S4 上→下转移（VW2=5，唯一交汇点）
   → 必须同时满足：下缸已排空（V1.7=0）且上缸已配完（VW304=3）
   → 阀B开，同步启动 T49 转移实测计时器；监测流量开关B+液位计A-低位，正常排空后关阀B
   → 液位计B-高位全程监测，一旦触发 → 立即关阀B+关NC球阀-下缸，转入漫溢报警
   → 上缸状态置"空"，下缸状态置"满"
   → T49 停止，将实测时长写入 VD_S6_Rolling(VD116)，作为本轮 S6 实际排水时长
   → VW304 = 4（已转移）
   ↓
S5 实验运行中（VW2=6）
   → 下缸"满"状态期间持续累加 VD_ExperimentDuration_Accum
   → S5 阶段覆盖完整的单轮换水周期：从本轮回 S4 转移完成开始，到下一轮回 S6 排水结束为止
   → FC40 持续管理当前活动倒计时器（T46/T48），并负责：
       1. 当倒计时剩余 ≤ VD_S6_Rolling 时，触发 S6（VW2=7）
       2. 当倒计时剩余 ≤ (VD_S1_Actual + VD_PreMixTime + VD430) 时，触发下一轮 S1（M16.1 脉冲）
       3. 倒计时到 0 仍未触发 S6 → 报警 V303.6（单轮换水周期超时）
   ↓（FC40触发S6）
S6 下缸排水（VW2=7）
   → 阀C开，监测流量开关C+液位计B-低位，正常排空后关阀C
   → 下缸状态置"空"，下缸"满"状态期间累加的实验时长已计入 VD_ExperimentDuration_Accum
   ↓（下缸排空）
   → 若 VW304 = 3（上缸已配完）:
       - 若结束条件满足（VW306 ≥ VD414 且 VD_ExperimentDuration_Accum ≥ VD_ExperimentTarget）→ 转 S7（VW2=8）
       - 否则 → 转 S4（VW2=5），换水计数 VW306 +1，切换双倒计时器标记 M16.0，开始下一轮
   → 若 VW304 ≠ 3（上缸未配完）→ 保持等待，不报警；待上缸完成后自然进入 S4

S7 实验结束（VW2=8）
   → 状态机锁定，所有阀门/泵停止
   → HMI滚动条提示"⚠️ 实验已结束，请按【系统复位】按钮后再启动"
   → 唯一出口为物理系统复位按钮 I0.3；回 S0 后再由 HMI 启动进入新一轮
```

### 4.4 关键规则

- **S4 转移是上下缸唯一交汇点**：必须同时满足"下缸排空（V1.7=0）"和"上缸已配完（VW304=3）"，避免下缸空等或上缸溶液未就绪即转移。
- **取消独立预循环**：S1 结束后直接进入 S2 搅拌+加药合并阶段，搅拌时间 VD28 严格固定，不可压缩。
- **上缸未配完时不报警**：S6 排水完成后若 VW304≠3，系统保持等待，不触发"24h换水次数无法保证"报警；该报警仅在倒计时到 0 仍未触发 S6 时由 FC40 触发。
- **结束条件**：必须同时满足换水次数 ≥ VD414 与实验时长累计 ≥ VD_ExperimentTarget，才进入 S7。
- **双倒计时器**：TimerA(T46) 与 TimerB(T48) 交替分配给连续轮次，每个计时器从本轮回 S1 开始，到本轮回 S6 结束，严格保证单轮换水周期。详见第七章。

> 原 S1/S2/S3/S3.5 作为独立主状态在 VW2 中的描述已删除；S1/S2/S3 现作为 VW304 上缸子流程状态并行执行。S5 不再执行原"预计排空时刻"比较与三层预规划，改为由 FC40 基于双倒计时器管理周期。

## 五、阀A"关闭后延时验证"逻辑【v7更新：加入限位反馈交叉诊断】

```
运行中：
  持续计算 本次进水量 = 当前流量计"计量值" − VD_FlowMeter_Snapshot（差值法，见第四章S1）
  → 本次进水量 ≥ HMI设定进水量：立即下达"关阀A"指令，锁存此刻"计量值"读数，启动延时 VD_Delay_ValveA_Verify

延时到达后校验：
  - 流量开关A应变为OFF：若仍为ON → 报警"阀A关闭异常或流量开关A故障"
  - 若阀已关闭但流量计"计量值"仍在持续增长（即差值仍在扩大）→ 报警"阀A内漏或流量计异常"

限位反馈交叉诊断【v7新增】：
  - 阀A关到位反馈(I8.1) 应在延时内变ON：
    若超时仍未ON → 报警"阀A执行机构关闭故障"（与流量开关无关，直接定位到阀体/执行器）
    若已ON但流量开关A仍显示有流 → 报警"阀A关到位但仍有流量，怀疑内漏"（与上面"流量计仍增长"是同一类问题，两个信号源交叉验证，提高判断可信度）
  - 阀A开启时同理：下达开阀指令后，阀A开到位反馈(I8.0)应在超时内变ON：

    若已ON但流量开关A始终无流 → 报警"阀A已开到位但无流量，怀疑上游缺水/管路堵塞/流量开关故障"（排除阀本身故障的可能）

全程安全监测（独立于上面逻辑，优先级最高）：
  液位计A-高位闭合 → 立即关阀A + 关NC球阀-上缸 + 触发漫溢类报警（强制人工确认）
```

## 七、双倒计时器周期管理 — FC40 功能重构【v2.2更新：删除三层纠偏，改为双倒计时器管理】

v2.2 取消原"配液节奏滞后—三层自动纠偏"机制，改为通过 **FC40_RhythmCorrection** 管理两个交替工作的周期倒计时器（T46/T48），严格保证 24h 换水次数硬约束。

### 7.1 设计原则

- **24h 换水次数硬约束**：用户通过 HMI 设定 24h 内下缸必须完成的换水次数 `VD414`，系统据此算出单次目标周期 `T_single = 86400.0 / VD414`。
- **双倒计时器交替**：TimerA(T46) 与 TimerB(T48) 交替分配给连续轮次，每个计时器从该轮 **S1 开始**计时，到该轮 **S6 结束**停止。
- **周期余量扣除**：实际倒计时总时长 `T_cycle = T_single − VD426 − VD430`，其中 VD426 为周期尾端转移余量，VD430 为上缸配液安全余量。
- **搅拌时间不可压缩**：VD28 为 S2 搅拌固定时长，不再参与任何纠偏压缩。
- **上缸未配完不报警**：S6 排水完成后若上缸尚未配完，系统保持等待，不触发报警；仅当倒计时归零仍未触发 S6 时，才报警"单轮换水周期超时"。

### 7.2 双倒计时器时序

```
时间轴 ─────────────────────────────────────────────────────────────────→

轮次N:    S1 → S2 → S3 → S4 → S5 → S6
          ↑_________________________↑
               TimerA 倒计时（T46）

轮次N+1:                  S1 → S2 → S3 → S4 → S5 → S6
                            ↑_________________________↑
                                 TimerB 倒计时（T48）

轮次N+2:                                          S1 → S2 → S3 → S4 → S5 → S6
                                                      ↑_________________________↑
                                                           TimerA 复用
```

- 当前下缸轮次使用哪个计时器由 `M16.0` 标记：M16.0=1 使用 TimerA(T46)，否则使用 TimerB(T48)。
- 每轮 S4 转移完成后切换 `M16.0 = NOT M16.0`，为下一轮启用另一个计时器。
- 每轮 S1 开始时根据 `M16.0` 选择启动 T46 或 T48，PT = `T_cycle × 10`（100ms 时基）。

### 7.3 周期计算

```
T_single  = 86400.0 / VD414          // 单次目标周期（秒）
T_cycle   = T_single − VD426 − VD430 // 实际倒计时总时长（秒）
```

若 `T_cycle ≤ 0`，则禁止启动，并报警 V303.6（周期参数过激进）。

### 7.4 计时器启动（S1 开始时执行）

```
IF M16.0 = 1 THEN
    VW286 = T_cycle × 10            // TimerA 的 PT 值（100ms时基）
    TON   T46, VW286                // 启动 TimerA
ELSE
    VW288 = T_cycle × 10            // TimerB 的 PT 值
    TON   T48, VW288                // 启动 TimerB
END_IF
```

### 7.5 S6 触发条件

```
S6_actual = VD116                   // S6滚动实测时长（首轮时实际存的是S4实测）
IF VW306 = 0 THEN
    S6_actual = VD108               // 首轮无实测值用默认值
END_IF

// TON 当前值 PV 为 100ms 时基，需与 S6_actual × 10 比较
IF Timer_Current_PV <= S6_actual × 10 AND VW2 = 6 AND VW6 = 0 THEN
    MOVW 7, VW2                     // 转 S6 排水
END_IF
```

### 7.6 下一轮 S1 触发条件

触发下一轮 S1 时，当前轮的 S1 已经完成，VD70 已有实测值，无需默认值。

```
Prep_Needed = (VD70 + VD28 + VD430) × 10    // 转换为 100ms 时基

IF Timer_Current_PV <= Prep_Needed AND VW304 = 0 AND VW6 = 0 THEN
    S  M16.1, 1                      // 触发下一轮 S1 脉冲
END_IF
```

### 7.7 倒计时到 0 报警

```
IF (M16.0 = 1 AND T46 计时完成) OR (M16.0 = 0 AND T48 计时完成) THEN
    IF VW2 ≠ 8 THEN                  // 不在 S7 结束态
        S  V303.6, 1                 // 单轮换水周期超时报警
    END_IF
END_IF
```

## 九、急停逻辑（硬件断电 + 软件感知复位 + 安全继电器反馈确认，v3更新）

### 9.1 接线原则：双触点分离，PLC监测回路与动力回路物理独立

急停按钮本身必须为**常闭型**触点（断线即安全：接线松脱或电缆断裂时效果等同于按下急停，系统自动进入安全停止状态，不会因故障而"检测不到急停"）。急停按钮至少需要两组独立常闭触点，分别用于两条完全独立的回路：

```
【第一组常闭触点】—— 安全回路，不经过PLC
  → 串入安全继电器（强制导向/force-guided型）的输入回路
  → 安全继电器线圈失电后，其主触点断开，切断潜水泵/注射泵/电动球阀的
    220V/380V动力电源（纯硬件动作，与PLC逻辑完全无关，PLC死机/程序卡死时仍生效）

【第二组常闭触点】—— PLC监测回路
  → 独立走PLC自身的24VDC电源，不接触220V
  → 接入 I1.1，供PLC感知"急停已被按下"，用于软件层面的状态机锁定与复位判断
```

两组触点物理独立、互不影响，即使PLC监测回路出现故障（断线、DI点损坏等），也不影响第一组触点直接切断动力电这一最基础的安全保障。

### 9.2 安全继电器反馈确认（新增，解决"动力回路是否真正切断"的确认问题）

普通接触器/继电器存在主触点因电弧烧蚀而粘连熔焊的风险——线圈已失电、控制回路已正确动作，但主触点可能仍卡死在闭合状态，动力电实际未断开，且PLC和操作员对此毫不知情。因此安全继电器必须选用**强制导向型（force-guided）**规格：其主触点（切动力电）与辅助反馈触点在机械结构上强制联动，主触点若粘连闭合，辅助反馈触点绝不可能同时显示"已断开"——这是判断动力回路是否真正切断的可靠依据。

```
安全继电器的强制导向辅助触点 → 独立接入PLC I1.2【v10.2纠正实际接线：I1.2=1 表示动力回路已接通；I1.2=0 表示动力回路已断开】

急停真正生效的判定条件（双重确认）：
  I1.1 = OFF（急停按钮已触发）
  AND I1.2 = 0（安全继电器辅助触点反馈动力回路已切实断开）
  → 才判定"急停真正生效"

若 I1.1 已触发（OFF），但延时一定时间后 I1.2 仍未反馈"已断开"：
  → 判定"安全继电器/接触器故障，主触点可能粘连（动力应断开但仍接通）"
  → 触发【继电器故障】最高优先级报警（见9.4），不允许任何自动恢复尝试，
    必须立即人工检修
```

> 建议选型时优先考虑符合 EN ISO 13849-1 / IEC 60204-1 标准、内置双通道冗余自检功能的安全继电器模块（如Pilz、Schmersal等品牌的对应产品），这类模块能周期性自检两路通道状态是否一致，进一步降低隐性故障风险。

### 9.3 急停触发与解除流程

```
急停触发：
  【硬件通道】安全继电器切断潜水泵、注射泵、电动球阀的动力回路（不经过PLC逻辑，物理层面立即生效）
  【软件通道】I1.1检测到OFF后：
    1. 强制所有阀门/泵内部输出线圈复位为OFF（M_EStop_Latch置位）
    2. 顶层状态机锁定，禁止任何自动状态切换
    3. 触发报警：灯光DO常亮（漫溢级处理）；声音DO按消音逻辑处理
    4. HMI显示"急停触发，等待释放急停按钮；释放后仍需按现场系统复位"
    5. 延时校验 I1.2 是否已变为 0（动力断开确认），I1.2 仍为 1 则升级为【继电器故障】最高级报警（见9.4）【v10.2 纠正】

急停解除【v9.1确认：急停释放不等于系统复位】：
  → I1.1恢复ON（触点重新闭合）后，状态机不自动恢复，M_EStop_Latch保持置位
  → 急停按钮旋转/拔起释放只代表硬件急停触点恢复，不清除PLC急停锁存，也不恢复自动流程
  → 操作员确认现场安全后，按下就地面板"系统复位按钮"(I0.3)
  → 复位后：上下缸状态强制置"空"，流程回到S0初始化重新开始
  → 不支持从中断点继续运行
```

### 9.4 继电器故障报警（新增，最高优先级）

```
触发条件：I1.1已确认急停触发（OFF），但超过设定延时后 I1.2 仍为 1（动力回路未断开）【v10.2 纠正】

处理方式：
  → 优先级高于漫溢风险级，不受 M_AlarmAckMode 影响，不允许任何形式的自动恢复
  → 状态机保持锁定，HMI持续提示"安全继电器/接触器故障，动力回路可能未真正切断，
    请立即人工检修，禁止在故障排除前尝试复位"
  → 该报警的确认/复位应设置为需要更高权限或更明确的二次确认操作（具体交互方式待后续
    HMI画面设计阶段细化），避免被误当作普通报警随手清除
```

### 10.2 RTC 时间同步机制（AQEX-51 新增，FC22_RTC_Sync）【v10.2 新增】

FC22 处理 HMI 校时请求与超时保护，每周期在 FC3（报警处理）之后、FC1（状态调度）之前由 OB1 调用：

```
OB1 调度顺序【v2.2更新,新增FC40周期管理 + FC10/FC11/FC1A上缸子流程调度】:
  FC0(SysInit) → FC2(EStop) → FC4(Modbus) → FC3(Alarm)
  → FC22(RTC Sync) → FC40(双倒计时器周期管理)【v2.2新增】
  → FC1(下缸主状态调度: VW2=0→FC10, VW2=5→FC15, VW2=6→FC16, VW2=7→FC17, VW2=8→FC18, VW2=99→FC19)
  → FC11(上缸S1, 仅 VW304=1 时)/ FC1A(上缸S2搅拌加药合并, 仅 VW304=2 时)【v2.2 FC1A替代原FC12+FC13串联】
  → FC20(阀门手动, 仅 VW2=0) / FC21(注射泵手动, 仅 VW2=0)
```

**v2.2 调度原则**:
- FC40 必须在 FC1 之前调用，确保 FC1 调度下缸主状态时已经得到最新的周期触发决策（M16.1 下一轮S1脉冲）。
- FC11/FC1A 调用位置由 OB1 而非 FC1 调度（FC1 只调度下缸 VW2 路径），避免 FC1 内调度嵌套导致状态机混乱。
- FC1 中**删除原 S1/S2/S3/S3.5 LBL 调度**（5.1 节），仅保留 S0/S4/S5/S6/S7/S_ERROR LBL。
- 上缸 VW304 子流程调度由 OB1 在 NET 7 完成（详见第七章附录 v2.2 FC 改动明细）。

**FC22 核心逻辑**：

1. 检测 V0.6（HMI 校时命令位）上升沿：
   - 将 VB906（星期）、VB907（保留）清零
   - 调用 TODW VB900 将 VB900~VB907（BCD 格式）写入 PLC RTC
   - 复位 V303.7 和 V0.6

2. 5 分钟超时保护：
   - 当 V303.7=1（请求校时）时，启动 T59（100ms 时基，PT=3000）
   - T59 计时到后，置 V303.5=1（M_Alarm_RTC_Lost），VW2=99（S_ERROR）

**涉及变量**：

| PLC 地址 | 名称 | 类型 | 说明 |
|---|---|---|---|
| V0.6 | CMD_RTC_Sync | 位 | HMI 校时命令位（上升沿触发） |
| V303.5 | M_Alarm_RTC_Lost | 位 | RTC 丢失报警（5 分钟超时后置位） |
| V303.7 | M_Need_RTC_Sync | 位 | 请求 HMI 校时标志 |
| VB900~VB905 | RTC_Year/Month/Day/Hour/Minute/Second | BYTE(BCD) | HMI 写入后 PLC TODW 的源缓冲区 |
| VB906 | RTC_Weekday | BYTE | 星期（不使用，固定清零） |
| VB907 | RTC_Reserved | BYTE | 保留 |
| T59 | 校时超时定时器 | 100ms TON | 5 分钟（3000×100ms） |

### 10.5.1 手动命令位（V306.0~V307.3）【v9.4 重大修复】

### 10.5.2 阀门/潜水泵手动控制（FC20）

FC20 使用中间存储 M13.0~M13.4 锁存手动输出状态，每周期映射到 Q 点，解决 S0 状态 FC 每周期清零 QB0 导致输出无法保持的问题。**仅 S0 态调用，非 S0 态由 OB1 清除 M13.0~M13.4**。

|---|---|---|
| M13.0 | Q0.2 + Q0.5 | 手动开阀A，同时联动打开上缸NC阀 |
| M13.1 | Q0.3 + Q0.6 | 手动开阀B，同时联动打开下缸NC阀 |
| M13.2 | Q0.4 | 手动开阀C（不联动NC阀） |
| M13.3 | Q0.0 | 手动启动潜水泵1 |

### 10.5.3 注射泵手动控制（FC21）【v10新增】

注射泵手动控制允许客户在 S0 态通过 HMI 手动启停注射泵，按参数页设定的总加药量执行**单次**或**循环**吸液/排液。由 OB1 仅在 S0 态调用。

**参数与反馈变量：**

| 地址 | 符号 | 说明 |
|---|---|---|
| VD384 | VD_ManualDose_Target | 手动总加药量（µL，HMI 设定），循环模式下为累积目标 |
| VW388 | VW_ManualDose_Mode | 模式选择：0=单次模式，1=循环模式 |
| VW390 | VW_ManualDose_State | 手动子状态反馈 |
| VD392 | VD_ManualDose_Dosed | 手动本轮累计加药量（µL，内部） |
| VD396 | VD_ManualDose_Remaining | 手动剩余待加药量（µL，内部） |
| VD350 | VD_StepResolution | 单步分辨率（µL/步），用于按总加药量折算步数 |

**子状态定义（VW390）：**

| 值 | 状态 | 说明 |
|---|---|---|
| 0 | 空闲 | 等待启动命令 |
| 1 | 抽液中 | 已下发 40006 抽液步数，等待完成 |
| 2 | 排液中 | 已下发 40007 排液步数，等待完成 |
| 3 | 回零中 | 已下发 40003 复位命令，等待完成 |
| 4 | 完成 | 单次 / 循环已结束并回零 |
| 99 | 错误 | 注射泵通讯 / 状态异常 |

**动作流程：**

```
启动(V3.6 上升沿)
  ↓
初始化：VD_ManualDose_Dosed=0，VD_ManualDose_Remaining=VD_ManualDose_Target
  ↓
子状态1：折算本次步数 = min(VD_Remaining / VD_StepResolution, 6000)
          写 40006 = 本次步数
  ↓
子状态2：等待抽液完成（VW4 从忙变就绪）
  ↓
子状态3：写 40007 = 本次步数
  ↓
子状态4：等待排液完成，累加 VD_ManualDose_Dosed
  ↓
子状态5：判断
  ├─ 停止请求(V3.7)=1           → 子状态6回零
  ├─ 单次模式                   → 子状态6回零
  ├─ 循环模式且累计≥目标量        → 子状态6回零
  └─ 循环模式且累计<目标量        → 返回子状态1继续下一周期
  ↓
子状态6：写 40003 = 1（复位 / 回零）
  ↓
子状态7：等待回零完成，VW390=4，结束
```

**关键行为：**
- **停止按钮是"软停止"**：非急停，置位停止请求后当前吸/排液周期仍完成，随后回零结束。
- **运行中再次按启动无效**，防止重置当前周期。
- **通讯异常兜底**：注射泵通讯失败（V303.4）或状态码错误（VW4≥4）时立即停止并置 VW390=99。
- **与自动 S3 隔离**：手动模式使用独立累计/剩余变量（VD392/VD396），不影响自动 S3 加药的 VD584/VD372/VD378。总加药量（VD384）仅供手动模式，**不用于 S3**，S3 目标量仍由工艺计算写入 VD584。

### 10.5.4 手动控制与自动工艺隔离

- 手动控制仅在 S0 态有效；进入 S1~S7、S_ERROR 时，OB1 清除全部手动锁存（M13.0~M13.4）与注射泵手动状态，确保返回 S0 前不残留手动输出。
- 急停、漫溢报警时，手动输出与自动输出一并强制失效，NC 阀按安全逻辑关闭。

### 12.5 单机故障隔离原则

任一PLC故障、断网、或程序下装调试期间，仅影响其对应的1套缸单元；其余7套单元的实验运行不受影响。HMI对该单元仅表现为"通讯中断"提示，不触发其余单元的任何联动动作。

HMI故障、重启或断网时，8套PLC不得依赖HMI继续执行实时控制；正在运行的自动流程应按PLC内部逻辑继续或按故障策略进入安全状态。急停和急停后的系统复位均为就地物理回路/按钮，不依赖HMI；报警确认、参数修改、状态强制修正等HMI操作在HMI恢复前暂停。

- 新增单元的PLC上电、接入以太网交换机、配置IP（192.168.2.10X）
- PLC程序无需重新下装或修改，8套PLC程序完全相同
- 在HMI画面8系统设置页勾选新单元使能开关，该单元在HMI总览页自动转为正常显示
- 扩展过程不影响已运行单元，符合"任一单元故障、停机、程序下装/调试均不影响其余单元"的架构原则

**HMI动态显隐机制概述**（详见《HMI画面架构规划文档》第九章）：
- HMI通过"单元使能（HMI内部位变量，断电保持）+ PLC通讯在线（HMI驱动自动检测）"双条件判定每个单元的显示状态
- 三态显示：已使能+在线→彩色正常；已使能+离线→黄色"通讯中断"占位；未使能→灰色"未接入"占位
- 8个单元卡片位置固定，不随接入数量重新排列，便于操作员形成固定位置记忆
- 单元使能变量存储在HMI断电保持区，不写入PLC
