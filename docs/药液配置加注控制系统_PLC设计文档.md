## 一、系统概述

设备为上下两层玻璃缸的实验室配液加注系统：
- **上部玻璃缸**：药剂配液缸，负责进纯净水、搅拌、加药
- **下部玻璃缸**：实验缸，接收配好的溶液，按换水周期定期更换

系统长期**无人值守**运行，因此所有异常检测、报警处理、断电恢复逻辑均按"最坏情况有人不在场"的原则设计。

**多单元架构原则【v9新增】**：全系统共8套上述缸体，各自独立成套（各1台PLC、1条485总线、1套阀门/泵/传感器），彼此之间**没有工艺耦合**，任一单元的故障、停机、程序下装/调试均不影响其余7套单元的实验运行。这一原则也延伸到安全设计：8套单元的急停回路、报警回路各自独立，不设集中联动急停或跨单元联动报警（详见第九章、第十二章）。

**流量计Modbus寄存器表（节选，与本设计相关部分）：**

| 寄存器 | 地址(HEX) | 含义 | 说明 |
|---|---|---|---|
| 0x0009 | 计量值 | 0~99999999，**只读**，低3位为小数部分 | 持续累加，**无清零/复位寄存器**，需用差值法计算单次进水量（见第四章S1） |
| 0x000F | 平均流速 | 只读，低2位小数 | 近1分钟平均流量，仅供监测参考 |
| 0x0017 | 瞬时流速 | 只读，低2位小数 | 实时流速，仅供监测参考 |
| 0x0012 | 单位 | 可读写，默认按"升(L)"=0x03假设 | 需现场核实实际配置值 |

**重要澄清（v8）**：该流量计"计量值"寄存器为**持续累加、只读**，设备本身**不提供清零/复位功能**（0x0011~0x0015等可写寄存器均为通讯地址/波特率/单价/单位/校正参数等配置项，与累计流量清零无关）。因此PLC无法像常见做法那样"进水前清零、进水后直接读增量"，必须改用**差值法**：阀A开启瞬间先读取并快照当前"计量值"，进水过程中用"当前计量值 − 快照值"计算本次实际进水量，详见第四章S1。

| 寄存器 | 地址(HEX) | 含义 | 说明 |
|---|---|---|---|

| 40003 | 0x0002 | 复位 | 0空闲，1复位（即初始化，泵上电后必须先执行一次） |
| 40006 | 0x0005 | 抽液 | 0~最大行程，**单位：步数**，写入目标抽取步数 |
| 40007 | 0x0006 | 排液 | 0~最大行程，**单位：步数**，写入目标排放步数 |

**重要澄清（v6）**：该泵为**柱塞式计量泵**（丝杆推动活塞，一次行程完成固定体积的抽取或排放），**不是**连续流动的蠕动泵/隔膜泵。控制方式是**直接写入目标步数**，泵完成后停止，没有"持续运行时长"的概念。因此第四章S3的加药逻辑改为"计算目标步数→下发抽/排液指令→轮询状态码确认完成"，不再是"运行时长计算"，详见下方S3更新。

## 四、顶层状态机（实验流程主状态）【v2更新：新增静止等候子步骤、节奏滞后判断、实验结束终态】

```
S0 初始化
   → 上下缸状态强制置"空"（开机默认，也可HMI手动强制）
   → 所有阀门/泵输出复位为OFF
   ↓
S1 上缸进水（阀A开启条件成立）【v8更新：流量计差值法】
   → 阀A开，同步启动"S1实测计时器"
   → 阀A开启瞬间，读取流量计"计量值"寄存器(0x0009)，快照为 VD_FlowMeter_Snapshot
   → 持续读取当前"计量值"，计算 本次进水量 = 当前计量值 − VD_FlowMeter_Snapshot
   → 本次进水量 ≥ HMI设定进水量 → 立即关阀A（关闭后延时验证，见第五章）
   → 液位计A-高位全程监测，一旦触发 → 立即关阀A+关NC球阀-上缸，转入漫溢报警
   ↓（阀A关闭且验证通过，上缸状态置"满"，S1实测计时器停止，记录本次S1实测时长S1_actual，
     本次进水量同时作为S3加药公式"上缸注水量"的输入）
   → 【v3新增】用S1_actual执行一次二次校正计算（见第七章7.3），
      重新核定本轮 VD_S2_Target / VD_RestTime_Target

   → 开启潜水泵1、潜水泵2，仅搅拌，不加药
   → 按 VD_S2_Target 计时（该目标值已在S5触发时预规划、S1完成后二次校正，见第七章）
   ↓
S3 加药【v6重写：步数控制+状态轮询，非时长控制】
   → 计算目标抽取体积：V目标 = (目标浓度×上缸注水量) / 母液浓度
   → 换算为步数：N步 = V目标(µL) ÷ 单步分辨率(µL/步)，单步分辨率取决于所选进样器规格

   → 写入注射泵"排液"寄存器(40007)=N步，下发排放到管路指令（泵阀一体内部阀自动切换流路）
   → 轮询状态码寄存器(41001)，确认排放动作完成/无错误
   → 潜水泵在整个S3期间持续运行（搅拌+加药同时进行）
   → S3完成判定：以状态码反馈为准，不是固定时长；S3计算值用于T的预估时仍可给出理论估算
     （N步×单步耗时的理论值），但实际完成时刻以轮询结果为准，逻辑上与S1"以流量计读数
     判断完成"是同一模式
   ↓
S3.5 静止等候【v2新增】
   → 溶液沉降缓冲，按 VD_RestTime_Target 计时（该目标值已在S5触发时预规划、S1完成后二次校正）
   ↓（S1实测 + S2标称 + S3计算 + 静止等候标称 = 本轮总时长，滚动更新 VD_T_Rolling）
S4 上→下转移（阀B开启条件成立，见第六章四态诊断）
   → 阀B开，监测流量开关B+液位计A-低位，正常排空后关阀B
   → 液位计B-高位全程监测，一旦触发 → 立即关阀B+关NC球阀-下缸，转入漫溢报警（不管四态诊断处于哪个状态）
   → 上缸状态置"空"，下缸状态置"满"
   → 记录下缸变满时间戳 DT_TankB_FullTime
   → 下缸"满"状态开始期间，持续累加 VD_ExperimentDuration_Accum
   ↓
S5 实验运行中（等待换水周期）【v4更新：调度预规划计算触发点改回S5，上升沿触发；v9.2更新：移除温度/pH采集】
   → 持续计算：下缸预计排空时刻 = DT_TankB_FullTime + VD_CycleSetpoint + VD_S6_Rolling
   → 持续比较：(下缸预计排空时刻 − 当前时间) ≤ VD_T_Rolling ？
     该条件由"不满足"变为"满足"的**上升沿**（仅触发一次，非逐扫描周期重复触发）：
       1. 立即执行一次性节奏预规划计算（可用时间=下缸预计排空时刻−当前时间 vs
          所需时间=VD_T_Rolling），按三层纠偏算法（见第七章）算出本轮
          VD_S2_Target / VD_RestTime_Target / VD_CycleExtend_Target
       2. 若上缸状态=空，同时启动新一轮S1；若上缸状态≠空，说明上一轮尚未收尾完成，
          属于比"节奏滞后"更严重的异常，单独报警（不在第七章讨论范围内）
   → 持续判断：VD_ExperimentDuration_Accum ≥ VD_ExperimentTarget？
              → 是 → 转入 S7 实验结束
   ↓（达到换水周期，下缸状态="满"，阀C/流量开关C无报警）
S6 下缸排水（阀C开启条件成立，见第六章四态诊断）
   → 阀C开，同步启动"S6实测计时器"，监测流量开关C+液位计B-低位，正常排空后关阀C
   → 下缸状态置"空"，S6实测计时器停止，滚动更新 VD_S6_Rolling
   → 下缸"满"状态结束，本轮满液时长已计入累加值
   ↓（下缸排空）
   → 若新一轮S1-S3.5已完成（阀B转移就绪）→ 直接返回S4转移

S7 实验结束【v2新增】
   → 状态机锁定，所有阀门/泵停止
   → HMI提示"实验时长已达标，实验结束"
   → 需人工在HMI确认后才能重新进入S0开始新实验（不自动重启）
```

## 七、配液节奏滞后 — 三层自动纠偏机制【v4更新：触发点改回S5上升沿，预规划+S1后二次校正】

### 7.1 设计原则：预先规划，而非执行中逐层试错

三层纠偏（压缩静止等候→压缩S2→顺延周期）中，**S2排在S3.5之前执行**——如果等到S3.5阶段才发现"纠偏不够用"，S2早已按标称时长跑完，来不及回头压缩。因此纠偏方案**必须在S1开始之前就一次性规划好本轮S2、S3.5各自要用多少时长**，而不是走一步看一步。

### 7.2 预规划计算触发点：S5阶段调度条件达成的上升沿

```
持续比较（第四章S5）：(下缸预计排空时刻 − 当前时间) ≤ VD_T_Rolling ？
该条件由"不满足"变为"满足"的上升沿触发一次计算（非逐扫描周期重复触发，PLC用
比较指令+边沿检测指令实现，与"固定节点算一次"实现难度相同）：

可用时间 Available = 下缸预计排空时刻 − 当前时间（触发那一刻的值，理论上正常情况下
                     应约等于 VD_T_Rolling，因为条件刚好在这一刻达成）
所需时间 Needed = VD_T_Rolling（本轮S1-S3.5标称总时长）

正常情况下 Available ≈ Needed，Δ≈0，本轮无需纠偏，直接按标称参数执行——
纠偏机制真正派上用场的场景，主要是"S1完成后二次校正"（见7.3）阶段捕捉到的
实际执行偏差，而不是这一步的预规划计算本身。

若 Available ≥ Needed（含近似相等情况）：
  → VD_S2_Target = VD_PreMixTime，VD_RestTime_Target = VD_RestTime，
    VD_CycleExtend_Target = 0
  → 若上缸状态=空，立即启动新一轮S1

若 Available < Needed（例如上一轮转移收尾延后、导致这一刻上缸还不能立即开始S1，
                       使实际可用时间比理论值更紧张），缺口 Δ = Needed − Available，
按顺序分层扣减：

  第0层额度 = VD_RestTime − VD_RestTime_Min
    若 Δ ≤ 第0层额度：
      VD_RestTime_Target = VD_RestTime − Δ
      VD_S2_Target = VD_PreMixTime
      VD_CycleExtend_Target = 0 → 规划完成
    否则：
      VD_RestTime_Target = VD_RestTime_Min（第0层用满）
      Δ = Δ − 第0层额度，继续第1层

  第1层额度 = VD_PreMixTime − VD_PreMixTime_MinSafe
    若 Δ ≤ 第1层额度：
      VD_S2_Target = VD_PreMixTime − Δ
      VD_CycleExtend_Target = 0 → 规划完成
    否则：
      VD_S2_Target = VD_PreMixTime_MinSafe（第1层用满）
      Δ = Δ − 第1层额度，继续第2层

  第2层额度 = VD_CycleExtend_Max
    若 Δ ≤ 第2层额度：
      VD_CycleExtend_Target = Δ（即预计下缸排空后允许"空等" Δ 这么久，
                                 等新溶液经S1-S3.5配好、阀B转移完成，见第四章S6末尾）
      → 规划完成，同时触发"配液节奏滞后"提示报警（一般故障级，非漫溢级）
    否则：
      → 三层额度全部用尽仍不够，触发【人工介入】报警（见7.4），
        M_Alarm_ScheduleLag 置位，停止自动纠偏，本轮不再规划，等待人工处理

若上缸状态=空，规划完成后立即启动新一轮S1。
```

### 7.3 S1完成后二次校正（提高精度，主要纠偏场景）

S1的实际耗时存在波动（如水压变化），是本机制真正需要应对的主要不确定性来源。S1真正跑完、上缸状态置"满"的那一刻，用实测值S1_actual重新校正一次剩余的S2、S3.5目标：

```
S1完成时刻，重新计算：
  剩余可用时间 Available' = 下缸预计排空时刻 − 当前时间（此刻重新取值，已扣除S1实际耗时）
  剩余所需时间 Needed' = VD_S2_Target（7.2已定的目标） + S3计算值 + VD_RestTime_Target（7.2已定的目标）

  按7.2同样的三层分层算法，用 Available' 和 Needed' 重新算一次 Δ'，
  重新核定 VD_S2_Target、VD_RestTime_Target（VD_CycleExtend_Target若在7.2已经定过，
  此处只做微调，不重复触发滞后报警，除非二次校正后发现缺口进一步扩大到超出已定额度）

  → 这一步用S1的确定性实测值替换了预规划阶段基于估算的假设，消除了S1本身波动带来的误差，
    使S2/S3.5的压缩量更精确，避免"压缩过头"或"压缩不够"
```

### 7.4 人工介入报警（触发条件：7.2预规划阶段或7.3二次校正阶段，三层额度用尽仍无法覆盖缺口）

```
处理方式：
  → 停止自动纠偏，M_Alarm_ScheduleLag 置位（需人工确认复位）
  → HMI提示"配液节奏严重滞后，已超出自动纠偏范围，需人工检查"
  → 系统保持当前状态等待人工处理，不再擅自继续顺延或空等
```

### 7.5 T的计算原则（沿用v2，无变化）

VD_T_Rolling滚动更新时仍取**标称值**（S1实测 + VD_PreMixTime标称 + S3计算 + VD_RestTime标称），不使用纠偏后的压缩值——因为它代表"正常无干扰情况下的基准耗时"，供下一轮预规划时估算所需时间用。

## 八、报警分级与消音/消光逻辑（沿用v1，无实质变化，漫溢类报警来源已扩展至上下两缸对称保护）

### 8.1 报警分级

| 级别 | 触发条件示例 | 处理方式 |
|---|---|---|
| **漫溢风险级（强制人工确认）** | 液位计A/B高位报警、任一NC球阀动作 | 无论 M_AlarmAckMode 设成什么，始终强制人工确认才能复位 |
| **节奏滞后级（强制人工确认）【v2新增】** | 三层纠偏用尽仍无法追平节奏 | 停止自动纠偏，强制人工确认后才能继续 |
| **一般故障级（按模式处理）** | 阀B/C四态诊断异常、超时保护触发、流量开关瞬时异常 | 按 M_AlarmAckMode 设定：人工确认模式→需在HMI执行报警确认；自动恢复模式→条件消失后自动清除 |

### 8.2 消音 / 消光独立处理（v9.1更新：消音与报警确认分离）

```
消音：操作员按下就地面板"消音按钮"(I0.4)，或在HMI报警页执行对应单元/全局消音命令，
      仅将声音DO置OFF，灯光DO、报警锁存和状态机锁定保持原状态；
      消音仅对当前已知报警生效，新报警重新鸣响
报警确认/消光：操作员必须先在本地HMI查看具体报警详情，再对指定单元/指定报警执行确认。
      报警根本原因未消失时，确认只记录"已知晓"，不得清除报警锁存或解锁流程；
      报警根本原因消失后，HMI下发报警确认命令，PLC才允许灯光DO置OFF、清除锁存并解锁状态机。
```

> 【v9.1说明】报警确认按钮放在HMI上，是因为操作员必须先通过屏幕看到具体报警类型、所属单元和可能原因后才能确认。HMI报警确认必须明确对象，默认不设置"一键确认全部8套"；高优先级报警（漫溢、节奏滞后人工介入、安全继电器故障等）应弹出二次确认或采用长按确认，避免误清除。

### 8.3 报警日志

记录字段：**时间戳 + 单元编号 + 报警类型 + 动作（触发/消音/已知晓/复位）**，写入断电保持区或HMI历史报警记录区。不做登录系统时不记录操作人员身份；若后续HMI启用权限登录，可扩展记录操作员名称。

## 九、急停逻辑（硬件断电 + 软件感知复位 + 安全继电器反馈确认，v3更新）

### 9.1 接线原则：双触点分离，PLC监测回路与动力回路物理独立

急停按钮本身必须为**常闭型**触点（断线即安全：接线松脱或电缆断裂时效果等同于按下急停，系统自动进入安全停止状态，不会因故障而"检测不到急停"）。急停按钮至少需要两组独立常闭触点，分别用于两条完全独立的回路：

```
【第一组常闭触点】—— 安全回路，不经过PLC
  → 串入安全继电器（强制导向/force-guided型）的输入回路
  → 安全继电器线圈失电后，其主触点断开，切断潜水泵/注射泵/电动球阀的
    220V/380V动力电源（纯硬件动作，与PLC逻辑完全无关，PLC死机/程序卡死时仍生效）

【第二组常闭触点】—— PLC监测回路
  → 独立走PLC自身的24VDC电源，不接触220V
  → 接入 I1.1，供PLC感知"急停已被按下"，用于软件层面的状态机锁定与复位判断
```

两组触点物理独立、互不影响，即使PLC监测回路出现故障（断线、DI点损坏等），也不影响第一组触点直接切断动力电这一最基础的安全保障。

### 9.2 安全继电器反馈确认（新增，解决"动力回路是否真正切断"的确认问题）

普通接触器/继电器存在主触点因电弧烧蚀而粘连熔焊的风险——线圈已失电、控制回路已正确动作，但主触点可能仍卡死在闭合状态，动力电实际未断开，且PLC和操作员对此毫不知情。因此安全继电器必须选用**强制导向型（force-guided）**规格：其主触点（切动力电）与辅助反馈触点在机械结构上强制联动，主触点若粘连闭合，辅助反馈触点绝不可能同时显示"已断开"——这是判断动力回路是否真正切断的可靠依据。

```
安全继电器的强制导向辅助触点 → 独立接入PLC I1.2

急停真正生效的判定条件（双重确认）：
  I1.1 = OFF（急停按钮已触发）
  AND I1.2 = 确认已断开（安全继电器辅助触点反馈动力回路已切实断开）
  → 才判定"急停真正生效"

若 I1.1 已触发（OFF），但延时一定时间后 I1.2 仍未反馈"已断开"：
  → 判定"安全继电器/接触器故障，主触点可能粘连"
  → 触发【继电器故障】最高优先级报警（见9.4），不允许任何自动恢复尝试，
    必须立即人工检修
```

> 建议选型时优先考虑符合 EN ISO 13849-1 / IEC 60204-1 标准、内置双通道冗余自检功能的安全继电器模块（如Pilz、Schmersal等品牌的对应产品），这类模块能周期性自检两路通道状态是否一致，进一步降低隐性故障风险。

### 9.3 急停触发与解除流程

```
急停触发：
  【硬件通道】安全继电器切断潜水泵、注射泵、电动球阀的动力回路（不经过PLC逻辑，物理层面立即生效）
  【软件通道】I1.1检测到OFF后：
    1. 强制所有阀门/泵内部输出线圈复位为OFF（M_EStop_Latch置位）
    2. 顶层状态机锁定，禁止任何自动状态切换
    3. 触发报警：灯光DO常亮（漫溢级处理）；声音DO按消音逻辑处理
    4. HMI显示"急停触发，等待释放急停按钮；释放后仍需按现场系统复位"
    5. 延时校验 I1.2 是否反馈"已断开"，未反馈则升级为【继电器故障】最高级报警（见9.4）

急停解除【v9.1确认：急停释放不等于系统复位】：
  → I1.1恢复ON（触点重新闭合）后，状态机不自动恢复，M_EStop_Latch保持置位
  → 急停按钮旋转/拔起释放只代表硬件急停触点恢复，不清除PLC急停锁存，也不恢复自动流程
  → 操作员确认现场安全后，按下就地面板"系统复位按钮"(I0.3)
  → 复位后：上下缸状态强制置"空"，流程回到S0初始化重新开始
  → 不支持从中断点继续运行
```

### 9.4 继电器故障报警（新增，最高优先级）

```
触发条件：I1.1已确认急停触发（OFF），但超过设定延时后 I1.2 仍未反馈动力回路已断开

处理方式：
  → 优先级高于漫溢风险级，不受 M_AlarmAckMode 影响，不允许任何形式的自动恢复
  → 状态机保持锁定，HMI持续提示"安全继电器/接触器故障，动力回路可能未真正切断，
    请立即人工检修，禁止在故障排除前尝试复位"
  → 该报警的确认/复位应设置为需要更高权限或更明确的二次确认操作（具体交互方式待后续
    HMI画面设计阶段细化），避免被误当作普通报警随手清除
```

## 十、换水周期与实验时长计时（时间戳方案）【v2：新增实验时长累加逻辑】

```
下缸状态由"空"变为"满"瞬间（阀B正常关闭完成后）：
  → 读取PLC当前RTC时间，写入 DT_TankB_FullTime（断电保持区）
  → 开始累加 VD_ExperimentDuration_Accum（仅在下缸="满"期间累加）

下缸状态由"满"变为"空"瞬间（阀C排空完成后）：
  → 停止累加，本轮满液时长已计入 VD_ExperimentDuration_Accum

实验停止判断（持续进行）：
  → VD_ExperimentDuration_Accum ≥ VD_ExperimentTarget（HMI设定）→ 转入S7实验结束

断电恢复：
  → DT_TankB_FullTime、VD_ExperimentDuration_Accum 均在断电保持区，
    前提是断电时长未超过CPU ST20超级电容保持能力（典型7天/最小6天）
  → 重新上电后用"当前RTC − DT_TankB_FullTime"重新算出已运行时长，累加值不受断电影响
  → 若断电时长超过6~7天导致RTC停走，需人工在HMI重新校准PLC时钟
    （建议加开机检测：若RTC时间早于DT_TankB_FullTime，判定时钟已丢失，触发提示报警）
```

## 十·五、手动控制逻辑【v10新增】

手动控制用于现场调试、阀门/泵检修、管路吹扫等场景，**仅在 S0 初始化态可用**（由 OB1 条件调用，非 S0 态不响应，返回 S0 前自动清除全部手动锁存）。手动控制划分为两部分：**阀门/潜水泵手动控制（FC20）** 与 **注射泵手动控制（FC21）**。

### 10.5.1 手动命令位（V2.4~V3.7）

手动命令位采用"上升沿触发 + PLC 清零握手"机制，区别于 V0 区系统命令位的置位握手，避免 HMI 侧残留 1 值导致重复触发。仅 VW2=0（S0）态响应。

| 地址 | 符号 | 说明 | 响应条件 |
|---|---|---|---|
| V2.4 | CMD_Manual_ValveA_Open | 手动开阀A | VW2=0 |
| V2.5 | CMD_Manual_ValveA_Close | 手动关阀A | VW2=0 |
| V2.6 | CMD_Manual_ValveB_Open | 手动开阀B | VW2=0 |
| V2.7 | CMD_Manual_ValveB_Close | 手动关阀B | VW2=0 |
| V3.0 | CMD_Manual_ValveC_Open | 手动开阀C | VW2=0 |
| V3.1 | CMD_Manual_ValveC_Close | 手动关阀C | VW2=0 |
| V3.2 | CMD_Manual_Pump1_On | 手动启动潜水泵1 | VW2=0 |
| V3.3 | CMD_Manual_Pump1_Off | 手动停止潜水泵1 | VW2=0 |
| V3.4 | CMD_Manual_Pump2_On | 手动启动潜水泵2 | VW2=0 |
| V3.5 | CMD_Manual_Pump2_Off | 手动停止潜水泵2 | VW2=0 |
| V3.6 | CMD_Manual_SyringePump_Start | 手动注射泵启动 | VW2=0 |
| V3.7 | CMD_Manual_SyringePump_Stop | 手动注射泵停止/回零 | VW2=0 |

**互锁说明**：手动操作时安全联锁仍生效（如阀B开启需上缸=满且下缸=空，阀C开启需下缸=满），由 PLC 在响应逻辑中校验。

### 10.5.2 阀门/潜水泵手动控制（FC20）

FC20 使用中间存储 M13.0~M13.4 锁存手动输出状态，每周期映射到 Q 点，解决 S0 状态 FC 每周期清零 QB0 导致输出无法保持的问题。**仅 S0 态调用，非 S0 态由 OB1 清除 M13.0~M13.4**。

| 锁存位 | 输出映射 | 说明 |
|---|---|---|
| M13.0 | Q0.2 + Q0.5 | 手动开阀A，同时联动打开上缸NC阀 |
| M13.1 | Q0.3 + Q0.6 | 手动开阀B，同时联动打开下缸NC阀 |
| M13.2 | Q0.4 | 手动开阀C（不联动NC阀） |
| M13.3 | Q0.0 | 手动启动潜水泵1 |
| M13.4 | Q0.1 | 手动启动潜水泵2 |

**NC 电磁阀联动规则【同步DO映射】**：
- 手动开阀 A → Q0.5 跟随 Q0.2（上缸 NC 阀打开）
- 手动开阀 B → Q0.6 跟随 Q0.3（下缸 NC 阀打开）
- 手动开阀 C → **不打开任何 NC 阀**（排水不经 NC 阀）
- 关阀后 NC 阀自动关闭

### 10.5.3 注射泵手动控制（FC21）【v10新增】

注射泵手动控制允许客户在 S0 态通过 HMI 手动启停注射泵，按参数页设定的总加药量执行**单次**或**循环**吸液/排液。由 OB1 仅在 S0 态调用。

**参数与反馈变量：**

| 地址 | 符号 | 说明 |
|---|---|---|
| VD384 | VD_ManualDose_Target | 手动总加药量（µL，HMI 设定），循环模式下为累积目标 |
| VW388 | VW_ManualDose_Mode | 模式选择：0=单次模式，1=循环模式 |
| VW390 | VW_ManualDose_State | 手动子状态反馈 |
| VD392 | VD_ManualDose_Dosed | 手动本轮累计加药量（µL，内部） |
| VD396 | VD_ManualDose_Remaining | 手动剩余待加药量（µL，内部） |
| VD350 | VD_StepResolution | 单步分辨率（µL/步），用于按总加药量折算步数 |

**子状态定义（VW390）：**

| 值 | 状态 | 说明 |
|---|---|---|
| 0 | 空闲 | 等待启动命令 |
| 1 | 抽液中 | 已下发 40006 抽液步数，等待完成 |
| 2 | 排液中 | 已下发 40007 排液步数，等待完成 |
| 3 | 回零中 | 已下发 40003 复位命令，等待完成 |
| 4 | 完成 | 单次 / 循环已结束并回零 |
| 99 | 错误 | 注射泵通讯 / 状态异常 |

**动作流程：**

```
启动(V3.6 上升沿)
  ↓
初始化：VD_ManualDose_Dosed=0，VD_ManualDose_Remaining=VD_ManualDose_Target
  ↓
子状态1：折算本次步数 = min(VD_Remaining / VD_StepResolution, 6000)
          写 40006 = 本次步数
  ↓
子状态2：等待抽液完成（VW4 从忙变就绪）
  ↓
子状态3：写 40007 = 本次步数
  ↓
子状态4：等待排液完成，累加 VD_ManualDose_Dosed
  ↓
子状态5：判断
  ├─ 停止请求(V3.7)=1           → 子状态6回零
  ├─ 单次模式                   → 子状态6回零
  ├─ 循环模式且累计≥目标量        → 子状态6回零
  └─ 循环模式且累计<目标量        → 返回子状态1继续下一周期
  ↓
子状态6：写 40003 = 1（复位 / 回零）
  ↓
子状态7：等待回零完成，VW390=4，结束
```

**关键行为：**
- **停止按钮是"软停止"**：非急停，置位停止请求后当前吸/排液周期仍完成，随后回零结束。
- **运行中再次按启动无效**，防止重置当前周期。
- **通讯异常兜底**：注射泵通讯失败（V303.4）或状态码错误（VW4≥4）时立即停止并置 VW390=99。
- **与自动 S3 隔离**：手动模式使用独立累计/剩余变量（VD392/VD396），不影响自动 S3 加药的 VD370/VD372/VD378。总加药量（VD384）仅供手动模式，**不用于 S3**，S3 目标量仍由工艺计算写入 VD370。

### 10.5.4 手动控制与自动工艺隔离

- 手动控制仅在 S0 态有效；进入 S1~S7、S_ERROR 时，OB1 清除全部手动锁存（M13.0~M13.4）与注射泵手动状态，确保返回 S0 前不残留手动输出。
- 急停、漫溢报警时，手动输出与自动输出一并强制失效，NC 阀按安全逻辑关闭。

## 十二、多机联网与本地集中HMI架构【v9新增/v9.1更新】

### 12.1 总体拓扑

```
                        ┌─────────────────────────┐
                        │   现场本地集中触摸屏 HMI   │
                        │ （10~15寸，建议12寸以上）  │
                        └───────────┬─────────────┘
                                    │ 工业以太网交换机
        ┌───────────┬───────────┬──┴────────┬───────────┬───────────┐
      PLC#1        PLC#2       PLC#3   ...  PLC#6       PLC#7       PLC#8
    （1号缸单元） （2号缸单元）（3号缸单元）      （6号缸单元） （7号缸单元） （8号缸单元）
```

每套缸单元的PLC通过CPU本体自带的以太网口接入交换机，与现场本地集中HMI组成同一以太网网段。HMI只做人机界面、参数设定、报警详情显示和确认，不承担实时控制逻辑；每套PLC内部仍完整保存本单元的状态机、报警锁存、急停处理、断电恢复、485设备轮询和泵阀控制逻辑。

每套单元自身的485总线（挂接注射泵/流量计2个从站【v9.2更新：原4个从站中的温度计、pH计已取消】）保持独立，不与其他单元共享，也不经过以太网转发。HMI或交换机故障时，PLC应继续按本地程序运行；需要人工操作的报警确认、参数修改等功能在HMI恢复前不可用，但不得影响急停硬件回路和PLC内部安全联锁。

### 12.2 IP地址规划（示例，需现场网络环境确认后定型）

| 设备 | IP地址（示例网段） | 说明 |
|---|---|---|
| PLC#1 ~ PLC#8 | 192.168.2.101 ~ 192.168.2.108 | 各PLC固定IP，与单元编号一一对应，便于故障定位 |
| 本地集中HMI | 192.168.2.10 | 固定IP |
| 工业以太网交换机 | 192.168.2.1（管理IP，若为网管型） | 8套缸同处一个实验室、彼此距离不远，1台9口及以上交换机即可满足组网需求，非网管型即可，无需分级级联 |

### 12.3 通讯协议与HMI选型

```
PLC↔HMI通讯协议：S7-200 SMART CPU本体以太网口支持S7通信协议、Modbus TCP（作为服务器）等；
                  具体采用哪种协议需与HMI品牌驱动支持情况匹配，待HMI选型阶段确认。

HMI选型建议：优先选用支持S7-200 SMART以太网通讯、支持多PLC站点连接、组态软件免费或随屏提供的
              工业触摸屏（如昆仑通态MCGS触摸屏、威纶通、步科、显控等同类产品）。
              屏幕尺寸建议不小于10寸，推荐12寸或以上，以便同时显示8套单元总览和报警摘要。
              需向厂家确认：是否支持同时连接8台S7-200 SMART PLC、变量点数、报警记录容量、
              历史趋势/数据记录能力、断电保存能力、工程软件下载授权方式。
```

### 12.4 就地物理操作与HMI操作分工

| 操作类型 | 执行位置 | 说明 |
|---|---|---|
| 急停 | 就地（各单元物理急停按钮） | 硬件安全回路，见第九章，不经过网络 |
| 急停后的系统复位 | 就地（各单元物理系统复位按钮，I0.3） | 急停旋转释放不等于系统复位；操作员确认现场安全后按本按钮，PLC回到S0初始化，见第九章9.3 |
| 消音 | 就地物理按钮I0.4，或HMI消音命令 | 只关闭声音，不清除报警、不解锁流程；可按单元消音，也可设置全局消音 |

### 12.5 单机故障隔离原则

任一PLC故障、断网、或程序下装调试期间，仅影响其对应的1套缸单元；其余7套单元的实验运行不受影响。HMI对该单元仅表现为"通讯中断"提示，不触发其余单元的任何联动动作。

HMI故障、重启或断网时，8套PLC不得依赖HMI继续执行实时控制；正在运行的自动流程应按PLC内部逻辑继续或按故障策略进入安全状态。急停和急停后的系统复位均为就地物理回路/按钮，不依赖HMI；报警确认、参数修改、状态强制修正等HMI操作在HMI恢复前暂停。

### 12.7 分期接入与HMI动态显隐【v9.3新增】

客户决定首期先实施1套单元验证效果，后续按需扩展至8套。本节说明分期接入对PLC侧的影响及与HMI侧动态显隐的配合。

**PLC程序侧（无需修改）**：
8套单元的PLC程序完全相同（本设计核心原则，见第一章"多单元架构原则"），每台PLC独立运行、不依赖其他PLC或HMI。PLC程序本身不需要知道自己"是否被HMI使能"——使能是HMI侧的管理概念，用于控制HMI画面显示哪些单元，不影响PLC内部状态机、安全联锁、485轮询等任何逻辑。

**首期实施（1套）**：
- 仅1号缸单元的PLC上电运行，2~8号缸单元的PLC不上电
- 1号PLC程序完整执行S0~S7流程，与全量8套时完全一致
- HMI工程按8套架构开发，但运行时仅1号单元使能并显示，2~8号灰显"未接入"（HMI侧机制，详见HMI画面架构规划文档第九章）

**后续扩展**：
- 新增单元的PLC上电、接入以太网交换机、配置IP（192.168.2.10X）
- PLC程序无需重新下装或修改，8套PLC程序完全相同
- 在HMI画面8系统设置页勾选新单元使能开关，该单元在HMI总览页自动转为正常显示
- 扩展过程不影响已运行单元，符合"任一单元故障、停机、程序下装/调试均不影响其余单元"的架构原则

**HMI动态显隐机制概述**（详见《HMI画面架构规划文档》第九章）：
- HMI通过"单元使能（HMI内部位变量，断电保持）+ PLC通讯在线（HMI驱动自动检测）"双条件判定每个单元的显示状态
- 三态显示：已使能+在线→彩色正常；已使能+离线→黄色"通讯中断"占位；未使能→灰色"未接入"占位
- 8个单元卡片位置固定，不随接入数量重新排列，便于操作员形成固定位置记忆
- 单元使能变量存储在HMI断电保持区，不写入PLC

**对BOM的影响**：
PLC、缸体设备等按套采购的条目天然支持分期（首期1套、后续按需增加）；交换机、HMI等公共设备需按全量8套规划容量，避免扩展时更换硬件。详见BOM清单分期标注。
