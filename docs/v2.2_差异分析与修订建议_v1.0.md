v2.2 流程重构方案 — 差异分析与修订建议
对《S2-S4 流程重构与 24h 换水次数硬约束设计方案 v2.2》及配套 PLC 代码进行逐项核对后，发现设计文档与实现代码在定时器方案、变量地址、状态机触发条件等方面存在多处不一致；同时 PLC 代码本身存在若干 P0 级逻辑缺陷，按现状无法自动完成首轮及后续换水循环。

文档版本：v1.1（v1.0 为硬件变更前基线，v1.1 仅增补基线说明，技术结论不变）
日期：2026-09-20
核对范围：docs v2.2 + plc/stl 主程序

> **版本基线说明（v1.1 增补）**：本报告 v1.0 生成于 v10.4 硬件变更（去除 S4 下缸 NC 阀 Q0.6、S6 流量开关 C I0.2）之前，核对对象为当时的 plc/stl 代码。v10.4 变更修改了 FC15/FC17（新增 VW284=VD60×10 计算等）并整体重写了 FC32，文中标注的行号（如 FC15 L34、FC17 L90、FC10 L45 等）可能已有少量偏移，引用时请以当前代码实际内容为准。本报告所列差异与缺陷（首轮 S1 启动、S6 排水触发、VD70、VW304=4 死状态、M16.0 重复翻转、VW290 冲突、计时器方案等）均与硬件变更正交，结论与定级在 v10.4 基线上依然成立。表 4 修订建议与后续代码修复任务应在 v10.4 之后的代码基线上执行。

2. 核心结论
关键判断
当前 PLC 程序无法按 v2.2 设计意图完成自动换水循环。主要阻塞点集中在“首轮 S1 无法启动”“S6 排水永不动作”“VD70 恒为 0”三个 P0 缺陷，以及“VW304=4 死状态”“M16.0 每周期翻转两次”等状态机逻辑错误。

设计方案文档本身仍停留在“T46/T48 TON 双倒计时器”的旧描述上，而实际代码已改为“VD248/VD252 32 位秒计数器 + T63 1 秒脉冲”的软件计时方案。文档与代码的不一致会直接影响后续调试、HMI 集成和验收。

建议先修订设计方案文档，明确以下三件事：

正式确认采用 VD248/VD252 + T63 的软件秒计数器方案，废弃 T46/T48 描述；
修正 FC10/FC11/FC15/FC17/FC40 之间的状态机协作逻辑，消除死状态和重复翻转；
同步更新变量地址表、HMI 变更清单和寄存器映射表。
3. 逐项差异与问题定级
3.1 致命缺陷（P0）— 程序无法自动运行
表 1：P0 级代码缺陷
缺陷	代码位置	具体表现	设计文档相关章节
P0 首轮 S1 永不启动	FC10 L45、OB1 NET 7	启动时 MOVW 0, VW304，然后置 M16.1；但全程序无消费者检查 M16.1 并把 VW304 切到 1	§5.8
P0 S6 排水永不动作	FC17 L15、FC16	FC17 以 M10.7 EU 作为 S6 首次进入脉冲，但 FC16 已删除对 M10.7 的置位，仅清不置	§5.6
P0 S1 实测时长 VD70 恒为 0	FC11 L30、L78-81	T37 仅被 R T37, 1 复位，从未 TON T37, ...；转 S2 时把 T37 当前值转 VD70	§5.3
P0 VW304=4 死状态	FC15 L34、OB1 NET 7	FC15 在 S4 完成后写 VW304=4，但 OB1 调度仅响应 1/2，且无其他 FC 把 4 转移走	§5.4
P0 M16.0 每周期翻转两次	FC15 L131、FC17 L90	S4 完成时切换一次，S6 完成时又切换一次，与设计“每个计时器跟踪完整 S1~S6 周期”矛盾	§2.3、§5.6
P0 下一轮 S1 触发条件不可达	FC40 NET 5 L125	触发条件要求 VW304=0，但首个周期后 VW304 走 1→2→3→4，永不回到 0	§4.4、§5.1
