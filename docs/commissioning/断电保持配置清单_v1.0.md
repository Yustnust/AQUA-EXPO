## 五、常见配置错误与排查

### 5.1 错误1: 漏配段6 (VB350~VB377)

**现象**: 断电后 VD350/VD354/VD366/VD370/VD374 全部归零
**原因**: AQEX-36迁移的6个VD参数未纳入保持范围
**修复**: 系统块→断电保持→添加 VB350~VB377 范围→重新下载项目→重做4.2验证

### 5.2 错误2: 漏配段5 (VB300~VB349)

**现象**: 断电后报警字VB300~VB303清零,VW6报警码可能丢失
**原因**: 报警字区域未覆盖
**修复**: 添加 VB300~VB349 范围(含VD308~VD344诊断数据迁移区)

### 5.3 错误3: 段范围重叠或断点

**现象**: 配置后某些变量保持,某些丢失
**原因**: 范围设置错误,如VB0~VB19 + VB200~VB223 中间VB20~VB199未配(此处属正常,但需确认VB230~VB289和VB300~VB349也无遗漏)
**排查**: 打印本清单2.1节,逐段核对系统块中断电保持范围列表

### 5.4 错误4: 配置后未下载到PLC

**现象**: STEP7中配置正确,但断电后变量仍丢失
**原因**: 修改系统块后未重新下载项目到PLC
**修复**: 文件→下载→选择"系统块"→下载→PLC断电重启

### 5.5 错误5: RTC时间丢失

**现象**: 断电较长时间(>7天)后,DT10时间戳异常,M_Alarm_RTC_Lost置位
**原因**: CPU ST20超级电容典型保持7天/最小6天,长时间断电会丢失RTC
**修复**: 这是设计预期行为,见plc_simulator FC0冷启动分支,通过M_Alarm_RTC_Lost提示用户重新校时

## 附录A: 系统块断电保持界面操作流程

```
1. 打开STEP 7-Micro/WIN SMART
2. 项目树 → 双击"系统块"
3. 系统块对话框 → 左侧导航选择"断电保持"
4. 在"断电保持范围"区域:
   a. 点击"添加范围"按钮
   b. 起始地址: 输入VB0
   c. 元素数: 10 (对应VB0~VB9)
   d. 区域: V区
   e. 点击"确定"
5. 重复步骤4,添加其余6段范围:
   - VB10 / 10 / V区
   - VB200 / 24 / V区
   - VB230 / 60 / V区
   - VB300 / 50 / V区
   - VB350 / 28 / V区
   - VB500 / 100 / V区
6. 切换到M区,添加3段:
   - M0.0 / 1 / M区
   - M10.0 / 1 / M区
   - M11.0 / 1 / M区
7. 点击"确定"保存系统块配置
8. 文件 → 下载 → 勾选"系统块" → 下载
9. PLC断电重启,执行第4章验证流程
```
