## 第1章 测试目的与合格判据总表

### 1.1 测试目的

本测试方案针对 AQUA-EXPO 系统在工厂调试与现场验收阶段需要量化的性能指标,提供可操作的测试方法、记录表格与合格判据,具体目标:

1. **量化PLC扫描周期**:确认 OB1 每周期执行 FC0/FC2/FC3/FC4/FC1 全部逻辑所需时间,保证实时控制响应。
2. **量化Modbus轮询性能**:确认 FC4 通过 CPU 本体 RS485(Port0)轮询注射泵(站号0x01,寄存器41001)与流量计(站号0x02,寄存器0x0009)的请求-响应耗时与稳定性。
3. **量化HMI单站点访问性能**:确认 HMI 通过 S7 协议(或 Modbus TCP,待HMI选型确认)读写 V 区的耗时。
4. **量化8连接并发性能**:确认 1台HMI同时连接8台PLC(192.168.2.101~108)时的并发响应、丢包率、长时稳定性。
5. **量化HMI画面刷新率**:确认主监控/趋势/报警/参数各画面的实际刷新周期与操作响应延迟。
6. **量化内存与资源占用**:确认 PLC 工作内存、断电保持区、HMI 内存与存储的占用率与长时泄漏情况。
7. **量化极限工况表现**:确认最大报警并发、最快换水周期、最长实验时长、参数边界值下的系统行为。

## 第2章 PLC扫描周期测试

### 2.1 测试目的

测量 OB1 主循环每扫描周期的实际执行时间,验证在不同负载条件下扫描周期是否满足实时控制要求。S7-200 SMART CPU ST20 的扫描周期直接影响:
- 阀门/泵 DO 输出的响应延迟(扫描周期越长,DI→DO 响应越慢)
- Modbus 轮询触发频率(FC4 每周期调用,扫描周期决定轮询密度)
- HMI 命令位(V0.x)响应延迟(HMI 写命令后,PLC 下一周期才响应)
- 急停响应(I1.1 触发后,FC2 在同一周期内强制 VW2=99,延迟 ≤ 1 个扫描周期)

### 2.2 测试方法

提供两种方法,优先采用方法A(硬件示波器法,精度高),方法B(STL内嵌计时器法)作为补充/无示波器时使用。

#### 2.2.1 方法A:SM0.6时钟脉冲+Q点翻转示波器法

**原理**:利用 S7-200 SMART 的 SM0.6(2Hz 时钟脉冲,500ms 周期)在 OB1 首尾翻转一个空闲 Q 点,通过示波器测量 Q 点脉冲宽度反映扫描周期。

> **注**:SM0.6 为 2Hz 时钟(2个完整周期/秒),在每个扫描周期开始时其状态被采样。若扫描周期远小于500ms(预期<10ms),则 SM0.6 在多个连续扫描周期内状态不变。因此本方法实际利用 SM0.6 作为"周期开始时刻标记",通过示波器测量 OB1 首次置位 Q 点到末尾复位 Q 点的时间差。

**STL片段示例(测试用,正式下装前移除)**:

```
// 在 OB1 NETWORK 1 之前插入测试NETWORK(占用空闲Q点,如Q1.1)
// 注意: Q0.0~Q8.0 已被DO占用(见变量地址表第三章),Q1.1需确认扩展模块未使用
// 或使用 M 区中间位 + 示波器接 PLC 输出端子(经继电器转换)
NETWORK 0: 扫描周期测试-Q点翻转(测试用,正式版移除)
LD     SM0.0
S      Q1.1, 1                     // 周期开始置位Q1.1

// ... OB1 正常 NETWORK 1~6 ...

NETWORK 7: 扫描周期测试-Q点复位(测试用,正式版移除)
LD     SM0.0
R      Q1.1, 1                     // 周期结束复位Q1.1
```

**测试步骤**:
1. 在 STEP 7-Micro/WIN SMART 中,在 OB1 最前和最后各插入一个 NETWORK,置位/复位 Q1.1(或选定的空闲 M 位经空闲 DO 输出)。
2. 编译下装,PLC 进入 RUN。
3. 示波器探头接 Q1.1 对应的继电器触点输出端(经继电器转换,见变量地址表第三章接线原则)。
4. 设置示波器触发为上升沿,时基 1ms/div,采集 1000 个脉冲。
5. 示波器统计功能读取脉冲宽度(=扫描周期)的最大值、最小值、平均值、P95。
6. 分别在 2.3 节三种负载条件下测试,每次采集 ≥ 1000 个样本。

> **注意事项**:
> - Q1.1 必须是空闲点,ST20本体8DO(Q0.0~Q0.7)+扩展8DO,需确认扩展模块对应地址。建议优先用扩展模块的空闲 DO 点。
> - 继电器转换会引入 1~5ms 跳动误差,若需更高精度,改用方法B。
> - SM0.6 在本方案中不直接作为测量信号(因其周期500ms远大于扫描周期),仅作时基参考。

#### 2.2.2 方法B:STL内嵌计时器累加法

**原理**:利用 S7-200 SMART 的 SMW22(扫描周期字,单位 ms,系统自动更新)直接读取,或用定时器 T32(1ms 时基)在 OB1 首尾读取差值。

**STL片段示例(方法B-1,使用SMW22)**:

```
// SMW22: 上一次扫描周期(ms),系统自动更新
// 在 OB1 末尾 NETWORK 中读取并累加到记录区
NETWORK 8: 扫描周期记录(测试用)
LD     SM0.0
MOVW   SMW22, VW980                // 当前扫描周期(ms)→VW980
// 若需统计最大值:
LDW>   SMW22, VW982                // 与历史最大值比较
MOVW   SMW22, VW982                // 更新最大值
// 若需统计累加次数:
INCW   VW984                       // 采样次数+1
// HMI 可读 VW980(当前)/VW982(最大)/VW984(次数) 实时监控
```

**STL片段示例(方法B-2,使用T32高精度计时)**:

```
// T32: 1ms 时基定时器,可测亚毫秒级
// 在 OB1 首尾读取 T32 当前值差
NETWORK 0: 扫描周期测试-T32启动(测试用)
LD     SM0.0
TON    T32, 32767                  // T32 启动(1ms时基,PT设最大值使其不复位)
MOVW   T32, VW990                  // 周期开始T32值→VW990

// ... OB1 正常 NETWORK 1~6 ...

NETWORK 7: 扫描周期测试-T32结束(测试用)
LD     SM0.0
MOVW   T32, VW992                  // 周期结束T32值→VW992
-I     VW990, VW992                // VW992 = 扫描周期(ms)
// 注意: T32在扫描中持续走,无需复位
```

**测试步骤**:
1. 在 OB1 插入测试 NETWORK,使用 VW980~VW994 作为测试记录区(需在系统块中断电保持区外,避免冲突)。
2. 编译下装,PLC 进入 RUN。
3. 通过 STEP 7 状态图表或 HMI 读取 VW980(当前扫描周期)、VW982(历史最大)、VW984(采样次数)。
4. 让 PLC 连续运行 ≥ 10 分钟(采样次数 ≥ 60000),记录 VW982 最大值。
5. 在不同负载条件下重复测试。

> **精度说明**:SMW22 为系统字,精度 1ms,适合测量 1ms 以上的扫描周期。T32 精度 1ms 但在扫描中持续走,差值法精度同 1ms。两者均能满足本方案 ≤ 10ms 量级的测量需求。

### 2.3 不同负载下测试条件

#### 2.3.1 空载条件

- PLC 程序已下装 RUN,VW2=0(S0 初始化完成态)
- 无 HMI 通讯(HMI 断网或未启动)
- 无 Modbus 通讯(RS485 总线断开或从站不上电)
- 无 DI 触发(所有 I 点保持空闲态)
- 无活动报警(VB300~VB303=0,VW6=0)

#### 2.3.2 S5运行中条件

- VW2=6(S5 实验运行中),V1.7=1(下缸满),VD_S5_Elapsed 累加中
- FC16(S5状态)每周期调用,FC40(节奏纠偏)在 S5 上升沿触发一次
- HMI 通讯在线(HMI 总览页持续轮询)
- Modbus 通讯在线(FC4 每周期调用,2个从站轮询)
- DI 模拟正常实验态:流量开关/液位计保持 S5 应有状态
- 无活动报警

#### 2.3.3 8报警同时活动条件

- VW2=99(S_ERROR),或保持运行态强制报警位
- 通过状态图表强制 8 个报警位同时置位(模拟8套每套1个报警并发场景,本测试在单PLC上模拟8个不同报警位同时活动):
  - V300.0(上缸漫溢)
  - V300.4(急停锁存)
  - V300.5(安全继电器故障)
  - V300.6(节奏严重滞后)
  - V301.0(阀A关后仍有流)
  - V302.0(阀B四态诊断异常)
  - V302.5(阀C四态诊断异常)
  - V303.4(注射泵故障)
- FC3 优先级链遍历全部 8 位,计算 VW6(预期=99,最高级)
- HMI 通讯在线
- Modbus 通讯在线(若从站故障,V303.4 会触发)

## 第3章 Modbus RTU注射泵通讯测试

### 3.1 测试目的

测量 FC4 通过 CPU 本体 RS485(Port0)轮询注射泵(站号0x01)与流量计(站号0x02)的通讯性能,验证:
- 单次轮询请求→响应耗时(报文往返时间)
- 一轮2从站轮询周期(注射泵+流量计各1次)
- 超时阈值(注射泵2000ms/流量计1000ms,见变量地址表11.1节)的正确触发
- 通讯中断后的恢复时间
- 长时连续轮询的稳定性

### 3.2 FC4轮询周期测量

**FC4 实现现状**(见 FC4_ModbusPolling.stl):
- NETWORK 1:每周期调用 MBUS_CTRL 初始化主站(Mode=1 RTU, Baud=9600, Parity=0, Port=0)
- NETWORK 2:用 VW250 作为轮询从站计数器(0=注射泵,1=流量计),基于 MBUS_MSG 的 Done 位顺序执行
- 注射泵:读 41001(0x03E8)→写入 VW4(MB_Pump_Status)
- 流量计:读 40010(0x0009)→写入 VD86(MB_Flow_Total)

> **注**:FC4 当前为骨架,实际 MBUS_MSG 参数(站号/地址/功能码)由 Story 1.1 细化。本测试基于 Story 1.1 完成后的实际代码执行。

**测试方法**:

#### 3.2.1 报文往返时间测量(串口抓包法)

**工具**:RS485 通讯抓包器(USB转RS485+串口监听软件,如串口调试助手/Modbus Poll 自带抓包)

**步骤**:
1. RS485 抓包器并联接入 PLC Port0 与从站之间(T形分接,A/B 双线)。
2. 串口监听软件设置 9600/8/N/1,启用时间戳(毫秒精度)。
3. PLC RUN,FC4 持续轮询。
4. 抓取 ≥ 100 次完整请求-响应报文对。
5. 计算每对的"请求最后一字节发出 → 响应第一字节到达"时间差,即从站响应延迟。
6. 计算每对的"请求第一字节发出 → 响应最后一字节接收"总耗时,即单次轮询耗时。

**报文结构(9600bps 理论耗时)**:
- 注射泵读41001(FC03读1寄存器):请求8字节(地址+功能码+起始地址2+数量2+CRC2)≈ 8.3ms,响应7字节(地址+功能码+字节数+数据2+CRC2)≈ 7.3ms,理论总耗时 ≈ 15.6ms + 从站处理延迟(典型 5~30ms)
- 流量计读0x0009(FC03读2寄存器,32位累计值):请求8字节 ≈ 8.3ms,响应9字节(地址+功能码+字节数+数据4+CRC2)≈ 9.4ms,理论总耗时 ≈ 17.7ms + 从站处理延迟

#### 3.2.2 STL内嵌耗时测量法

**STL片段示例(测试用,在FC4中插入)**:

```
// 在 FC4 NETWORK 2 注射泵轮询分支前后插入T33(1ms时基)读取
// 注: T33为TON类型,1ms时基,需选用未占用定时器
NETWORK 2.1: 注射泵轮询耗时测量(测试用)
LD     SM0.0
LPS
AW=    VW250, 0                    // 当前轮询注射泵
TON    T33, 32767                  // T33启动(1ms时基)
MOVW   T33, VW960                  // 请求发出前T33值→VW960

// ... MBUS_MSG 调用 ...

LD     M10.0                       // MBUS_MSG Done位
MOVW   T33, VW962                  // 响应接收后T33值→VW962
-I     VW960, VW962                // VW962 = 单次轮询耗时(ms)
R      T33, 1                      // 复位T33,准备下次
LPP

// 流量计同理,用 T34 + VW964/VW966
```

#### 3.2.3 连续轮询稳定性测量

**步骤**:
1. PLC RUN,FC4 持续轮询 ≥ 1 小时。

## 第7章 内存与资源占用

### 7.1 PLC工作内存占用测试

**测试目的**:验证 OB1+所有FC编译后占用 CPU ST20 工作内存 ≤ 70%(8.4KB/12KB)。

**测试方法**:
1. STEP 7-Micro/WIN SMART 中,执行"PLC→编译"。
2. 编译输出窗口显示"程序内存使用量 X 字节 / 12288 字节"(CPU ST20 工作内存12KB)。
3. 记录程序代码占用 + 数据占用 + 系统开销。
4. 计算占用率 = 占用量 / 12288 × 100%。

### 7.2 PLC断电保持区占用测试

**测试目的**:验证实际使用的断电保持V区范围 ≤ 配置保持区的80%。

**测试方法**:
1. 在系统块→断电保持中核对配置范围(见变量地址表附录A):VB0~VB9、VB10~VB149、VB150~VB199、VB200~VB229、VB230~VB289、VB300~VB304、VB305~VB349、VB500~VB599、DT10。
2. 统计实际使用地址范围(见变量地址表附录B快速索引)。
3. 计算占用率 = 实际使用字节数 / 配置保持区总字节数 × 100%。

### 7.3 HMI内存与存储占用测试

**测试目的**:验证 HMI 运行时内存占用 ≤ 70%,24小时运行后存储占用 ≤ 80%。

**测试方法**:
1. HMI 工程下装,启动运行。
2. 通过 HMI 组态软件的系统监控功能(若支持)或 HMI 系统设置页查看:
   - 运行时内存占用(MB 或 %)
   - 存储占用(报警记录/历史趋势/工程文件)
3. 24 小时连续运行后再次记录,计算存储增长。
4. 若 HMI 无内置监控,通过组态软件下装时的"工程大小"估算。

### 7.4 长时间运行内存泄漏检测

**测试目的**:验证 PLC 扫描周期与 HMI 内存在 24 小时运行后无显著增长(≤ 10%)。

**测试方法**:
1. PLC 启动后,记录初始扫描周期(用2.2.2节方法B,记录 VW980~VW984)。
2. HMI 启动后,记录初始内存占用。
3. 连续运行 24 小时(S5态循环换水)。
4. 24小时后再次记录扫描周期与 HMI 内存。
5. 计算变化率 = (终值 - 初值) / 初值 × 100%。

**判定准则**:
- PLC 扫描周期变化率 ≤ 10%(无突变尖峰,无明显增长趋势)
- HMI 内存变化率 ≤ 10%(无内存泄漏)

> **PLC 侧说明**:S7-200 SMART 无动态内存分配,扫描周期增长通常源于:
> - 报警日志缓冲区(VB500~VB599)写入量增加(FC3 NETWORK6,见 SAT_FAT TC-08-011)
> - 历史数据累加(VD_T_Rolling、VD_S6_Rolling 等滚动变量)
> 若扫描周期增长 > 10%,需排查上述变量写入逻辑。

## 第8章 极限工况测试

### 8.1 测试目的

验证系统在边界条件下的行为符合设计预期,包括:
- 最大报警并发(8套同时活动报警)
- 最快换水周期(短 VD_CycleSetpoint 设定值)
- 最长实验时长(长 VD_ExperimentTarget 设定值)
- 参数边界值设定(VD 区各参数上下限)

### 8.2 最大报警并发测试

**测试目的**:验证 8 个不同报警位同时置位时,FC3 优先级链正确遍历,VW6 正确反映最高优先级,扫描周期不超标。

**测试方法**:
1. PLC RUN,无活动报警。
2. 通过状态图表一次性强制 8 个报警位同时置位(对应8套每套1个报警并发场景):
   - V300.0(上缸漫溢,代码10)
   - V300.4(急停锁存,代码14)
   - V300.5(安全继电器故障,代码99)
   - V300.6(节奏严重滞后,代码20)
   - V301.0(阀A关后仍有流,代码30)
   - V302.0(阀B四态诊断异常,代码40)
   - V302.5(阀C四态诊断异常,代码45)
   - V303.4(注射泵故障,代码64)
3. 观察下一扫描周期:
   - VW6 应 = 99(最高优先级为安全继电器故障)
   - Q8.0=1(灯光常亮)
   - Q0.7=1(声音报警)
   - FC3 优先级链遍历全部 8 位
4. 同时用 2.2 节方法测量扫描周期,确认 ≤ 10ms(8报警同时活动判据)。
5. 逐个清除报警位(按优先级从低到高),观察 VW6 跟随更新。

### 8.3 最快换水周期测试

**测试目的**:验证在 VD_CycleSetpoint 设定为理论下限值时,S1~S6 流程能完整执行无 S_ERROR。

**理论下限值计算**:
- VD_CycleSetpoint 下限 ≈ VD_T_Rolling(S1+S2+S3+S3.5 标称总时长) + VD_S6_Rolling(S6 排水时长)
- 默认参数:VD_PreMixTime=120s + VD_RestTime=60s + S1估算60s + S3估算30s = 270s + VD_S6_Default 估算30s = 300s ≈ 5min
- 即 VD_CycleSetpoint 下限约为 5min(默认参数下),实际下限需现场实测核定。

**测试方法**:
1. 将 VD_CycleSetpoint 设为下限值(待确认,默认参数下建议 5min)。
2. 启动实验,VW2=0→S1→S2→S3→S3.5→S4→S5→S6→S5 循环。
3. 观察 3 个完整循环,确认:
   - 每轮 S1~S6 状态切换正常,无 S_ERROR
   - VD_S5_Elapsed 在 S5 态累加,达到 VD_CycleSetpoint×60 后转 S6
   - VD_T_Rolling、VD_S6_Rolling 滚动更新
   - DT10 每轮更新
   - FC40 节奏纠偏不触发人工介入报警(V300.6=0),或仅触发 V300.7 滞后提示(可接受)
4. 若触发 V300.6(严重滞后人工介入),说明 VD_CycleSetpoint 设定过短,需上调。

### 8.4 最长实验时长测试

**测试目的**:验证 VD_ExperimentDuration_Accum 累加至 VD_ExperimentTarget 后正确转 S7,且长时间运行无累计误差。

**测试方法**:
1. 将 VD_ExperimentTarget 设为较短测试值(如 30min,缩短测试时长)。
2. 启动实验,VW2 进入 S5 循环。
3. 持续运行,观察 VD_ExperimentDuration_Accum 累加(仅下缸满期间累加,见设计文档第十章)。
4. 当 VD_ExperimentDuration_Accum ≥ VD_ExperimentTarget 时,确认:
   - VW2 由 6 转为 8(S7 实验结束)
   - QB0=0(所有输出停)
   - VD96 锁定最终值
   - HMI 提示"实验时长已达标,实验结束"
5. 需 HMI 确认 CMD_Start(V0.0)后才能回 S0(不自动重启)。
6. 累计误差验证:对比 VD_ExperimentDuration_Accum 与秒表实测下缸满总时长,误差 ≤ 1%(以 PLC RTC 为基准)。
