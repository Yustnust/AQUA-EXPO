## 二、PLC程序备份

8套PLC程序完全相同(变量地址表§1.1、PLC设计文档§12.7),区别仅在IP地址(192.168.2.101~108)。备份策略按"1份源工程+8份含IP差异的现场实例"管理。

### 2.1 STEP 7-Micro/WIN SMART 上传(从PLC读项目)

**用途**: 将运行中PLC的程序块/数据块/系统块读取到PC,生成可编辑工程文件。

**前置条件**:
- STEP 7-Micro/WIN SMART V2.0及以上已安装于调试PC
- PC与目标PLC同网段(192.168.2.x,x≠101~108),网线物理连通
- PLC处于RUN或STOP状态均可,推荐RUN状态上传以获取最新运行参数
- 已通知操作员此PLC即将进行上传操作(无需停机,但建议在停机时执行)

**操作步骤**:
1. 打开 STEP 7-Micro/WIN SMART
2. 菜单 `通信` → 弹出"通信"对话框 → `设置PG/PC接口` → 选择 `TCP/IP`(网卡) → `查找CPU`
3. 在搜索结果中双击目标PLC(显示IP 192.168.2.10X,对应单元号X)
4. 菜单 `PLC` → `上传` → 弹出"上传"对话框
5. 勾选上传内容:
   - ☑ 程序块(主程序/子程序/中断程序)
   - ☑ 数据块
   - ☑ 系统块(含IP/断电保持配置,关键!)
   - ☐ 菜单(可选,含HMI注释)
6. 点击 `上传`,等待进度条完成,显示"上传成功"
7. 在工程中 `文件` → `另存为` → 按本方案§2.3命名规范保存为 `.mwp` 文件
8. 关闭工程前 `PLC` → `信息` → 记录 PLC 程序校验和(Checksum)、固件版本、最后修改时间

**验证方法**:
- 打开保存的 .mwp,`PLC` → `编译`,应显示 `0 error, 0 warning`
- `视图` → `符号表` 检查符号(如 `VD_C_Set`、`M_Alarm_Overflow_A`)是否完整
- `视图` → `数据块` 检查 VD10~VD140 等默认值是否与变量表§6一致
- `视图` → `系统块` → `断电保持` 检查配置范围是否与变量表附录A一致

### 2.2 STEP 7-Micro/WIN SMART 下载(写项目到PLC)

**用途**: 将PC上的工程文件写入PLC,用于程序更新或恢复。

**前置条件**:
- 已完成维护手册§12.1安全确认:急停按下、220V动力回路断路器OFF、挂牌
- 仅24VDC控制回路可带电,220V必须断电
- 已备份当前PLC运行程序(按§2.1上传并存档),作为回滚依据
- 已记录当前PLC的IP地址(下载系统块会覆盖IP,需确保系统块中IP与目标PLC一致)

**操作步骤**:
1. 打开 STEP 7-Micro/WIN SMART,打开目标 .mwp 工程文件
2. `PLC` → `编译`,确认 `0 error, 0 warning`
3. `视图` → `系统块` → `通信接口` 确认 IP=192.168.2.10X 与目标PLC单元号一致
4. `视图` → `系统块` → `断电保持` 确认范围与变量表附录A一致(VB0~VB9/VB10~VB149/VB150~VB199/VB200~VB229/VB230~VB289/VB300~VB303/VB304/VB305~VB349/VB500~VB599,DT10)
5. 菜单 `PLC` → `下载` → 弹出"下载"对话框
6. 勾选下载内容:
   - ☑ 程序块
   - ☑ 数据块
   - ☑ 系统块
   - ☑ 强制值(如有强制表则勾选,通常不勾)
7. 点击 `下载`,PLC自动切换至STOP模式,等待下载完成
8. 下载完成后弹出"是否切换至RUN模式?" → 选 `是`
9. 验证 PLC RUN灯常绿、ERR灯灭
10. `PLC` → `信息` → 确认扫描周期 <10ms、无错误

**验证方法**:
- 按维护手册§5.1执行断电保持测试(断电30秒再上电,V304.0=1,数据保持)
- 按维护手册§3.1巡检项3.1确认 PLC RUN灯/EM指示灯/HMI通讯正常
- 按维护手册§5.3确认485通讯(查V303.4注射泵报警状态)正常

### 2.5 8台PLC版本一致性核对方法

由于8套PLC程序完全相同,需定期核对8台PLC当前运行的程序版本是否一致,防止"局部更新导致版本漂移"。

**核对方法(每半年1次,与维护手册§7.3全量备份同步执行)**:

1. 对8台PLC逐台执行§2.1上传,生成8份 .mwp
2. 在 STEP 7-Micro/WIN SMART 中,`PLC` → `信息` → 记录每台的:
   - 程序校验和(Checksum,16进制,如 `0x1A2B`)
   - 程序块大小(字节)
   - 数据块大小
   - 固件版本
   - 系统块版本
3. 将8台记录填入下表,核对全部字段一致:

| 单元号 | IP地址 | 程序校验和 | 程序块大小 | 数据块大小 | 固件版本 | 系统块IP | 一致性 |
|---|---|---|---|---|---|---|---|
| U01 | 192.168.2.101 | 0x____ | ___B | ___B | V__ | 192.168.2.101 | □一致 |
| U02 | 192.168.2.102 | 0x____ | ___B | ___B | V__ | 192.168.2.102 | □一致 |
| ... | ... | ... | ... | ... | ... | ... | ... |
| U08 | 192.168.2.108 | 0x____ | ___B | ___B | V__ | 192.168.2.108 | □一致 |

**判定标准**:
- 8台程序校验和必须一致 → 程序逻辑完全相同
- 程序块大小、数据块大小必须一致 → 防止"只下了部分块"
- 固件版本一致 → 防止跨版本行为差异
- 系统块IP各自不同 → 这是预期差异(每台IP不同),不视为不一致

**不一致处理**:
- 若某台校验和与其余7台不同 → 用主源工程按§2.2重新下装该台(注意系统块IP保持原值)
- 若多台不一致且无主源工程 → 警报升级,启动第七章§7.5整机灾难恢复流程

## 三、PLC参数备份

PLC断电保持V区参数是实验运行的核心数据,丢失将导致实验数据失连续、需重新录入30余项设定值。CPU ST20超级电容保持典型7天/最小6天,长期断电(>7天)将丢失V区数据(变量表§10)。本节定义参数的备份方法、字段格式与恢复步骤。

### 3.1 备份对象(参数范围)

按变量表附录A断电保持区配置,本方案需备份以下V区段:

| 地址段 | 内容 | 字段数 | 类型 |
|---|---|---|---|
| VB0~VB9 | 系统命令位/状态位/状态机VW2/泵状态VW4/报警码VW6/轮次VW8 | 10字节 | BOOL/INT混合 |
| VB10~VB149 | HMI设定参数VD10~VD66 + 实测值VD70~VD102 + 纠偏VD104~VD140 | 140字节 | REAL为主 |
| VB150~VB199 | 纠偏中间变量VD150~VD190 + 断电恢复中间量VD194/VW198 | 50字节 | REAL/INT混合 |
| VB200~VB229 | Modbus寄存器映射缓冲VW200~VW228 | 30字节 | INT/WORD |
| VB230~VB289 | 阀门诊断子状态/PT转换值VW230~VW289 | 60字节 | INT/WORD |
| VB300~VB303 | 报警字VB300~VB303(32位按位编码) | 4字节 | DWORD |
| VB304 | M_InitDone初始化完成标志(V304.0) | 1字节 | BOOL |
| VB305~VB349 | 阀门诊断数据VD308~VD344 | 45字节 | REAL/DWORD |
| VB500~VB599 | 报警日志缓冲区(FC3 NETWORK6) | 100字节 | 结构化 |
| DT10 | DT_TankB_FullTime下缸满时间戳 | 8字节 | DT |

**重点保护参数**(必备份,丢失影响最大):
- VD10~VD66 设定值(浓度/时间周期/超时保护)→ 实验配方参数
- VD132~VD140 注射泵速度参数 → 与泵硬件相关,需重新核实
- VW8 实验轮次计数 → 实验进度
- VB300~VB303 报警字 → 当前未确认报警状态
- VW2 状态机 → 当前流程状态
- DT10 下缸满时间戳 → 换水周期计算基准

### 3.3 备份方法B:Modbus读取V区导出CSV(自动化,可定时)

**前提**: PLC侧已配置 Modbus TCP Server(若选用 Modbus TCP方案,见MCGS组态实施指南附录B:OB1调用MBUS_SERVER,HoldStart=VB0,MaxHold=200映射VB0~VB399,端口502)。若项目选用S7协议,本方法不适用,改用方法A或C。

**操作步骤**:
1. 在工控机PC上使用 Modbus Poll 工具(Modbus调试通用工具),或编写Python脚本(基于 `pymodbus` 库)
2. 连接目标PLC:IP=192.168.2.10X,端口=502,单元号=1
3. 读取保持寄存器40001~400200(对应VB0~VB399,共200字=400字节)
4. 导出为CSV,按地址段切分(便于人工核对)

**Python脚本示例(仅供参考,实际部署需调试)**:
```python
from pymodbus.client import ModbusTcpClient
import csv, datetime

UNIT_IPS = [f"192.168.2.{i}" for i in range(101, 109)]
PORT = 502
START_REG = 1   # 40001
NUM_REGS = 200  # VB0~VB399
VARIABLE_MAP = {
    # (寄存器偏移, 长度字, 符号, 类型, 单位)
    (1, 1, "VW2_状态机", "INT", "—"),
    (3, 1, "VW4_泵状态码", "INT", "—"),
    (4, 1, "VW6_报警码", "INT", "—"),
    (5, 1, "VW8_实验轮次", "INT", "次"),
    (6, 2, "VD10_目标浓度设定", "REAL", "%"),
    (8, 2, "VD14_母液浓度", "REAL", "%"),
    # ... 完整映射按变量表填写
    (151, 2, "VB300_报警字1", "DWORD", "位"),
    (152, 2, "VB302_报警字3", "DWORD", "位"),
}

for idx, ip in enumerate(UNIT_IPS, 1):
    client = ModbusTcpClient(ip, port=PORT)
    if not client.connect():
        print(f"U{idx:02d} ({ip}) 连接失败")
        continue
    rr = client.read_holding_registers(START_REG, NUM_REGS, slave=1)
    if rr.isError():
        print(f"U{idx:02d} 读取失败: {rr}")
        client.close()
        continue
    regs = rr.registers
    today = datetime.date.today().isoformat().replace("-", "")
    fname = f"AQUA-EXPO_PLC_U{idx:02d}_Param_{today}.csv"
    with open(fname, "w", newline="", encoding="utf-8-sig") as f:
        w = csv.writer(f)
        w.writerow(["单元号","Modbus寄存器","V区地址","符号","类型","值(原始)","值(解析)","单位"])
        for offset, length, symbol, dtype, unit in VARIABLE_MAP.items():
            reg_vals = regs[offset:offset+length]
            raw = " ".join(f"0x{v:04X}" for v in reg_vals)
            # REAL解析(32位浮点): 高字在前
            if dtype == "REAL" and length == 2:
                import struct
                val = struct.unpack(">f", struct.pack(">HH", reg_vals[0], reg_vals[1]))[0]
                parsed = f"{val:.4f}"
            elif dtype == "INT":
                val = reg_vals[0] if reg_vals[0] < 0x8000 else reg_vals[0] - 0x10000
                parsed = str(val)
            else:
                parsed = raw
            w.writerow([f"U{idx:02d}", f"4{START_REG+offset:05d}", 
                       f"V{offset*2}~", symbol, dtype, raw, parsed, unit])
    client.close()
    print(f"U{idx:02d} 备份完成: {fname}")
```

**注意**:
- Modbus 保持寄存器按字(WORD)对齐,VD双字需读2个连续寄存器,REAL解析需按大端序(高字在前)
- DT10 时间戳不在 Modbus 保持寄存器映射范围(V区不含DT),需通过STEP 7方法C单独备份
- 实际部署前需在测试环境验证寄存器映射地址正确性

### 3.5 参数恢复(下装)步骤

**前置条件**:
- 已确认待恢复PLC的IP与目标单元号对应
- 已备份当前PLC参数(防止恢复失败回滚,按§3.2/3.3/3.4任一方法备份当前值)
- 已通知操作员此PLC即将进行参数恢复操作
- PLC处于STOP或S0初始化态(避免运行中改参数引发状态机异常)

**操作步骤(以STEP 7状态表写入为例)**:
1. STEP 7 连接目标PLC
2. `视图` → `状态表` → 打开备份的CSV文件(或将CSV内容粘贴至状态表)
3. 在"新值"列填入待恢复的参数值(从备份CSV复制)
4. `调试` → `写入全部` → PLC将"新值"写入V区
5. `调试` → `读取全部` → 验证"当前值"列已更新为新值
6. **关键参数人工复核**:VD10(目标浓度)/VD14(母液浓度)/VD18(步分辨率)/VD132~140(泵速) → 与实验配方核对一致
7. **报警字复核**:VB300~VB303应为0(无未确认报警)或与备份一致;若有未确认报警,确认报警根本原因已消除后再清除
8. **状态机复核**:VW2若需恢复至运行态,按§3.6回滚说明评估风险(通常恢复至S0后由操作员重新启动实验)

### 3.6 回滚方案

| 回滚场景 | 触发条件 | 操作 |
|---|---|---|
| 参数写入失败 | STEP7提示写入错误 | 检查PLC连接/STOP状态;重试;若仍失败,断电重启PLC后重试 |
| 参数写入后状态机异常 | VW2=99(S_ERROR)且报警码非预期 | 立即用"恢复前快照"按§3.5步骤还原原参数;若仍异常,按§7.2整机程序恢复 |
| 实验中断需继续 | VW8轮次与断电前一致,DT10有效 | 状态机恢复至断电前态(VW2=断电前值);按PLC设计文档§10断电恢复逻辑验证 |
| 实验需重新开始 | 参数恢复后无法继续原实验 | VW2强制写0(S0),VW8清零,DT10清零;按SOP重新启动实验 |
| 参数恢复后PLC死机 | ERR灯亮,无法通讯 | 断电重启PLC;若仍死机,按§7.1 PLC程序损坏恢复流程 |

**回滚验证清单**:
- [ ] 当前参数与恢复前快照逐项对比(允许DT10/VD96实测值差异)
- [ ] 状态机VW2回到预期态
- [ ] 报警字VB300~VB303符合预期(无新增报警)
- [ ] HMI画面1~7显示与PLC实际状态一致
- [ ] 注射泵/流量计485通讯正常(V303.4=0,VW4合理)

- 异地副本与现场物理距离≥500米(或不同建筑物),防止火灾/水浸

### 6.2 3-2-1备份原则

## 七、恢复操作SOP

### 7.1 场景A:PLC程序损坏恢复(单台)

**故障现象**: PLC ERR灯亮、无法通讯、程序丢失、固件损坏等。

**前置条件**:
- 备份文件可用:主源工程 `AQUA-EXPO_PLC_Main_V{X.Y.Z}_{YYYYMMDD}.mwp`
- 备份文件可用:目标单元实例 `AQUA-EXPO_PLC_U{NN}_V{X.Y.Z}_{YYYYMMDD}.mwp`(含正确IP)
- 已确认硬件无物理损坏(电源/网线/扩展模块正常)
- 维护手册§12.1安全规程已执行(急停按下、220V断电、挂牌)

**操作步骤**:
1. STEP 7-Micro/WIN SMART 连接目标PLC(§2.1步骤1~3)
2. `PLC` → `信息` → 读取故障代码(若可通讯);若完全不可通讯,跳至步骤5
3. `PLC` → `清除` → 选择"程序块+数据块+系统块"→ 清空PLC(慎用,此操作不可逆)
4. 若不可通讯:断电重启PLC,长按RUN/STOP按钮进入STOP模式,再尝试通讯
5. 打开单元实例 .mwp 文件(§2.3命名规范),含正确的IP 192.168.2.10X
6. 按§2.2执行下载(系统块+程序块+数据块)
7. 下载完成后,`PLC` → `切换至RUN` → RUN灯常绿、ERR灯灭
8. 按§3.5恢复参数(从最近一次参数备份CSV恢复)
9. `PLC` → `设置RTC` → 同步PC当前时间(若RTC丢失)
10. 验证(见下)

**验证方法**:
- STEP 7 `PLC` → `信息`:扫描周期<10ms、无错误、程序校验和与备份记录一致
- 按维护手册§5.1执行断电保持测试:断电30秒再上电,V304.0=1,数据保持
- 按维护手册§5.3执行Modbus通讯测试:注射泵VW4、流量计VD86通讯正常
- HMI画面1总览页:该单元卡片恢复"在线"彩色显示

**回滚方案**:
- 若下载后PLC仍ERR:断电→检查扩展模块总线连接器→重新下装→仍ERR则怀疑硬件故障,联系PLC技术支持
- 若参数恢复后状态机异常:按§3.6回滚至S0,重新启动实验
- 若通讯仍异常:检查网线/IP/防火墙,排除网络问题

### 7.2 场景B:PLC参数丢失恢复(单台)

**故障现象**: 长期断电(>7天超级电容保持期)后PLC上电,V区参数恢复为默认值,实验数据失连续。

**前置条件**:
- 备份文件可用:最近一次参数备份CSV(按§3.2/3.3/3.4任一方法)
- PLC程序本体完好(RUN灯常绿、ERR灯灭)
- 已确认报警根本原因(如断电原因已排除)

**操作步骤**:
1. STEP 7 连接目标PLC
2. `视图` → `状态表` → 读取当前V区值,确认丢失(对比备份CSV)
3. 按§3.5执行参数恢复(从备份CSV填入新值→写入全部)
4. 关键参数人工复核(§3.5步骤6):VD10/VD14/VD18/VD132~140
5. **报警字处理**:VB300~VB303若为0则无未确认报警;若非0,逐位检查:
   - V300.5(继电器故障):最高级,需人工现场检修安全继电器后才能清除
   - V300.4(急停锁存):需现场系统复位按钮I0.3清除
   - V303.5(RTC丢失):若PLC RTC时间早于DT10,触发此报警,需先校时再清除
6. **状态机处理**:
   - 若实验未启动或需重新开始:VW2强制写0(S0),VW8清零,DT10清零,按SOP重启实验
   - 若实验进行中且DT10有效:VW2恢复至断电前态(从备份),按PLC设计文档§10断电恢复逻辑验证(下缸=满期间累加VD96)
7. `PLC` → `设置RTC` → 同步PC当前时间(若RTC异常)
8. 验证(见下)

**验证方法**:
- STEP 7 状态表:VD10~VD66设定值与备份CSV逐项一致
- HMI画面4参数设置页:显示值与设定值一致
- HMI画面1总览页:VW2状态机显示正确、VW6报警码=0(或预期值)、VW8轮次正确
- HMI画面6趋势曲线页:VD96实验时长累加值连续(若实验继续)

**回滚方案**:
- 按§3.6回滚方案执行
- 若实验数据无法连续:接受实验中断,VW2写0重新开始,记录为"参数丢失致实验中断"事件

### 7.3 场景C:HMI组态损坏恢复

**故障现象**: HMI黑屏/卡死/组态丢失/无法启动/触摸失效等。注意:HMI故障不影响PLC实时控制(PLC设计文档§12.5)。

**前置条件**:
- 备份文件可用:`AQUA-EXPO_HMI_V{X.Y}_{YYYYMMDD}.mcp` 及配方/报警/用户配置备份
- HMI硬件无物理损坏(电源/屏幕正常)
- McgsPro组态PC可用

**操作步骤**:
1. 在组态PC上打开McgsPro,打开备份的 .mcp 工程文件
2. `工程` → `检查` → 编译验证无错误(若有错误,按组态实施指南§11 checklist排查)
3. 组态PC通过USB或网线连接HMI本体(McgsPro下载方式取决于HMI型号)
4. `工具` → `下载` → 选择"全部"(工程/配方/报警/用户/脚本)
5. 等待下载完成(728变量+8画面+32报警+脚本,预计10~30分钟)
6. HMI本体重启,验证启动正常
7. 恢复用户密码:每个用户名重新设置密码(因导出CSV不含明文密码)
8. 恢复单元使能标志:在画面8系统设置页,勾选当前已接入的单元(首期1号=TRUE,2~8号=FALSE)
9. 恢复RTC:HMI开机时间 → 同步至8台PLC(组态实施指南§9脚本)
10. 验证(见下)

**验证方法**:
- HMI启动正常,无报错弹窗
- 画面1总览页:8单元卡片显示正常(已使能+在线→彩色;未使能→灰色)
- 画面4参数设置页:VD10~VD66显示值与PLC实际一致(需PLC未丢失参数)
- 画面5报警日志页:当前报警VW6显示正确
- 画面7趋势曲线页:7条曲线显示正常
- L1/L2/L3三级用户登录测试通过

**回滚方案**:
- 若新工程下载后HMI异常:重新下载"恢复前快照" `AQUA-EXPO_HMI_PreDownload_{YYYYMMDD}.mcp`
- 若HMI本体硬件故障(屏幕破裂/主板损坏):按维护手册§9.5返修或更换备件,组态重新下装
- HMI恢复期间,PLC按本地逻辑继续运行(PLC设计文档§12.5),急停/系统复位/消音按钮物理操作不受影响

### 7.4 场景D:HMI历史数据恢复

**故障现象**: HMI本体历史数据丢失(硬盘损坏/循环覆盖误删/McgsPro异常),需从备份恢复查询能力。

**前置条件**:
- 备份文件可用:NAS或U盘上的月度/年度历史数据CSV
- HMI本体已恢复运行(场景C已完成)
- 历史数据为查询/追溯用途,不直接影响实时控制

**操作步骤**:
1. 在工控机PC或HMI本体上,从NAS/U盘拷贝目标月份CSV至本地查询目录
2. 用Excel或SQLite工具打开CSV(若McgsPro支持导入历史数据,可通过组态实施指南§10脚本反向导入)
3. 按需筛选:
   - 按时间范围:`时间戳 BETWEEN 'YYYY-MM-DD' AND 'YYYY-MM-DD'`
   - 按单元号:`单元号 = N`
   - 按报警类型:`报警码 IN (10,11,12,...)`
4. 导出分析报告(可选):按维护需求生成报警统计/趋势分析报告

**验证方法**:
- CSV文件完整可读(§5.4完整性验证)
- 关键时间点的数据存在(如当月发生的最高级报警记录)
- 与HMI本体当前实时数据衔接(无大段时间断档)

**回滚方案**:
- 历史数据恢复为只读查询用途,不写入HMI本体(防止污染当前数据)
- 若需恢复至HMI本体供画面7趋势曲线显示:仅在McgsPro明确支持时执行,且先备份HMI本体当前数据
- 数据丢失不可恢复时,记录为"HMI历史数据丢失致追溯中断"事件,在审计日志中标注

### 7.5 场景E:整机灾难恢复(8台PLC+HMI全失)

**故障现象**: 实验室火灾/水浸/盗窃/大规模雷击等导致8台PLC与HMI全部损坏或数据全失。

**前置条件**:
- 异地备份可用:外置硬盘或异地NAS含最近半年全量备份
- 备件可用:1台PLC备件(CPU ST20+EM DT16/DR16)、1台HMI备件(维护手册§10.1)
- 硬件现场已恢复供电与网络

**操作步骤(按优先级)**:

**优先级1:恢复1号单元最小可运行配置(目标:24小时内恢复单单元实验能力)**

1. 取1台PLC备件,按维护手册§12.1安装到1号控制柜
2. 按IO现场接线核对表v1.0完成20DI+9DO接线
3. 接入485总线(注射泵+流量计)
4. STEP 7 设置IP=192.168.2.101(系统块配置)
5. 按变量表附录A配置断电保持区(系统块→断电保持)
6. 打开主源工程 `AQUA-EXPO_PLC_Main_V{X.Y.Z}_{YYYYMMDD}.mwp` → 下载(§2.2)
7. 按§3.5从参数备份CSV恢复1号单元参数(VD10~VD140、VW8等)
8. 校时:`PLC` → `设置RTC` → 同步PC当前时间
9. 取1台HMI备件,按组态实施指南§1~§11完成MCGS工程下装(`AQUA-EXPO_HMI_V{X.Y}_{YYYYMMDD}.mcp`)
10. 恢复单元使能:画面8勾选1号=TRUE,其余=FALSE
11. 按PLC首次下装与上电调试Checklist v1.0执行5天调试流程(到货→安装→IO打点→单机功能→联动调试)
12. 1号单元SAT验收通过 → 最小可运行配置恢复完成

**优先级2:恢复其余7台PLC(目标:1~2周内恢复全系统)**

13. 重复步骤1~8,将IP分别配置为192.168.2.102~108(对应2~8号单元)
14. 每台PLC按各自参数备份CSV恢复参数(8套参数可能略有差异,如VD18步分辨率因进样器规格不同)
15. HMI画面8勾选2~8号单元使能=TRUE(随接入进度逐个勾选)

**优先级3:恢复历史数据追溯能力**

16. 从异地备份恢复历史数据CSV至NAS
17. 在HMI本体/工控机查询历史数据(场景D)

**验证方法**:
- 8台PLC程序校验和与主源工程记录一致(§2.5)
- 8台PLC IP分别为192.168.2.101~108,均能ping通
- HMI画面1总览页8单元全部"在线+彩色"
- 按SAT_FAT验收测试用例v1.0对1号单元执行101用例验收
- 急停/系统复位/消音物理按钮测试通过(每台独立)

**回滚方案**:
- 整机灾难恢复无回滚可能,按"先恢复单单元、再扩展"策略降低风险
- 若某台PLC恢复失败,跳过该单元继续恢复其余7台(单机故障隔离原则,PLC设计文档§12.5)
- 恢复过程中若备件耗尽,记录缺失单元,优先保障实验关键单元

### 8.4 备份失败处理

| 失败现象 | 可能原因 | 处理措施 |
|---|---|---|
| STEP 7 上载失败 | PLC通讯异常/STEP7版本不兼容 | 检查网线/IP/防火墙;升级STEP7至V2.5+;若仍失败联系PLC技术支持 |
| Modbus 读取超时 | PLC未配置Modbus TCP Server/端口被占用 | 改用方法A或C;检查MBUS_SERVER配置;检查端口502占用 |
| HMI U盘导出失败 | U盘格式不支持/容量不足/HMI脚本异常 | 格式化U盘为FAT32;更换U盘;检查McgsPro导出脚本日志 |
| NAS同步失败 | 网络中断/权限不足/NAS磁盘满 | 检查网络;重新映射网络驱动器;清理NAS旧文件;联系IT |
| 备份文件损坏 | 存储介质故障/病毒 | 用第二份副本恢复;杀毒;更换介质重备份 |
| HMI工程编译错误 | 组态文件版本不兼容/变量丢失 | 用上一版本 .mcp 恢复;重新导入变量CSV模板 |
| 恢复后PLC异常 | 参数恢复错误/系统块配置丢失 | 按§3.6回滚;重新下载系统块;联系PLC技术支持 |

**备份失败上报流程**:
1. 操作员发现 → 立即通知维护工程师
2. 维护工程师30分钟内响应 → 1小时内修复或上报
3. 若24小时内无法修复 → 上报项目经理,启动应急预案(§9)
4. 备份失败期间 → 严禁对PLC/HMI进行程序变更或参数修改(防止变更无备份可回滚)

## 九、应急预案

### 9.1 备份不可用时的应急处置

**场景**: 需恢复时发现备份文件损坏/丢失/版本不匹配。

**处置原则**: 优先保障PLC安全运行,牺牲历史数据完整性,后续逐步重建。

| 备份失效场景 | 应急处置 |
|---|---|
| PLC源工程损坏 | 用8台PLC中任一台上传获取运行程序(若PLC本体完好);若8台PLC均损坏,联系原PLC工程师从邮件/版本库找回源工程;启动现场重编程(预计1~2周) |
| PLC参数备份损坏 | 用变量表§6的"默认值"列作为初始参数;按现场实际浓度/时间需求重新录入;实验需重新开始(VW8清零) |
| HMI工程损坏 | 用组态实施指南重新组态(预计1~3天);PLC可独立运行,无HMI期间通过物理按钮操作 |
| 历史数据损坏 | 接受数据丢失;从HMI本体当前数据开始重新积累;不影响实时控制 |
| 异地副本损坏 | 检查NAS副本;若NAS也损坏,从工控机硬盘副本恢复;启动数据重建(§9.3) |

### 9.2 数据重建优先级

整机灾难后,按以下优先级重建数据(对应§7.5优先级):

| 优先级 | 重建对象 | 重建来源 | 预计耗时 |
|---|---|---|---|
| P0(立即) | PLC运行程序(主源工程) | 异地备份/邮件/版本库 | 2小时(若有备份)~2周(若无) |
| P1(24h内) | 1号单元PLC参数(默认值) | 变量表§6默认值列 | 1小时 |
| P1(24h内) | HMI最小可运行组态(仅1号单元) | 组态实施指南 | 1天 |
| P2(1周内) | 8台PLC参数(逐台录入) | 变量表§6 + 现场实测 | 1~2天 |
| P2(1周内) | HMI完整组态(8单元) | 组态实施指南 | 1~3天 |
| P3(1月内) | 历史数据(从当前开始重新积累) | HMI本体实时记录 | 持续累积 |
| P4(长期) | 历史数据追溯(若异地备份可恢复) | 异地备份恢复查询 | 按需 |

### 9.3 最小可运行配置

整机灾难时,以下为"最小可运行配置",保障核心实验能力:

| 配置项 | 最小配置 | 说明 |
|---|---|---|
| PLC | 1台CPU ST20 + EM DT16/DR16 | 仅1号单元运行 |
| PLC程序 | 主源工程 .mwp | 8台相同,1份即可 |
| PLC参数 | 变量表§6默认值 | 浓度5%/周期30min/实验480min等 |
| HMI | 1台昆仑通态MCGS 12寸 | 仅组态1号单元(画面1~7) |
| 单元使能 | 仅1号=TRUE | 其余7号=FALSE |
| 网络 | 1台非网管交换机 + 2根网线 | PLC#1 + HMI |
| 485从站 | 1台注射泵 + 1台流量计 | 仅1号单元的2个从站 |
| 急停/复位/消音按钮 | 各1套 | 1号单元就地面板 |
| 安全继电器 | 1个(强制导向型220V) | 1号单元急停回路 |

**最小可运行配置能力**:
- 1号单元完整执行S0~S7实验流程
- 急停/系统复位物理回路完整
- HMI显示1号单元实时状态、报警、参数、趋势
- 不支持2~8号单元(灰显"未接入")
- 历史数据从恢复时刻开始记录

**升级路径**:
- 备件到位 → 接入第2台PLC → HMI画面8勾选2号使能 → 重复至8台全接入
- 全部接入后按§7.5验证清单与SAT_FAT验收测试用例执行全系统验收
