## 一、审查背景与方法

### 1.1 审查背景

本次审查聚焦于一个核心问题:**`feature/v2.2-doc-revisions` 分支的代码是否实现了 v2.2 流程重构的设计意图?**

v2.2 重构涉及重大架构调整:
1. 取消独立预循环,S2 合并搅拌+加药
2. 上下缸并行(双状态机 VW2+VW304)
3. 24h 换水次数硬约束(FC40 双倒计时器)
4. 新建 FC1A_State_S2_MixDose
5. 多个 FC 函数的逻辑重构(详见 §5 改动清单)

如果这些**设计意图没有在代码中正确实现**,意味着:
- 代码层和设计层"对不上"
- 系统实际上并未按设计意图运行
- 必须尽快修复或更新设计文档

### 1.2 审查方法

1. **逐章通读设计文档** v10.3(§3-§10.5)+ v2.2 重构方案(§1-§5)
2. **对应代码逐 FC 审查**:
   - FC0/FC1/FC1A/FC2/FC3/FC4/FC10/FC11/FC15/FC16/FC17/FC18/FC19/FC20/FC21/FC22/FC30/FC31/FC32/FC40
   - OB1_MAIN/SBR25/SBR26
3. **关键变量验证**:
   - 双状态机:VW2(下缸)+VW304(上缸)
   - 倒计时器:T46/T48
   - 触发位:M16.0/M16.1/M16.2
   - 24h 约束:VD414
4. **对照设计-实现差异**,对每条设计意图建立实现状态标签

### 1.3 标注方法

| 标签 | 含义 |
|---|---|
| ✅ 已实现 | 代码完全符合设计意图 |
| ⚠️ 部分实现 | 代码有相关逻辑,但存在关键缺陷或边界情况未处理 |
| ❌ 未实现 | 代码完全没有相应逻辑,或因 BUG 导致逻辑失效 |
| ➖ 不适用 | 设计意图在 PLC 代码侧无需实现(HMI 侧等) |

## 三、各 FC 设计意图实现情况详解

### 3.1 FC40_RhythmCorrection 双倒计时器 ❌

**设计意图**(主设计文档 §7):
- T46/T48 双计时器管理上缸配液节奏
- 当活动计时器 PV ≤ 下一阶段所需时间时,触发下一阶段

**代码位置**:`plc/stl/FC40_RhythmCorrection.stl`

**实现情况**:

| 设计功能 | 实现状态 | BUG 编号 |
|---|---|---|
| T46/T48 双计时器结构 | ✅ | - |
| M16.0 = NOT M16.0 切换活动计时器 | ⚠️ (需要 FC15 触发) | - |
| T46/T48 PT = 6000(10 分钟) | ✅ | - |
| T46/T48 启动逻辑(L57-62) | ❌ 栈消耗失效 | - |
| S6 触发逻辑(L74-93) | ❌ 栈消耗失效 | - |
| 下一轮 S1 触发逻辑(L96-117) | ❌ 栈消耗失效 | - |
| 周期超时报警 V303.6(L56/L136) | ✅ | - |

**关键 P0 BUG**:
1. **L57-62 启动 T46/T48**:
   ```stl
   LD SM0.0              // 栈深 1
   LPS                   // 栈深 2 (LPS 复制栈顶)
   A M16.0               // 栈深 2
   TON T46, 6000         // T46 看栈顶使能(L57)
   LPP                   // 弹栈 → 栈深 1
   AN M16.0              // 栈深 1
   TON T48, 6000         // T48 看栈顶使能(L62)
   ```
   - 这部分逻辑**栈管理正确**,TON 看栈顶使能,看起来 OK
   - 但**实际使能条件是 SM0.0**(永久 ON),所以 T46 和 T48 **同时启动**!
   - 设计意图:只有 M16.0=1 启动 T46,M16.0=0 启动 T48(互斥)
   - **实际:两个都启动,PV 同步,失去"切换"意义**

2. **L74-93 触发 S6**:
   ```stl
   LD SM0.0              // 栈深 1
   MOVR VD116, VD190     // 栈深 1 (MOVR 不消耗栈)
   *R 10.0, VD190        // 栈深 1
   ROUND VD190, AC0      // 栈深 1
   MOVW AC0, VW194       // 栈深 1
   LD SM0.0              // 栈深 1
   MOVW VW190, VW192     // 栈深 1
   -I VW194, VW192       // 栈深 0 ⚠️ -I 消耗栈顶
   AW<= VW192, 0         // 栈深 0 ⚠️ 比较操作不执行
   LPS                   // 栈空,操作未定义
   ... (后续逻辑失效)
   ```
   - **LPS 之后所有条件不成立**,MOVW 7, VW2 不执行
   - **S6 永远不会由 FC40 触发**

3. **L96-117 触发下一轮 S1**:
   - 同样的栈消耗模式
   - **S M16.1, 1 不执行**
   - 下一轮 S1 永远不会由 FC40 自动触发

**修复建议**:
```stl
// S6 触发逻辑修复
LD     SM0.0
MOVR   VD116, VD190
*R     10.0, VD190
ROUND  VD190, AC0
MOVW   AC0, VW194
LD     SM0.0
AW<=   VW190, VW194              // 直接比较,不绕道 VW192
LPS
LDW=   VW2, 6
AW=    VW6, 0
LPP
ALD
MOVW   7, VW2
```

> 完成判定:T38 计时到 AND 注射泵子状态 9 → VW304=3。

**代码位置**:`plc/stl/FC1A_State_S2_MixDose.stl`

**实现情况**:

| 设计功能 | 实现状态 | BUG 编号 |
|---|---|---|
| S2 进入条件 | ✅ | - |
| 启动潜水泵 1/2(Q0.0/Q0.1) | ✅ | - |
| 启动 T38(搅拌计时) | ✅ | - |
| 加药子状态机(VW226) | ✅ | - |
| 注射泵 Modbus 轮询(FC4) | ✅ | - |
| S2 完成判定(VW304=3) | ❌ 栈消耗失效 | P0 |

**关键 P0 BUG**(L65-72):
```stl
LDW= VW226, 9          // 栈深 1
A    T38                // 栈深 1
LPS                    // 栈深 2 (LPS 复制栈顶)
R    Q0.0, 1            // R 消耗栈顶 → 栈深 1
R    Q0.1, 1            // 消耗栈顶 → 栈深 0
R    T38, 1             // 栈空,不执行! ⚠️
MOVW 3, VW304           // 栈空,不执行! ⚠️
LPP                    // 弹栈 → 栈深 0
```

**后果**:
- S2 完成时:潜水泵 1/2 关闭 ✓
- **T38 不复位** → 后续周期 T38 起始值不归零
- **VW304=3 不写入** → S2 永远卡在 VW304=2,**状态机无法进入 S3**

**修复建议**:
```stl
LDW= VW226, 9
A    T38
=    V_temp_latch     // 用中间位保存触发条件
LD    V_temp_latch
R    Q0.0, 1
LD    V_temp_latch
R    Q0.1, 1
LD    V_temp_latch
R    T38, 1
LD    V_temp_latch
MOVW 3, VW304
```

### 3.3 FC11_State_S1_FillIn 启动 T46/T48 ⚠️

**设计意图**(S2-S4 v2.2 §5.3):
> FC11 删除二次校正,S1 启动后立即启动 T46/T48(双倒计时器)。

**代码位置**:`plc/stl/FC11_State_S1_FillIn.stl`

**实现情况**:

| 设计功能 | 实现状态 | BUG 编号 |
|---|---|---|

- 设计要求 T46/T48 PT=10min=6000,这个 OK
- **但如果 VD414 设置更大,可能超过 32767**——目前不会触发,但属于隐患

### 3.13 FC2/FC3 VW6 编码冲突 ⚠️

**设计意图**:VW6 应按"优先级最高的报警"编码。

**实际代码**:
- FC2 急停:`MOVW 10, VW6`(急停 VW6=10)
- FC3 高水位:`MOVW 14, VW6`(高水位 VW6=14)
- **FC3 在 FC2 之后执行,覆盖 FC2 写入**——急停期间若同时高水位,VW6=14(高水位),VW6=10(急停)被覆盖

**实际后果**:急停报警可能被高水位报警覆盖,HMI 显示错误报警码。

**建议**:VW6 写入应加优先级判断,只有新值 < 当前值才覆盖。
