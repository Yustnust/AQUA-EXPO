## 四、失败用例根因分析

### 4.1 仿真器缺失功能(占失败约80%)

**根因1: 计时器T38/T39/T40未实现时基驱动**
- 表现: TC-04-004~008(S2→S3→S3.5→S4→S5→S6)全部失败,VW2=99(被错误转S_ERROR)
- 原因: 仿真器PLCSim未实现TON指令的PT值写入与计时累加,导致T38永不到时,状态机卡住
- 修复方向: 补全仿真器的TON指令仿真(基于run_cycle调用次数×时基推算)

**根因2: FC1状态调度不完整**
- 表现: 状态机转移类失败
- 原因: FC1仅实现了S0→S1,后续状态的调用与跳转条件未完整仿真
- 修复方向: 按STL源码补全FC1对FC11~FC17的调用与VW2切换

**根因3: 阀门诊断FC30/31/32子状态机不完整**
- 表现: TC-05-008~012(阀B/C诊断)失败,V302/V303报警位未置位
- 原因: 仿真器对FC31四态诊断的子状态VW262调度、I0.6/I0.7判断、关到位I1.6联动未实现
- 修复方向: 按FC31.stl逐NETWORK实现仿真

**根因4: FC40节奏纠偏未实现**
- 表现: TC-06-005/007/008/009/010失败
- 原因: 仿真器完全未实现FC40(预规划/二次校正/三层纠偏)
- 修复方向: 补FC40仿真逻辑(Story 1.4范围)

**根因5: FC19系统复位未实现**
- 表现: TC-04-011(S7→S0)失败
- 原因: 仿真器未实现FC19人工确认重启逻辑

### 4.2 仿真器逻辑bug(占失败约15%)

**根因6: 急停时QB0未正确清零**
- 表现: TC-07-001/008,TC-09-003 失败,断言`128 == 0`(QB0=128=0x80=Q0.7仍ON)
- 原因: 仿真器急停处理时未将Q0.7(报警声音)清零,导致输出未失效安全
- 修复方向: 在FC2急停分支补充`R Q0.7`等输出清零

**根因7: 漫溢保护未联动V300.0/V300.1**
- 表现: TC-03-008 失败
- 原因: 仿真器DI I0.5/I0.7触发时未置V300.0/V300.1报警位(STL中FC30/31有该逻辑,但仿真器未实现)
- 修复方向: 在仿真器FC30/31漫溢分支补全

### 4.3 测试期望与STL设计不一致(占失败约5%)

**根因8: 安全继电器报警码期望值**
- 表现: TC-07-002 `assert 14 == 10` 失败
- 分析: 变量表9.2定义安全继电器报警码=99(最高级),但STL FC2实际置VW6=10(漫溢级),测试期望10,仿真器返回14
- 结论: **仿真器返回值14与变量表99均不一致,需核查FC2实际STL的VW6赋值**(待确认项)

### 4.4 STL真实缺陷(本轮已修复)

**根因9: V300.2/V300.3 NC阀报警未置位**
- 本轮已通过Edit修复FC30/FC31 NETWORK1(补`S V300.2`/`S V300.3`)
- 仿真器尚未同步该修复,相关用例待补

## 七、结论与建议

### 7.1 结论

1. **仿真器完成度约35%**,能验证冷启动/S0→S1/急停锁存/基本DI-DO/部分阀A诊断,但无法验证完整状态机循环与节奏纠偏。
2. **测试通过率51.3%**,通过项可信(真实反映STL+仿真器交集行为),失败项根因清晰(80%为仿真器缺失)。
3. **交叉发现1项STL疑似缺陷**(FIND-SIM-05:FC2安全继电器VW6赋值与变量表不符),需人工核查FC2.stl确认。
4. **本轮STL修复(V300.2/3)有效**,但因仿真器未同步,待仿真器补全后回归。

### 7.2 建议

**短期(本周内)**:
- 核查FC2.stl中VW6在安全继电器故障时的赋值,确认是10/14/99中的哪个,统一变量表与STL
- 仿真器补全SIM-01(TON驱动)与SIM-06(急停Q清零),预计可提升通过率至70%+

**中期(Story 1.1~1.4范围)**:
- 补全FC4 Modbus轮询、FC19系统复位、FC40节奏纠偏的STL实现,仿真器同步
- 仿真器补全SIM-02/03/04/05/07,目标通过率90%+

**长期(现场调试前)**:
- 仿真器覆盖率达到100% FC实现,通过率≥95%
- 失败用例清零或明确标注"需硬件验证"
- 将仿真测试纳入CI,每次STL提交触发回归
